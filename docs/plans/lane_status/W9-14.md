## Question, options and recommendation

The issue's shared preamble requires that nothing in a statement is constructed
from a value. Wanted item 2 requires Redshift `COPY ... FROM` an S3 prefix with an
IAM role. `redshift-connector` does not implement client-side literal escaping for
its bound parameters: they become server-side `$1` and `$2` placeholders. COPY's
S3 location and IAM role positions require string literals rather than SQL value
expressions. The current fake accepting bound COPY is not evidence that a real
Redshift cluster supports that syntax, and must not be used to claim completion.

Question: may COPY alone use strictly validated, correctly escaped SQL literals
for its non-secret S3 location and IAM role ARN, retaining bound parameters for
all other values?

Options:

1. Approve a COPY-only exception for validated S3 location/IAM role literals.
   Both are public identifiers, not AWS credentials. Keep passwords, temporary
   credentials and AWS keys out of SQL text; test quotes, boundaries and rejection.
2. Require a server-side stored procedure accepting bound parameters and building
   COPY dynamically. This adds a server object not on the Wanted list and requires
   installation/permissions/lifecycle decisions.
3. Demonstrate live Redshift acceptance of bound COPY with this exact connector
   and retain the original preamble unchanged if that evidence exists.

Recommendation: option 1, with the exception explicitly recorded on issue #15.
Stop this package until the lead resolves the policy; other lanes continue.
