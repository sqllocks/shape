## Escalations (for the lead)

1. **`iso-4217` and `iso-639` not shipped: no redistribution licence could be confirmed.**
   SIX Group (ISO 4217) offers the list "free of charge" and states no licence that allows
   redistribution. The Library of Congress ISO 639-2 file has no licence statement. SIL's ISO 639-3
   terms name their site as the only authorised distribution site and forbid a product that provides a
   means to redistribute the code set. CLDR's currency list is not ISO 4217's (no funds or metal
   codes, four missing numeric codes), so a CLDR-derived `iso-4217` would not be the ISO list. The
   owner could confirm the SIX or Library of Congress terms; then the script's builders ship them
   unchanged. Meanwhile `iso-639-1` (not requested by that name) covers the `iso639_1` validator.
2. **Issue claim "every transposition of two adjacent different characters is rejected" is
   mathematically impossible with the specified checks.** Swapping an adjacent `1` and `B` (B is 11)
   leaves the MOD 97-10 digit string unchanged (RO49 AAAA 1B31...). The test pins exactly that
   exception (each survivor's digit expansion equals the original's) and requires every other swap to
   be rejected. All same-kind substitutions are rejected, as claimed.
3. **`iban-lengths` is a fourth pack**: the issue says "a table in the core pack"; a pack keeps source
   and licence (schwifty, MIT; lengths from the SWIFT IBAN Registry) with the table.
4. **`us_zip` accepts numbers 1 to 99999** (a ZIP read as a number lost its zeros; the CSV reader
   makes ZIP columns numbers). Text is checked exactly.
5. Workflow diff for the lead: none needed (CI already installs `plugins/shape-domains`). A nightly
   `scripts/build_reference_packs.py PACK --source FILE --check` needs the source files, so it is not
   proposed.
