# P6-10 — Profile registry parity (lane/P6-10)

Status: **built; awaiting lead verification.** Fixes: none.

## Decision D-13 (recorded as asked)
Shape reads and writes only its own formats. The registry stores **Shape profiles** (`.shape` profile
artifacts), not the baseline's JSON profile format, and there is **no import of baseline profiles**.
`export` writes, and `import` reads, only Shape's own `shape-profile` JSON; any other JSON is refused (exit 2,
test `test_import_rejects_a_foreign_json_file`). `shape profile capture` and the old `shape profile diff` were
not reintroduced; registry comparison is `shape profile registry diff`. `shape registry` is unchanged (the
content-addressed artifact registry; test `test_shape_registry_keeps_its_meaning`); the two stores are separate.

## Baseline defects fixed (owner standing decision 2026-10-01), each with a test
1. Identity parts (system, table, name, tag) were used unchecked in paths, so `../x` could write outside the
   root. Now plain names only (`test_registry_rejects_names_that_could_leave_the_root`, delete of `../../etc/passwd`).
2. `save` silently overwrote an existing profile. Now an error unless `--overwrite`, and nothing is written when
   any table of a multi-table save would collide (`test_registry_save_never_replaces_silently`).
3. `reindex` and bulk import swallowed every error and dropped files. `reindex` and `list` now print each
   skipped file and why (`test_registry_reindex_rebuilds_and_reports_skips`, `test_list_shows_...`).
4. Writes were not atomic (a crash left a truncated profile or index). Temp file + `os.replace`.
5. `exists` trusted the index only, and `delete` left empty folders. Existence is the file; folders are removed.
6. `validate` in the baseline needed generated data and never checked the store. Here it checks every file
   (content id, structure) and the index against the files, and with `--data` compares the data's profile with
   the stored one (columns, types, null-rate drift). Tampered files are found
   (`test_registry_validate_store_and_data`).
7. Diff reports per-field changes and the row count, not whole dicts.
