## Interpretations and deviations (for the lead)

1. **"Histories of 1, 2 and 30 versions"** is read as 1, 2 and 30 *candidate* versions after the
   good version (a history of one version has nothing to compare). The 30-day history has 31
   versions, so the third case has good = day 0 and bad = the last day (30 candidates).
2. **`--coarse` "with fewer full profiles read"** cannot hold literally: merging a window reads
   every profile in it, so a coarse search reads more profiles than a plain bisect. What it does
   save is full per-version diffs (`cost.full_profile_tests`: 5 against 8 on a 120-version
   history, asserted in a test); `cost.versions_read` reports the reads honestly. `docs/HISTORY.md`
   says this. Coarse window tests drop `row_count_change` (a merged window holds several
   versions' rows) and `--coarse` is refused with `--contract` (row-count and uniqueness rules are
   about one version) and with `--verify-all`.
3. **Share-safe profiles and `--contract`.** The issue's message for a share-safe version under
   the diff test mentions `--contract` as an alternative. `shape.check` needs a raw profile too, so
   the message says to commit raw profiles with `--allow-raw` and that `--contract` needs raw
   profiles as well; it does not suggest something that would fail.
4. `--json` on `bisect` and `bisect layers` is a flag that prints the JSON on standard output (as
   `shape project validate --json`), not a file path as `shape diff --json` takes.
5. `shape bisect layers` is routed before argument parsing (like `shape profile merge`), so a
   registry directory literally named `layers` must be written `./layers`.
6. Change points in `timelapse` are decided against the previous frame that has the column, with
   `shape diff` at the source's thresholds. A heavy-tailed column can show `range_change` between
   two ordinary days (seen on a log-normal column in the tests); `docs/HISTORY.md` says how to
   quiet it. No threshold or default was changed.
7. Layer status: a layer after the origin is `persists` when a column changed at the origin is
   also changed in it, else `disappears` (so every later layer without the change is listed as
   disappearing, and a layer where it comes back is `persists`).
