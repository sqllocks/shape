## P3-04 — Stream-source plugins

Fixes: none.

### What was built
- `src/shape/streaming/messages.py` (strict-typed, in core so the two plugins share one decoder and
  neither depends on the other): `StreamMessage`, `decode_messages`, `DecodeStats`,
  `StreamSourceError`, `freeze`/`conform`, `partition_offsets`. A message body is a JSON object; its
  fields become columns (nested values kept as JSON text; a column that mixes types becomes a string
  column when the schema is inferred); `_shape_event_time` (timestamp us, UTC) is the body's field
  (ISO-8601 or a number in `s|ms|us`), else the broker timestamp, else null. With a frozen schema a
  row that cannot take its column's type is *rejected*, never coerced; a body that is not a JSON
  object is *undecodable*. Both are counted and the offset moves past them. `with_offsets` adds
  `_shape_partition`/`_shape_offset` for row-level dedupe.
- `plugins/shape-kafka` (`kafka://host:9092[,host2:9092]/topic`, entry point
  `shape.stream_sources:kafka`): Shape owns the position. The consumer is *assigned* every partition
  at explicit offsets (no group rebalancing, nothing committed to the broker), so a `StreamOffset`
  is `{partition: next offset}`, which `StreamConsumer` already deduplicates on (P3-03). Watermarks
  give the end the topic had when the read began (`stop_at_end`, the default); `position()` is used
  when a poll is empty, so transaction markers and compacted offsets cannot stall a bounded read; a
  checkpoint older than the broker's retention starts at the oldest message left. `KafkaException`
  from the client is mapped: transport failures to `ConnectionError` (the consumer reconnects), the
  rest to `StreamSourceError`. `confluent-kafka` loads when a read starts, never at plugin load.
- `plugins/shape-eventhubs` (`eventhubs://namespace/hub[?consumer_group=cg]`, entry point
  `shape.stream_sources:eventhubs`): per-partition *sequence numbers* as explicit start positions
  (nothing is checkpointed in Blob Storage); offset `{partition id: next sequence number}`. The SDK
  delivers on a worker thread through a bounded queue (backpressure instead of unbounded memory);
  connection string (option or `SHAPE_EVENTHUBS_CONNECTION_STRING`) or `azure-identity`. One
  partition is asked for by id: without a partition id the SDK also reads the other partitions from
  their start (found against the emulator).
- **Deterministic bounded reads:** a bounded read takes the partitions one after the other, in
  order. Found by running the plugin kit against the real emulator: interleaving partitions in
  arrival order makes "reading from the offset after batch k yields exactly the batches after k"
  false. Following (`stop_at_end=False`) reads all partitions together in arrival order (set
  allowed lateness for windows).
- Both plugins: `testing.py` (in-memory `FakeBroker` / `FakeHub` with fault injection), entry
  points and dependencies in their `pyproject.toml`, READMEs; core extras `[kafka]` and
  `[eventhubs]` now point at the plugin distributions (T-08, as `[sqlserver]` does). `[streaming]`
  is untouched (it is not a T-08 extra; CI installs it).
- CI: new `stream-plugins` job (Linux and Windows: contract tests on every PR), and nightly
  `kafka-e2e` and `eventhubs-e2e` jobs (T-26).
- Docs: `docs/plugins/streaming.md` (new), `docs/specs/STREAMING_SEMANTICS.md` section 7,
  `docs/plugins/builtins.md`, `docs/plugins/authoring.md`, `docs/INSTALL.md`.
- Tests: `tests/streaming/test_messages.py` (20), `plugins/shape-kafka/tests/test_source.py` (26),
  `plugins/shape-eventhubs/tests/test_source.py` (24), `test_emulator.py` in each (contract tests
  are marker `contract`, emulator tests marker `emulator`).

## P3-05 — `shape stream-profile`

Fixes: none.

### What was built
- `src/shape/streaming/cli.py` (strict-typed) and the argparse block in `src/shape/cli/main.py`
  (the command's `--help` costs nothing at start-up: `shape version` still imports neither numpy
  nor pyarrow, test-enforced). `shape stream-profile URI`: finds the stream-source plugin by the
  URI's scheme, takes the first batch to fix the schema (handed to the profiler again, not read
  twice), builds a global/tumbling/sliding/session profiler (bounded mode), and runs it through
  `StreamConsumer` with `--checkpoint`, `--checkpoint-every`, reconnects (`--max-reconnects`),
  `--follow`, `--max-events`, `--idle-timeout`, `--start`, `--allowed-lateness`, `--event-time`,
  `--option`/`--options-file` (secrets stay out of the command line).
- Output: the `global` window is the profile engine's document (`mode: "bounded"`) at `-o`;
  other windows are JSON lines at `--windows`, written as they close and keyed by
  `(kind, start, end)`: a restarted run reads the file and does not write a window it already
  holds, so the file has each window once although the consumer delivers windows at least once.
  Ctrl-C finishes the profile from what was read and keeps the checkpoint resumable. A checkpoint of
  a finished run is final (a rerun says so and writes nothing). Errors are exit 2 with a message
  (an unreachable broker was a raw `KafkaException` traceback until the end-to-end run found it).
- Tests: `tests/streaming/test_cli.py` (45: the global profile equals batch bounded profiling,
  windows, kill and resume with the window file, 100+ reconnects, option/duration parsing, every
  argument error, start-up weight), `plugins/shape-kafka/tests/test_cli.py` (4: **D2 replay equals
  batch bounded profiling through the kafka plugin**, 1 and 3 partitions, plus 100+ forced
  reconnects equal to a clean run), and `test_stream_profile_on_*` in each plugin's
  `test_emulator.py` (the command, the real plugin, the real broker or emulator).
- **What the output is not:** a `.shape` artifact. Windows are in the engine's layout (`mode:
  "bounded"`, T-15 error models), which is not the layout `shape check`/`shape diff` read from
  `.shape` profiles; a `.shape` form of a bounded profile is a separate decision for the lead
  (not in the P3-05 text, so not done).

## Notes for the lead
- **Plugins installed next to core break two core tests.** `tests/plugins/test_host.py::
  test_unknown_groups_are_ignored` and `::test_reload_rediscovers` assert that no third-party
  distribution is installed; with `pip install -e plugins/shape-kafka` (or any plugin) they fail
  (`records()` lists the plugin). The core suite above ran with the two plugins uninstalled; CI's
  `test` job installs only `.[dev]`, so it is unaffected, and the plugin jobs run only plugin tests.
  I left the tests alone (not in these work packages).
- **Kafka retention deleted my first test topic** (an emulator-test bug, not a source bug): the
  e2e tests produced messages with fixed 2023 timestamps; the broker's retention check (every 5
  minutes, 7 days) deletes data whose timestamp is older, so a topic emptied a few minutes after
  creation and the next read, correctly, saw nothing. It appeared as an intermittent failure (three
  of the first seventeen runs) until a probe showed a topic with old timestamps going from (0, 500) to
  (500, 500) about 80 s in while one with current timestamps stayed intact. The tests now produce
  current, minute-aligned timestamps; see "Emulator results" for the runs since.
- Offsets are `{partition: next offset}` for both brokers, so the P3-03 consumer dedupes whole
  batches only; row-level dedupe needs `with_offsets` and `offset_column` (library use).
- The schema is the first batch's (or the checkpoint's). On a live trickle the first batch can be
  tiny: all-null columns become strings and later rows that do not fit are *rejected and counted*
  (in the command's summary). `--batch-size` is the sample size on a backlog. A `--schema` option
  would be a follow-up.
- Event Hubs: an emulator run takes about 2 minutes (a connection per partition, about 3 s each).
  `get_partition_properties` on a hub that does not exist gives `ConnectError` after the SDK's own
  retries, reported as a connection error (exit 2 after `--max-reconnects` attempts).
- The decoder keeps one Python `json.loads` per message; throughput of the source path was not
  measured (STREAM-PROF is the profiler's, as the plan defines it).
