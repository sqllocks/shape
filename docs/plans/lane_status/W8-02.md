## Decisions taken inside the package (§0.3), for the lead to see

- **CMS-HCC V24.** The issue lists "at least CMS-HCC V24 and V28, ESRD V24, RxHCC V08", and
  also "every model version the existing mapping table carries". The pinned 2027 mapping and
  model software carry CMS-HCC V22 and V28, ESRD V21 and V24, RxHCC V08; there is no CMS-HCC V24
  in the 2027 release (the mapping's "CMS-HCC ESRD Model Category V24" column is ESRD V24). I
  built every model the mapping carries, which includes everything the list names except a
  CMS-HCC V24 that the pinned release does not publish. Adding it would mean pinning the 2026
  software, whose categories would then not join the 2027 mapping (deliverable 5's join test).
  Not escalated as a blocker; flagged here.
- **`software` column and argument.** RxHCC V08 is published three times for 2027 (`R0826.84.T2`
  PDP+MAPD, `.Y1` MAPD only, `.Y2` PDP only) with the same segment names. The table keeps all
  three with a `software` column, and `score` takes a keyword-only `software=` that is required
  only when a segment is published by several packages (the error names them). The positional
  signature is the issue's.
- **Segment names** are the published score variable names without `SCORE_` (`COMMUNITY_NA`,
  `INSTITUTIONAL`, `NEW_ENROLLEE`, `DIAL`, `G_COMM_ND_PBD_GE65`, `CE_NoLowAged`, ...). ESRD
  coefficients with no segment prefix (transplant and graft adjustment factors) are kept with a
  null segment and their whole published name.
- **Interactions and demographic cells** are named by the caller in `demographics` (a mapping of
  variable to 0/1 or a list): the published tables give coefficients, not the SAS logic that
  derives those variables, and re-implementing it is outside "a small reference scoring
  function". Count variables (`D1` ... `D10P`) are derived from the categories.
- **Licence-read date.** The new assets were read on 2026-10-04, so
  `tests/test_assets.py` now pins each asset's date exactly (the two new ones 2026-10-04, every
  other one still 2026-10-02) instead of one date for all.
