## Decisions I took inside the package (nothing outside the Wanted list)

* `--sink-config mssql.identity=server` (the name in the issue) is accepted as an alias of the sink's own
  name, `sqlserver.identity=server`; both work.
* `identity=server` with an `upsert` whose primary key is the identity column is refused
  (`identity=server cannot match rows on the identity key ...`): a rerun could not match its rows.
  A table made only of identity columns is refused with `identity=server` (nothing to insert).
* `ConstraintError` (a `WriteError` with `exit_code = 1`) is how a failed re-enable gets exit 1:
  `shape.cli.errors.fail` returns an error's `exit_code` when it has one (2 otherwise). A run stops at
  the first table whose constraints do not hold, so the message names every failing constraint of that
  table, not of tables never reached. `docs/CLI.md` lists the new exit-1 case.
* `shape emit` has no per-table generation schema in its options, so a SQL Server target takes only what
  the new options need from it (identity columns, and the key for `upsert`): tables an emit creates
  keep the DDL they always had. The schema is passed as `TargetOptions.schema_hint`.
* `SqlServerSink.preflight(uri, {table: options})` (called by `shape generate --to` and `shape emit`
  before the first table) makes the refusals exit 2 before anything is written.
* `--auth kerberos` is refused for `warehouse://` and for `--scale-mode` jobs (exit 2).
* The DuckDB schema (`?schema=`) is created in a step of its own, under a lock, because two transactions
  that create the same schema conflict in DuckDB; every table is written on its own connection,
  because `shape emit` keeps every table's write open for the whole stream.
* `FakeSqlServer` (shipped test double of `shape-fabric`) learned identity, primary keys (opt-in with
  `enforce_keys`, so existing tests that append the same rows twice are unchanged), foreign keys and
  check constraints, `MERGE`, temporary tables and `DELETE`.

## Changes to existing tests and harnesses, and why

* `plugins/shape-fabric/tests/test_auth.py` and `test_auth_cli.py` used `kerberos` as their example of an
  unknown `--auth` mode. It is a mode now, so they use `ntlm`; what they assert (an unknown mode is
  refused, exit 2, before a job is made) is unchanged. `AUTH_MODES` in `test_auth.py` gained `kerberos`.
* `plugins/shape-databases/tests/test_conformance.py`: the installed plugin list gained `duckdb`, and the
  lockstep test checks the `duckdb` extra and that DuckDB is not in core's `dependencies` (T-07).
* `benchmarks/vs_refengine/ddl_1to1/differences.py`: **F12** (an `IDENTITY`/`SERIAL`/`AUTO_INCREMENT` column
  carries `"identity": true`; the baseline's schema has no such key), the same way ISS-gen added F9 to F11:
  one entry per identity column of each fixture, in both modes, each required to match
  (`test_without_its_entries_a_fix_is_reported[F12]`). No other field was allowed.
* A sink that failed *after* consuming its last batch hung the run: `write_targets` and the emit table
  writer drained their queue waiting for an end marker the sink had already taken. Fixed in
  `shape/generation/output.py` and `shape/streaming/emit/tables.py`; regression test
  `tests/generation/test_sink_failure_after_last_batch.py` (it times out without the fix).
