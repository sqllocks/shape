## P4-03 — Rust generation kernel

Contract: `docs/GENERATION_KERNEL.md`. Code: `rust/shape-kernel/src/gen/{rng,alias,strings,temporal,mod}.rs`; twin `src/shape/kernel/reference/gen.py`; stubs in `src/shape/_kernel.pyi`.

- **Philox4x64-10** (`rng.rs`): block `c` of a stream is the cipher on counter `c + 1` (numpy increments before it generates); verified against `numpy.random.Philox(...).random_raw()` for four keys, blocks 0, 1, 7, 1000, 2^20+3, every `per_row` 1..7 and unaligned starts. Results are independent of how the rows are split into calls or threads (tests split at 1, 4095, 8192, 65,537, 150,000 and run 400k-row calls on all cores).
- **Alias sampling** (`alias.rs`): Vose's method, identical to the twin bit for bit (hypothesis property test, mass conservation); a draw uses two words.
- **Pool and string assembly** (`strings.rs`): `pool_take`, `template_strings` (literals, column slots with zero padding, string and int64 columns), `join_strings`, `string_case` (upper, lower, title), `uuid4_strings`, `random_strings`.
- **Temporal sampling** (`temporal.rs`): `day_weights` (month and day-of-week profiles, each (month, weekday) pair carrying its own weight), `hour_weights_peaks` (bimodal and general Gaussian peaks, own erf series so both implementations agree), `temporal_sample` (day, hour, offset inside the hour; microsecond or whole-second).
- **Differential tests**: `tests/kernel/test_gen_kernel.py` (30 tests): Rust against the twin on every function; integer and string results equal, `philox_normal` and `hour_weights_peaks` to 1e-12 relative (different libm). Error cases raise `ValueError` in both.
- **Microbenchmarks** recorded in `benchmarks/vs_refengine/results.json` under `kernel_microbench` (schema extended; `run.py` keeps the key). Script: `benchmarks/vs_refengine/kernel_bench.py`; equivalence of each kernel with its twin is checked on the timed output before any time is recorded.

Fixes: **G1** (Appendix A: the seed was added to the row index, so seed `s + 1` was seed `s` shifted by one row, and a negative seed overflowed). `address_vectorized._u64` and `FastAddressPack.generate_columns` now read the Philox stream keyed by the seed (any Python integer); `FastAddressPack.generate` already used `random.Random(seed)`. Regression tests `tests/regressions/test_g1_seed_stream.py` (9 tests: 8 fail on the old code with the shifted-copy assertion or `OverflowError`, all pass now).

`shape.generation.rng.RowStream` now reads through the selected kernel (native when built): `raw`, `uniform` and `normal` take `per_row` and `slot`; its words and uniforms are unchanged (the existing `test_gen_rng.py` passes unmodified).

- Per-strategy statistical test against the pinned baseline under T-21 (b)-(e): `tests/generation/test_strategies_p404a.py` (134 tests, 37 cases: 2 sequence, 1 uuid, 5 weighted_enum, 16 distribution, 3 empirical, 7 pattern). ## P4-05 — distributions and calendars

- Families (`src/shape/builtins/distributions/families.py`; fits in numpy only, `special.py`): the plan's eight plus exponential, gamma, beta, weibull, triangular, negative binomial, power law with cutoff, histogram, mixture, truncation of any family. Rejection (gamma, truncation) takes a fixed number of attempts per row from derived streams, so rows stay independent.
- `tests/generation/test_distribution_recovery.py` (39 tests): the plan's fixed table, 10^6 draws, every parameter within max(2 %, 3 SE); SE = spread of the fit over 20 blocks / sqrt(20). All 15 families pass. `test_distribution_families.py`: histogram TVD <= 0.01, mixture proportions, truncation equals the conditional distribution, new families through the `distribution` strategy.
- 80/20 helper: `shape/generation/fanout.py` (`FanOut`, `concentration_weights`, `top_share_of`); `test_fanout.py`: top share within 0.01 for five configurations and both shapes (2M children).
- Calendars (`src/shape/builtins/calendars/`: `rules.py` D-11 engine, `effects.py`, `composite.py`): rules, events with ramp-up and decay, dips and closed days, custom events, paydays (1st/15th, monthly, biweekly, weekend shift), month-end and quarter-end, trends (growth, steps, ramps), `composite` plugin with `with_spec`; US federal and retail take `lifts`, `ramp_up_days`, `decay_days`; earlier behaviour unchanged; plugin kit conformance passes.
- `shape/generation/temporal.py` (`sample_timestamps`, row addressed) and `shape/profile/temporal.py` (`temporal_profile`, `holiday_lifts`, `tail_index`); docs `docs/GENERATION_CALENDARS.md`.
- `tests/generation/test_calendars.py` (18 tests): Black Friday 3.0, Cyber Monday 2.5, Christmas 0.4 recovered within 5 % (6M rows; errors 0.1 % to 1.7 % over three seeds); paydays and month-end within 3 %; profile -> generate -> profile month, weekday and hour TVD <= 0.01; Hill tail index within 5 %.
