## What was built

- **`shape fidelity REFERENCE SYNTHETIC`** (alias **`compare`**, plan §10 parity map): scores synthetic
  tables against reference tables (a file or a directory of one file per table; Parquet, CSV, JSONL),
  per column, per table and overall (`docs/FIDELITY.md`). Exit 0 pass, 1 a pass mark missed, 2 bad input.
  Pass marks `--min-score` (overall, 85), `--min-table-score` (70), `--min-column-score` (none); a missing
  column or table, a reference with no tables, columns or rows always fail. `-o FILE` (repeatable) writes
  `.json`, `.md` or `.html`; `--format` chooses what is printed.
- **Scoring** `src/shape/generation/report/compare.py` (pure numpy and pyarrow: core has no pandas or
  SciPy). A line-for-line port of the baseline comparator's arithmetic (kind 10, null rate 10,
  cardinality 10; numeric and datetime: mean 20, spread 10, KS 10; other kinds: Jaccard 20, chi-squared 20)
  on Arrow arrays, with its own `gammaincc` for the chi-squared p-value and `ks_statistic`, both tested
  against SciPy. Differences by design, all in `docs/FIDELITY.md`: a missing column scores 0 and counts
  in its table's mean; a missing table scores 0; an empty reference fails; datetimes are compared in
  nanoseconds whatever their Arrow unit (the baseline compares raw integer counts, so microseconds
  against nanoseconds scores badly there).
- **Formats via `shape.reports`**: built-ins `json`, `md`, `html` (`src/shape/builtins/reports/`, in the
  catalog and `pyproject.toml`, deterministic bytes, conform to `kit.check_report_format`, HTML is
  self-contained with escaped text and no scripts); `shape.generation.report.render_report(report, fmt)`
  goes through the plugin host, so a plugin's format works too.
- **G3 and G4** (below). `shape fidelity PROFILE.json DATA.csv` (a first argument ending `.json`) keeps its
  previous behaviour (certify a CSV against a captured profile, `--tolerance`, exit 3) apart from G3.
- **Harness** `benchmarks/vs_refengine/fidelity_1to1/` (README there): `baseline_scores.py` (the baseline
  comparator in `$REFENGINE_PY`), `run.py` (both comparators on every pair, edge pairs, the CLI),
  `golden_data.py` + `golden.py` + `fixtures/expected_scores.json` (the baseline's scores for pairs that
  hit every branch; `golden.py --check` proves the file still equals the comparator's output). The
  P4-07 harness is reused for generation (`domain_1to1/generate.py`); its `verify.py` clause (h) is
  untouched.
- Docs: `docs/FIDELITY.md`, `docs/plugins/builtins.md` (the three formats), `CHANGELOG.md`.

### 2. A missing column scores 0, and an empty reference fails

- Missing column (`run.py`, edge pair `missing_column`: `customer.email` dropped from the synthetic side): the
  column scores 0 and is listed missing, the table scores the baseline's score x 7/8 (84.03 -> 73.53; the
  baseline ignores the column), every other table within 0.5, the report fails. Also in
  `tests/generation/test_fidelity_report.py` and `tests/cli/test_fidelity_cli.py`.
- Missing table (`missing_table`): scores 0, the report fails, other tables within 0.5.
- Empty reference (`empty_reference`: every table sliced to zero rows): **every table scores 0, the report
  fails** (the baseline gives 37.85 overall). Also an empty reference with no tables or no columns, the CLI
  exits 1, and `certify` with an empty profile fails (G3).
- Type mismatch (`type_mismatch`: a timestamp as ISO text, a number as text): the two comparators agree
  (1.4e-14).
- Unit mismatch (`unit_mismatch`: microsecond timestamps against nanosecond ones): the baseline scores
  `order` 91.58 against 98.58 for the same data in matching units; Shape gives 98.58 either way. This
  is the one place where the scores differ on purpose and for no other reason (item above).

### 3. JSON, MD and HTML via `shape.reports`; thresholds; non-zero exit

`run.py` drives the installed `shape` command: retail pair with the default pass marks exits 0 and writes all
