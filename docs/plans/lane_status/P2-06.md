## What was built

- `src/shape/plugins/kit.py` — the conformance kit, no test-framework dependency. One check per
  Protocol (`check_source`, `check_sink`, `check_detector`, `check_fitter`, `check_strategy`,
  `check_distribution`, `check_calendar`, `check_domain`, `check_chaos`, `check_emitter`,
  `check_stream_source`, `check_transform`, `check_command`, `check_report_format`), the shared
  rules (`check_common`: Protocol, `name`, `schemes`), `check_module_api` (`SHAPE_API` major),
  `check_plugin(group, obj, **sample)` and `CHECKS` (group -> check), and `check_installed(dist,
  samples)` which loads every `shape.*` entry point of an installed distribution through the
  plugin host and checks it. `python -m shape.plugins.kit DIST [--samples MODULE:ATTR]` runs the
  latter (exit 0 conform, 1 not). Failures raise `ConformanceError(AssertionError)` naming the rule.
  Rules are only what the Protocols and host promise (types, determinism, inputs untouched, group
  rules such as a source claiming only URIs it can read and a stream source resuming after its
  offset). Chunk-layout independence is opt-in (`layout_independent=True`): the built-in
  strategies and distributions key by chunk, not by row, and pass without it.
- `examples/plugin/`: the P2-03 example (source, detector, command) now has `README.md` and
  `tests/test_conformance.py` using the kit.
- `plugins/shape-{kafka,eventhubs,fabric,sqlserver,domains,simulation,mcp}/`: skeletons for every
  T-09 distribution: `pyproject.toml` (`sqllocks-shape-<name>`, version = core's, depends on
  `sqllocks-shape==<core version>`, setuptools), `LICENSE`, `README.md`,
  `src/shape_<name>/__init__.py` (`SHAPE_API = "1.0"`, no entry points yet), `tests/test_skeleton.py`.
  No third-party dependencies were invented; the implementing work packages add them. Core's extras
  are untouched (re-pointing `[kafka]` etc. at these distributions belongs to the packages that move
  the code).
- `scripts/check_plugin_skeletons.py`: lockstep rules (name, version, core pin, LICENSE, `SHAPE_API`,
  entry-point groups) and `--build OUT [--no-isolation]` (builds each from a scratch copy so nothing
  is left in the tree; checks `py3-none-any`, package, licence, no tests shipped).
- CI (`.github/workflows/ci.yml`): `plugins` joins the ruff scope (T-27); `check_plugin_skeletons.py`
  in the `test` job; new `plugin-skeletons` job on Linux, macOS and Windows: build the seven wheels,
  `check_user_facing --wheel` on each, then the kit and install tests. `Makefile`: same ruff scope and
  the skeleton check.
- Docs: `docs/plugins/authoring.md` (the author guide: anatomy, groups table with kit check and
  sample, testing, install, monorepo rules, versioning); link from `docs/plugins/host.md`.
- Tests: `tests/plugins/test_kit.py` (39: every built-in passes the kit; one wrong plugin per
  Protocol fails with the named rule; the guide covers every group and check),
  `tests/plugins/test_plugin_kit_install.py` (7, below).

## Notes for the lead

- Windows: nothing is deleted or replaced while open; builds run from a scratch copy and the temp
  directory is removed with `ignore_errors`.
- The install tests use `--no-build-isolation` when `setuptools` is importable (no network needed),
  otherwise pip's isolated build (CI on 3.12+ venvs).
- For G2: core's own code consumes plugins only through `shape.commands` today (`shape hello` runs
  end to end). A plugin source or detector registers, loads and passes the kit, and `shape plugins
  list` shows it, but `shape profile` does not yet look sources up through the host, nor consult
  `shape.detectors` plugins. G2's wording ("adds a source, a detector and a command without any core
  change") is met as registration and loading; if the lead reads it as end-to-end use of the source
  and detector in profiling, that wiring is outside P2-06 and needs a work package.
- Version lockstep: changing core's version means editing the seven `plugins/*/pyproject.toml` in the
  same commit (the script and a test fail until they match).
