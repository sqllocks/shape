### `shape stream` and `shape emit`: one implementation

`shape stream` adds no runtime of its own. The two commands share the option list, the sinks, the
runtime and the plan; they differ in what the stream is: `emit` streams the tables of a schema one
after another in row order, `stream` streams one table earliest event first. The full table is in
`docs/EMIT.md` ("`shape stream`: one table in event-time order").

Every option of the baseline's `stream` is accepted with the same meaning: `--table/-t`,
`--scale/-s`, `--seed` (default 42 as the domain's), `--rate`, `--max-events`, `--duration`,
`--out-of-order`, `--sink` (console, file, plus Shape's emitter URIs: kafka, eventhubs, eventstream,
eventhouse), `--output/-o`, `--mode/-m`, `--realtime/--no-realtime`, `--burst` (repeatable),
`--anomaly-fraction`; plus Shape's `--envelope`, checkpoint, delivery and `--live-*` options.
Differences in behaviour, all documented: `--duration` also applies to a run that is not paced (the
baseline ignores it without `--realtime`); `--anomaly-fraction` is honoured (below).

### D-13: names

Shape's events use `_shape_table`, `_shape_seq`, `_shape_event_time` (the runtime's own names,
reused from P5-01); there are no aliases and no option naming the baseline. The harness
(`stream_common.FIELD_MAP`, outside the package) maps the baseline's three names to these and
compares field names and order through the map; the map is recorded in the verifier's report.

### Baseline defect: allow-list (owner's standing decision, 2026-10-01)

`stream_common.ALLOWED`, one entry, each shown by a probe that fails if the defect is not there:

* **ST-1 — `--anomaly-fraction`.** The baseline accepts the flag and ignores it (its command
  passes no anomaly registry when the fraction is above 0): the output with `--anomaly-fraction 0.2`
  is byte-identical to the output without, and it reports 0 anomalies. Shape honours the flag
  (P5-01): the probe shows 18.9% of the events changed at 0.2, identically on a second run.

No other difference was found that is a trust-harming defect. Differences that are not defects and
that the verifier handles by comparing values: the baseline writes a timestamp as
`2022-01-16 21:22:16` and Shape as ISO-8601 `2022-01-16T21:22:16`; Shape numbers rows by their
position in the table (`_shape_seq`), as the baseline does.

## Acceptance, item by item

### 1. e2e tests

`tests/streaming/emit/test_stream.py` (32 tests, all pass; run as part of the suites below):
the encoder is byte-identical to the row encoder on 12 random batches covering every type it
treats specially (ints, uint64, float64 across magnitudes and non-finite values, float32,

a table without a time column stays in row order, exactly one table, resume equals the suffix at
five offsets (with `--out-of-order`), `--max-events` is the prefix, out-of-order deterministic,
the order is part of the checkpoint identity. The command: the file equals `shape emit`'s events
for that table, in time order; `--max-events N` is the first N lines of the whole run; short flags
equal long flags; `--table` required (exit 2) and single; `--rate` 10 (emit stays 100); `--burst`
needs `--realtime`; `--anomaly-fraction` honoured; stop at 3,000 events and rerun with the same
checkpoint equals an uninterrupted run, byte for byte.

## Decisions for the lead

* **The encoder replaces the row encoder for flat events everywhere** (`shape emit`, `shape stream`,
  every `FileSink`/`StdoutSink`), with byte-identical output (differential tests); the CloudEvents
  envelope and `encode_events` (one message per event, for Kafka and Event Hubs) still use the row
  encoder. A batch of 16,384 or more events is encoded on up to 4 threads (`SHAPE_THREADS` when
  set); an Arrow capacity or not-implemented error falls back to the row encoder. Revert is one
  line (`encode_batch`) if a different policy is wanted.
* **Single-thread ratio 9.1x** (see acceptance 3): the gate (default threading) is met; whether
  T-19's "reported alongside" single-thread figure needs its own bar is the lead's / owner's call.
  Where the rest of the single-thread time goes: generation of the whole schema (the `order`
  table's total is computed from `order_line`, so the whole schema is generated), then sort, encode
  and write, each serial.
* **`shape stream` sets a 32,768-event delivery batch when not paced** (the encoder's per-call cost is
  per column, so 1,000-event batches were twice as slow). `shape emit`'s default stays 1,000
  (`EmitConfig` untouched; `runtime.py` and `rate.py` not edited, so `lane/P5-01b` is unaffected). A larger
  checkpoint granularity is the only consequence.
* **Memory:** `shape stream` holds the whole table as events (the table must be sorted); it is
  documented. `shape emit` is unchanged.
* **`results.json`** (the committed reference) is not rewritten here: `run.py --only stream` writes a
  file with only the stream workload, and a full-file rewrite belongs to whoever runs `--full` for
  all workloads. The figures are in `docs/plans/evidence/P5-04/`.
* G5's other two items (the 1-hour realtime soak, live fidelity) are P5-01's and P5-03's.
* Nothing in the plan needed escalating.
