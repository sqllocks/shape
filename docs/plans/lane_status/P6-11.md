## Differences from the baseline, by design (not allow-list entries)

- Envelope: `{"api_version", "id", "command", "ok", "result"|"error", "warnings"}` instead of
  `{"status", "data"|"error"}`; arguments in `args` (names unchanged), errors have a code, group and
  hint, and no traceback.
- `describe`/`dry_run` `generation_order` is the engine's order (the same as the baseline for retail);
  `profile_info` may report **more** distributions than the baseline (`product.unit_price`,
  `return.refund_amount`: Shape's `distribution` strategies); `describe` columns are in the declared
  order like the baseline (a generated table lists keys first in both implementations).
- A `stream` chunk is the schema at `scale`, each table at most `chunk_size` rows, seed `seed ^ chunk`
  (the baseline's seed rule and row cap); a Parquet sink writes each chunk under `chunk-NNNNNN/`
  (the baseline interleaves part files across chunks) and the memory sink only counts.
- `stream_status` of a stopped stream still answers (as `cancelled`); the baseline forgets it.
- Domains: Shape has `retail` only so far (P6-01 is in progress elsewhere), so `list` is a subset of
  the baseline's 14 domains (`domains_not_in_shape` in the report) and all data parity is retail.
