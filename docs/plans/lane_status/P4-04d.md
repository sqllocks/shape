## Deviations and findings (for the lead)

- `foreign_key` ignores `ref_column` in the baseline (always the primary key pool); Shape uses the named column (identical when it is the key, which holds for all 242 FKs of the 28 domain dumps).
- `pareto`'s cap is the theoretical 99.5th percentile, not the batch's empirical one (chunk independence). `max_per_parent` is exact (the baseline's redistribution stops after 10 rounds) and holds one index array per table in memory.
- `sample_rate` wraps when the child has more rows than the sample (the baseline errors).
- `scd2` returns `timestamp[us]`; null business keys give nulls; `effective_date_column` also applies to `is_current`/`version`. The baseline hard-requires a column literally named `effective_date`.
- `composite_foreign_key`: only the table's own columns are output (the baseline also leaks `ref_columns` names as extra columns when they differ).
- `AddressPack.generate` now raises "No reference geography" up front for an empty scope entry (as `FastAddressPack` already did), not when a row first draws it.
- `composite_foreign_key`'s `ref_table` is not in `Table.fk_dependencies` (the baseline's order has the same property); the parent is generated on demand.
- Pre-existing, fixed by the merge of lane/P4-03: six stale tests (`test_dry_run_*`, `test_errors`, docs names) failed on the lane's base commit before the merge.
