## Where the map settled things the issue left open (deviations)

pyx12's 005010X214 map (test-only) rejected the first draft and fixed these:

1. **2220D `STC03` allows only `U`.** A service-line row whose action is `WQ` (explicit, or derived
   from `A1`/`A2`) raises `ContractError` naming claim and line, instead of writing an invalid file.
2. **2200C totals use `QTY*QA` / `QTY*QC`** (2200B uses `90` / `AA`); `AMT*YU` / `AMT*YY` at both.
3. **2200C `STC02` and 2220D `STC04` are "Not Used"** and are left out.
4. 2200B/2200C `STC03`: the X12 request for interpretation RFI 2105 says it describes the whole
   transaction or billing-provider group (accepted if any is accepted, rejected only if all are).
   I write `WQ` when any claim below is accepted, else `U`. The status written there is
   `AckOptions.accepted_status` / `rejected_status` (defaults `A1:19:PR` / `A3:21:PR`; codes copied
   through, none curated).

## Open point: category to action code mapping (A1 A2 / A3 A6 A7 A8)

Read against public sources: pyx12's map has the category and status code *sets* only, not the
pairing. A public payer 277CA companion guide's examples show `A1`/`A2` with `WQ` and `A3` with `U`,
which supports those three. I found no readable text for `A6`, `A7`, `A8` (the guide text I could
fetch was image-only, and implementation-guide material is licensed), so those rejections follow the
issue's reading and are **not independently confirmed**. The explicit `action_code` column path is
kept for every other category (and wins over the derivation). A real payer file also uses non-`A`
categories with `WQ` (for example a warning), which is why unmapped categories raise rather than guess.
Lead: confirm `A6`/`A7`/`A8` against the licensed guide if you hold it.
