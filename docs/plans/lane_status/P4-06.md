## What was built

- Sinks (all `shape.sinks` plugins, registered in `builtins/catalog.py` and `pyproject.toml`):
  - Core: `tsv` (new), `sql` (new, `builtins/sinks/sql.py`); `csv`, `jsonl`, `parquet`, `ipc` existed.
    Parquet now follows T-17: snappy, dictionary encoding on (was zstd). JSONL writes dates and times
    as ISO 8601 (was `str()`); decimals stay exact strings.
  - Plugins with extras: `excel` (`[excel]`, openpyxl, write-only mode, one workbook per table) and
    `delta` (`[delta]`, deltalake). Both import their library lazily (test: importing the sinks loads
    neither). Implemented as built-ins behind the extras, as P2-04 did for the Delta source, not as
    separate distributions under `plugins/`.
- SQL: `--sql-dialect tsql|tsql-fabric-warehouse|postgres|mysql`, `ddl`/`drop`/`go`, `schema_name`,
  `batch_size`. Streams; deterministic (no timestamp; the baseline's header stamps the time). Differences
  from a naive port, all documented in `docs/GENERATION_ENGINE.md`: BIGINT for integers in every dialect;
  T-SQL batches capped at 1,000 rows (server limit; the baseline's CLI default of 5,000 would not run);
  Fabric Warehouse gets VARCHAR / DATETIME2(6), a comment instead of a PK constraint, and no
  `DISTRIBUTION` clause; NaN and infinity become NULL; MySQL escapes backslashes.
- `shape.generation.output`: `write_result` (parallel per table), `write_engine` (streams with one chunk of
  look-ahead when `needs_post_pass` is false, else writes `engine.generate()`), `format_summary` (the
  `summary` output), `sql_options` (types, nullability and primary key from the generation schema).
- Not done here: the `shape generate` CLI flags (`--format`, `--sql-*`, `--dry-run`) belong to P4-10, which
  calls this module.
- Harness: `benchmarks/vs_spindle/writers_1to1/verify.py` (Shape writes Parquet; the baseline venv reads it
  with pandas and its own `DataProfiler`; compares rows, columns, nulls, sums).
