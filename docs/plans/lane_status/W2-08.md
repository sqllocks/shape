## Decisions taken inside the package (no D-xx/T-xx changed)

* `commit_rows` is applied at whole-input-batch granularity for Snowflake and Synapse (one
  `COPY INTO` per run of batches reaching `commit_rows`): `shape emit --to` passes `commit_rows=1`,
  which would otherwise mean one `COPY INTO` per row. Databricks: every statement commits, so
  `commit_rows` makes a statement never wait for the next input batch; it does not shrink statements.
* `--sink-config` resolves references before a sink sees them, so `snowflake.private_key` arrives as
  PEM text; the Snowflake sink accepts a `file://`/`env://` reference or a PEM, and refuses other text.
* Databricks OAuth M2M is a plain HTTPS exchange at `/oidc/v1/token` (no `databricks-sdk`), so the
  extra is only `databricks-sql-connector`.
* Databricks table and schema names with capitals are refused (Unity Catalog lower-cases them, which
  is a name the database would change).
* The `WarehouseWriter` got two hooks (`_prepare`, `_copy_statement`) and `_tsql.create_table_sql` /
  `prepare_table` an `options` argument for `WITH (...)`; `WriteError` gained `rows_committed`; the
  shared `DatabaseSink` base got hooks (`parse_target`, `resolve_auth`, `check_schema`,
  `create_table_sql`) and `_undo` now returns the rows still committed. Existing behaviour and tests
  are unchanged.
* Core change: `shape.cli.to` accepts `synapse` among the sinks that take `--auth`/`--connection-string`.
* Not done (not on the list): a friendlier "install the plugin" message in core when a plugin is
  absent for `snowflake://`, `databricks://` or `synapse://`; the generic "no installed sink writes
  ..." message applies.
