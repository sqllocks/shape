## Test tables

Real tables written by **Apache Spark 4.2.0 + Delta Lake 4.4.0** (installable here with pip plus
the Delta jars from Maven Central), committed under `tests/fixtures/delta_fallback/`
(`dv`, `cm`, `plain`) with the generator `make_fixtures.py` and a README. No delta-rs-written
table is used for the features. Spark was able to write both features, so no fallback to
hand-made fixtures was needed. The DuckDB `delta` extension is downloaded on first use; the test
module fails (does not skip) if it cannot be installed.

## Findings that shaped the design

1. **`deltalake` 1.6.6 does not refuse column-mapped tables: it returns the right number of rows
   with every column null.** Measured on the `cm` fixture. (`deltalake` 0.25.5 raises
   `DeltaProtocolError: The table's minimum reader version is 2 but deltalake only supports
   version 1 or 3 ...`.) So an error-driven fallback is not enough; a column-mapped table is
   detected from its configuration (`delta.columnMapping.mode` other than `none`) and sent to the
   fallback before delta-rs is asked. Consequence: with no `delta-fallback` extra, a column-mapped
   table that previously "profiled" (with null columns) now stops with the explicit error.
2. Deletion vectors: delta-rs raises `DeltaProtocolError` (both releases), so that path is
   error-driven; delta-rs stays the default and a future release that reads them is used as is.
3. Pre-existing, not changed: delta-rs resolves `--as-of` from the log files' modification times,
   not the `commitInfo` timestamps. A copied or checked-out table (all mtimes equal) resolves
   to version 0, and `read_delta`'s later check against the `commitInfo` time does not catch
   it. The as-of tests therefore copy the fixture and set the mtimes to the commit times. A
   follow-up could resolve `as_of` from `history()` instead.

## Not verified / not done

- **`delta+abfss://` against real OneLake/ADLS was not run** (no storage account or network
  credentials here). The DuckDB secret and `delta_scan` SQL are verified against a recording
  connection only; whether DuckDB's `azure` extension accepts a OneLake `abfss://` URL with a
  bearer-token secret needs a live check by the owner.
- `--as-of` still needs `deltalake` installed (it reads the log); the fallback only replaces the
  data read.
- delta-rs's other silent failure modes (if any) beyond column mapping are not enumerated; any
  other feature it refuses with `DeltaProtocolError` falls back.
