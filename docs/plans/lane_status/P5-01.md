| `runtime.py` | `EmitRunner`: generator thread -> bounded queue -> pacing, delivery with retries, checkpoint; `EmitConfig`, `EmitReport` |

Deliverables, one by one:

- **Rate modes**: `--no-realtime` is the default; `--realtime --rate N` paces each batch to its
  absolute due time (so sleep overshoot never accumulates); `--burst START:DURATION:MULT`
  (repeatable) multiplies the rate inside the window. A slow sink makes the run fall behind (no
  event dropped); the report carries `max_lag`.
- **`--out-of-order F`** (+ `--ooo-window N`): an event moves later by 1..N places inside its window;
  event time unchanged; determined by (seed, table, row), so it does not depend on chunking.
- **`--anomaly-fraction F`** through `shape.chaos` (+ `--anomaly-mutator NAME`): honoured, never
  ignored. A fraction above 0 with no usable mutator is an error (exit 2), as is `--anomaly-mutator`
  without a fraction. `test_anomaly_fraction_is_honoured` is the regression test for the baseline's
  silent ignore (output with the flag differs from output without, in about the requested share of
  rows, identically on a second run).
- **`--max-events`** (a position in the stream: counts events a previous run delivered, so a resumed
  run stops at the same place) and **`--duration`** (wall-clock seconds of this run).
- **D-12 formats**: flat rows (default) and `--envelope cloudevents`; idempotency key
  `(_shape_table, _shape_seq)`; `_shape_seq` is the row position in its table.
- **Backpressure**: bounded queue (`--queue-batches`; default 8, about one second of batches when
  realtime); a slow sink blocks the runner, the queue fills, the generator waits
  (`test_backpressure_blocks_the_generator`: `max_queue_depth == queue size`).
- **At-least-once + checkpoint on shutdown**: a batch counts as delivered when `send` returns, and
  only then can the checkpoint (atomic JSON: offset, plan fingerprint, completion) move past it.
  Written every `--checkpoint-every` events / `--checkpoint-seconds`, and always on shutdown (end of
  data, limit, SIGINT/SIGTERM, error). A checkpoint of a different stream is refused; `--fresh` starts
  over; a finished run is not repeated. Transient `OSError`/`ConnectionError`s are retried
  (`--retries`).
- Documentation: `docs/EMIT.md`; `CHANGELOG.md`; nightly job `emit-rate-soak` (one hour).

3. **kill -9 and restart, then dedupe on the key, equals an uninterrupted run.**
   `test_kill_9_then_restart_equals_an_uninterrupted_run[1500|9000|21000]`: a real process, realtime
   6,000/s with out-of-order 0.15 and anomaly fraction 0.05, SIGKILLed once the file holds that many
   events, restarted with the same command, then deduplicated on the key keeping the first sighting:
   byte-identical to the uninterrupted run, in the same order. With a stale checkpoint

   the events after the checkpoint twice and dedupe removes them. `test_sigterm_shuts_down_...`: a
   graceful stop writes the shutdown checkpoint (offset == lines written) and a restart leaves no
   duplicate at all. `test_a_torn_last_line_is_repaired_on_resume` covers a writer killed mid-line.

   anomalies) and `test_rows_equal_shape_generate` (events equal `shape generate`'s tables, for a

## Decisions for the lead

- **`shape.chaos` built-ins do not exist yet** (P6-02, a parallel lane). The runtime calls the
  `ChaosMutator` protocol and loads `--anomaly-mutator NAME` from the `shape.chaos` group; until
  P6-02 lands the default is `ValueAnomalyMutator` (in `streaming/emit/anomaly.py`), which implements
  that protocol. When P6-02 merges, the default can be switched to its mutators; the constraint that
  a stream mutator keeps row count and schema stays (it is what makes `_shape_seq` the row position).
- The command is `shape emit`, not `shape stream`: P5-04 owns `shape stream` (RefEngine's `stream`
  options and the sinks) and can wrap this runtime. The module is `src/shape/cli/emit.py`.
- `FileSink`, `StdoutSink` and `EmitterSink` are the runtime's own minimal sinks so the command and
  the tests run end to end; P5-02 owns the real emitters (console, file, JSONL, Kafka, Event Hubs,
  Fabric) and plugs in through `shape.emitters` / `EmitterSink`.
- Event order across tables is fixed (table by table, dependency order); `--max-events` therefore
  streams the first tables first. Interleaving was not asked for and would need a decision.
- The first block of a table that a post-pass changes (retail: `order`, `product`, `return`) waits
  for the whole schema to generate once; the other tables stream with bounded memory.
