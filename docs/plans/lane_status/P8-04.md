## How the release works (summary; the checklist has the steps)

```
publish.yml (owner: manual run testpypi|pypi, or a v* tag)
 ├─ build: release.yml (workflow_call)
 │   ├─ versions        check_versions.py [--release] [--tag v<version>]
 │   ├─ wheels          wheels.yml: 7 T-04 targets, each installed on 3.11 and 3.14 (+ Intel macOS)
 │   ├─ python-dists    build_release_dist.py --verify-pure (pure wheel, core sdist, 24 plugin archives);
 │   │                  the core sdist builds the kernel with stable Rust
 │   ├─ sbom            --check-set; twine check --strict; release_sbom.py build/check --schema;
 │   │                  environment SBOM + pip-audit; attest-build-provenance (archives + SBOMs);
 │   │                  attest-sbom (resolved SBOM); gh attestation verify every archive
 │   └─ smoke           release_smoke.py --source dist --kernel rust: 5 runners x {3.11, 3.14},
 │                      + Alpine x86_64/aarch64 in Docker
 ├─ publish             environment testpypi|pypi, id-token: write, pypa/gh-action-pypi-publish
 │                      @release/v1 (no token; PEP 740 attestations), skip-existing for re-runs
 ├─ index-hashes        release_index_check.py SHA256SUMS: the index serves exactly those files
 └─ installed           release_smoke.py --source testpypi|pypi --kernel rust, on every platform
```

- **Why `release.yml` is reusable:** the trusted publisher O-01 registered is `publish.yml` with
  the environments `pypi`/`testpypi`, so the upload must stay in `publish.yml`. The build is a
  called workflow so it can also be run alone (Actions → Release build) to rehearse a release
  without uploading anything. The Sigstore build attestations therefore name
  `.github/workflows/release.yml` as the signer workflow (`gh attestation verify --repo` accepts
  them; the checklist says so).
- **One build per release:** every index gets the same archives (artifact `release-dist`), and
  `SHA256SUMS` plus `index-hashes` tie what the index serves to what was attested.
- **Per-archive SBOMs** are made from the archive: its metadata (subject, SHA-256, licence
  expression, every declared requirement as a component, `required` or `optional` by extra) and,
  for archives carrying the kernel, every crate of the `Cargo.lock` (licences from
  `THIRD_PARTY_NOTICES_RUST.md` inside the archive; the lock is a superset of the linked crates,
  which a property states). They are deterministic (serial number from the archive hash;
  timestamp only from `SOURCE_DATE_EPOCH`). The resolved SBOM is `cyclonedx-py environment` over a
  clean install of `[all]`, first-party from the release only.

## Open points for the owner and the lead

1. **Attestations need a public repository** (O-08) or GitHub Enterprise Cloud. Until then the
   `sbom` job's attest steps fail; nothing else depends on them.
2. **O-01 must cover all 13 projects** on both indexes before the first run: one project without
   a publisher fails the whole upload. `sqllocks-shape` exists on PyPI (0.9.0), so it gets a
   publisher in its settings; the 12 plugin projects need pending publishers.
3. **Platform coverage of third-party wheels is not verifiable here.** The `smoke` and
   `installed` jobs install `[all]` (confluent-kafka, pyodbc, deltalake, scipy, azure-eventhub,
   ...) on every runner, Python 3.11 and 3.14, including Alpine and Intel macOS. Where a
   dependency has no wheel for a platform the job builds it from source (the jobs install
   `librdkafka`, `unixodbc` and a compiler on macOS and Alpine for that); if one still fails, it
   is a real gap in "`[all]` on each platform" and is reported by that job, not hidden.
4. **TestPyPI and PyPI never accept a file name twice.** The checklist rehearses with
   `Release build` first (no upload), and a partial upload is recovered by re-running the failed
   jobs of the same run (`skip-existing` plus `index-hashes`), never by a new run.
5. **"Early access" wording at 1.0:** `check_versions.py --release` requires the words in README
   only below 1.0 (DM-03's rule for 0.x); at 1.0 whether to keep them is the owner's call
   (checklist step 2.4). The `publish.yml` README grep of DM-03b is replaced by that rule.
6. **CHANGELOG:** `--release` requires a `## <version>` section; the version change renames
   `## Unreleased` to `## 1.0.0`, and the owner adds the date when tagging (checklist step 2.3).
