Lane branch `lane/HC-behavior`. Builder notes; the lead merges. No issue was commented on,
labelled or closed; no PR. Never edited §11, §2.3 or `$SPINDLE_ROOT`.

## Where HC-domain starts

**The API sketch and docs are first in the history: `docs/plugins/behavior.md`** (module
document format, state types, Python API, event schema, extension point, GMF import, CLI, and
section 10 for the `shape.behaviors` group). Implementation: `plugins/shape-behavior`
(distribution `sqllocks-shape-behavior`, package `shape_behavior`, the public names are in
`shape_behavior/__init__.py`). The domain-agnostic event table is `shape_behavior.EVENT_SCHEMA`;
domain packs add state types with `register_state_type` and write their modules as JSON.

## Decisions for the lead to look at

* **T-09 lists the first-party distributions; `behavior` is a new one.** I added `behavior` to
  `EXPECTED` in `scripts/check_plugin_skeletons.py` and moved the counts 7 -> 8 in
  `tests/plugins/test_plugin_kit_install.py`, as the task asked for `plugins/shape-behavior`. The
  plan text (T-09, section 5) is untouched; it needs the one-line addition.
* The kit does **not** require a behavior to depend on its seed (a module without randomness is
  valid); it requires determinism for a given seed.
* The previous session's doc promised an external-generator calibration stub
  (`shape_behavior.external`, "[VERIFY]"). No such code exists and nothing could run it here, so
  I removed that section instead of shipping an unenforced claim; calibration against an external
  generator is not built.
* `healthcare_screening` uses one ICD-10-CM code (I10) as a plain string; no terminology file is
  shipped and no module of the GMF project is vendored (D-13 and the trademark note: no Shape
  name derives from that project; the importer is `import_gmf`, "Generic Module Framework").
