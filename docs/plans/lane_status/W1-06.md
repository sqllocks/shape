## Decisions and findings

- **Two schema files.** The loader's schema (`generation-schema-v1.json`) stays lenient about
  generator keys, because `GenSchema.validate()` only warns about an unknown key and old files with
  one must still load. The published one is strict. The published file is *built* from the loader's
  schema plus `spec_keys`, `STRATEGY_REQUIRED_KEYS` and the plugin registry, so it cannot drift.
- **Additive change to the loader schema:** `x-*` keys and `$comment` are accepted on every closed
  object (`patternProperties`). The loader ignores them.
- **Bug found and fixed:** `GenSchema.from_dict` raised `KeyError: 'generation'` for a document
  without a `generation` block, which the loader's own schema allows. It now uses `{}`.
- **`maximum` was ignored** by the checker (`null_rate` > 1 passed the structural check and only
  `validate()` caught it). It is now enforced in both schemas.
- **Specs the existing tests and domains use were swept.** All 928 distinct documents passed to
  `GenSchema.from_dict` by `tests/generation`, `cli`, `packs`, `scenario`, `regressions`, `iss_gaps`,
  `model`, `spec`, `streaming` and `dimensional` were checked against the published schema. The 38
  problems left are specs that tests build wrong on purpose (typos, a missing required key, a wrong
  version, a bad `output_type`). Findings from the sweep: `distribution` without a `distribution`
  key is a uniform (used widely), so it is not required; specs made by
  `shape.generation.learn` carry `temporal.type` and `faker.max_length`, which the strategies
  ignore. They are accepted as `deprecated` keys (`LEGACY_IGNORED_KEYS`); stopping `learn` from
  writing them is a separate change and is not made here.
- Only JSON specs are supported by the edit API (the format has no comments; `$comment` is the
  place). YAML is out of scope (not on the Wanted list).
