Status: **blocked; no feature implementation shipped**. Base: `faba6633`.

## Question for the Owner

Which supported writer should implement deletion-vector upsert without rewriting
matched files? `deltalake` 1.6.6 can enable the table property, but its public merge
API rewrites the original file rather than attaching a deletion vector. Merely
enabling the property does not satisfy Wanted item 4. The current extra allows
`deltalake>=0.17`; its floor is explicitly awaiting an Owner decision.

Options:

1. Approve a writer/backend and version that demonstrably supports deletion-vector
   upsert, together with any required optional extra and dependency-floor decision.
2. Amend Wanted item 4 to permit file-rewriting upsert, accurately documented.
3. Split item 4 into a deferred package and authorize the remaining items now.

Recommendation: option 1, after a local capability proof showing deletion-vector
log actions and unchanged original data files. Do not claim that setting
`delta.enableDeletionVectors` implements deletion-vector upsert, or manufacture
transaction-log changes outside the writer's supported API.

## Evidence

The existing Delta protocol tests ran before implementation:
`pytest tests/generation/test_delta_protocol.py -q`, with `SHAPE_KERNEL=python`:
exit **0**, `6 passed in 0.62s`.

A local temporary table experiment used installed `deltalake` **1.6.6** and
`pyarrow`, without credentials or network access:

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import json
import deltalake
import pyarrow as pa

with TemporaryDirectory() as root:
    table = Path(root) / "table"
    deltalake.write_deltalake(
        table,
        pa.table({"id": [1, 2], "value": ["old", "keep"]}),
        configuration={"delta.enableDeletionVectors": "true"},
    )
    delta = deltalake.DeltaTable(table)
    print(deltalake.__version__, delta.version(), delta.protocol())
    print(delta.merge(
        pa.table({"id": [1, 3], "value": ["new", "insert"]}),
        "target.id = source.id",
        source_alias="source", target_alias="target",
    ).when_matched_update_all().when_not_matched_insert_all().execute())
    actions = [json.loads(line) for line in
        (table / "_delta_log" / "00000000000000000001.json")
        .read_text().splitlines()]
    print(sum("deletionVector" in action.get("add", {}) or
              "deletionVector" in action.get("remove", {})
              for action in actions))
```

Observed protocol: reader **3**, writer **7**, with `deletionVectors` in both
reader and writer features. It additionally advertises `variantType` and writer
features `appendOnly` and `invariants`. Version advanced from **0** to **1**.
Merge reported:

- `num_target_rows_inserted=1`, `num_target_rows_updated=1`;
- `num_target_rows_deleted=0`, `num_target_rows_copied=1`;
- `num_target_files_added=1`, `num_target_files_removed=1`;
- `num_output_rows=3`.

The version-1 log contains an `add` for a new Parquet file and a `remove` for the
original Parquet file; **zero** actions have a `deletionVector` field. This is a
file rewrite, including the unmatched row. Experiment exit **0**.
