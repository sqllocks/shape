# FIX-684: bound every member of a share bundle (`shape share-bundle verify`)

Branch `fix/684` (from `fix/DEMO-LIVE` at 1d4e0313). Issue sqllocks/shape#684.

## Problem

`share_bundle.verify` read `manifest.json` with an unbounded `zf.read`, and streamed every
`data/*` member to disk with no per-member, total-size or compression-ratio limit, so a ~40 KB
bundle could take ~1.2 GB. Only `attestation.json` was size-limited, and an oversize one was
reported as "not valid JSON".

## Diff summary

- `src/shape/share_bundle.py`
  - New module constants `MAX_MEMBERS`, `MAX_DATA_MEMBER_BYTES`, `MAX_DATA_TOTAL_BYTES`; the
    expansion rule imports `MAX_EXPANSION` and `MAX_PLAIN_BYTES` from `shape.io.excel` (the
    Excel reader's zip-bomb guard, #282/#563) instead of new constants.
  - `_check_sizes` (after `_check_names`, before anything is read or extracted): member count,
    the two JSON members against `_MAX_JSON_BYTES`, each data member against the per-file limit
    and the expansion rule, then the data total against the total limit and the expansion rule.
  - `_read_json`: reads the attestation and the manifest with `read(_MAX_JSON_BYTES + 1)`, so the
    bound holds even when the header lies.
  - `_stream_member`: copies data members in 1 MiB chunks, counting the bytes actually inflated;
    more than the header declared, more than the per-file or total limit, or past the expansion
    rule stops before the chunk is written. Read errors (bad CRC, a truncated stream) become
    `BundleError`.
  - Every refusal is a `BundleError` (exit 2) naming the member and the limit, never data. The
    extraction directory is a `TemporaryDirectory`, removed when the refusal propagates.
- `tests/w5_10/test_share_bundle.py`: nine `test_684_*` tests (below).
- `docs/SHARE_BUNDLE.md`: the limits table and the exit-2 row; `CHANGELOG.md`: Unreleased entry.

## Limits and why

| limit | value | why |
|---|---|---|
| members | 10,000 | same as the `.shape` container reader (`artifact/io.py` `max_members`) |
| `attestation.json`, `manifest.json` | 8 MiB | the existing `_MAX_JSON_BYTES`; real ones are KiB |
| one data file | 2 GiB | generous for generated tables; `verify` loads every table into memory anyway |
| all data files | 8 GiB | same reason |
| expansion | > 100x once > 16 MiB, per file and in total | reused Excel guard; CSV/JSONL pack 3-20x, Parquet ~1x, deflate tops out near 1000x |

With the expansion rule, a bundle must be at least 1/100 of what it inflates to past 16 MiB, so a
small bundle can no longer fill the disk.
