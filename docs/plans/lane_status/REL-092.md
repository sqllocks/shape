## Validator root cause and regressions

The global raw-string-list guard scanned legitimate schema-column names in
`tables.<table>.sampling.internal[].columns` as data. The fix grants only an
exact structural-path exemption for unique string references present in that
same table's column mapping, within the documented sampling-entry fields.
It never grants an exemption by a field name or an object identity, and still
PII-scans every string. Empty/malformed dataset/table structures fail closed.
No count floor, PII regex, extreme-pair rule, full-capture rule or tolerance changed.

`tests/privacy/test_rel092_dataset_validator.py` exercises actual CLI dataset
captures with internal sampling, plus raw sensitive values, full captures, leaking
per-table payloads, malformed datasets, unknown-column lists, renamed metadata,
nested leaks, PII-looking column references and an aliased list outside metadata.
The existing safe-validator tests are unchanged.

Tests-first observations: reference replacement tests 2 failed before data changes;
actual dataset metadata regression 1 failed/11 passed before the exemption;
additional malformed structures 2 failed/13 passed before structural refusal;
FHIR synthetic coding regression failed before local code-system routing.
