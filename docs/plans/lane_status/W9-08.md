## Semantics

The Event Hubs SDK offers writable AMQP message creation time. `timestamp=event_time`
sets that native field, not service-owned enqueue time. Read metadata prefers creation
time and falls back to enqueue time. Kafka receives producer timestamp milliseconds.
This implements the issue's message timestamp requirement without an Owner decision.

Keys remain binary on read. Header/property maps use binary values, or JSON text with
hex-encoded values when `nested=False`. Null key components become empty strings;
composite keys join components with `|`. Submillisecond event time is truncated to
transport milliseconds. Metadata columns are excluded from drift unless explicitly
selected. Legacy default keys, envelope bytes and synthetic metadata names remain.
No new persistent format or core dependency was introduced; the existing profile
format has a save/load compatibility test. The SQL/CSV/JSON byte corpus is unchanged; the lead-authorized additive CLI snapshot refresh is recorded below.
W9-09 has not started.
