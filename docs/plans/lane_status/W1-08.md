## Deliverables

1. **Planted-drift sweep.** `tests/diff/test_drift_sweep.py`. Pairs come from `DriftPlan` (11
   events), the generation engine's row counts (2) and `shape.chaos.groundtruth` corruptions (6);
   each is an answer-key entry (column, kind, size, kinds that find it). Asserts zero misses and
   the false-positive bounds (5% of same-distribution pairs with any change, 0.5% of column
   comparisons; documented in `docs/DRIFT.md`). Tests first: against the original engine the sweep
   failed 3 tests (missed row-count changes; 26/50 quiet pairs noisy; `distribution_change` fired).
   Negative check inside the suite: blinding the detector to one kind fails the sweep.
2. **`row_count_change`.** `tests/diff/test_row_count_change.py` (boundaries, empty table, dataset,
   thresholds, bad values, stream window, monitor). Medium severity, thresholds
   `row_count_ratio_max` = 2.0 and `row_count_ratio_min` = 0.5.
   - Defaults are 2.0 and 0.5, not 1.5 and 0.67: existing tests
     (`test_unique_ids_with_a_different_row_count_...`, a 1.54x extract) require that size to be
     quiet, and I did not change them.
   - Not applied to stream windows (existing `test_a_window_profile_can_be_passed_to_diff`
     compares a 600-row window with a 6,000-row baseline and expects no change); `ShapeMonitor`
     drops the kind (its buffer is a window).
3. **Quieter `distribution_change`.** `tests/diff/test_distribution_change_sample_size.py`. A
   changed family name is reported only when the KS distance between the samples exceeds the
   alpha = 0.001 critical value for their sizes (no 0.10 floor); without quantiles, only samples
   of `min_rows` or more. Justification, sweep numbers (same-distribution pairs):

   | | pairs with a change | column FP rate | `distribution_change` fires |
   |---|---|---|---|
   | before, fast (2,000 rows, 50 pairs) | 26 (52%) | 6.4% | amount 21, score 8 |
   | before, full (20,000 rows, 400 pairs) | 203 (50.7%) | 6.1% | yes |
   | after, fast | 0 | 0% | 0 |
   | after, full, both kernels | 2 (0.5%) | 0.06% | 0 (both are `range_change` of the heavy-tailed log-normal column, a known, documented behaviour) |

   No planted change missed after the change: 760/760 (full), 95/95 (fast); both kernels. The
   existing `test_distribution_family_change_is_low` (normal vs uniform) still passes.
4. **CI and nightly.** `ci.yml`: the sweep at fast size under `SHAPE_KERNEL=python` and `rust`
   (it also runs in the main pytest step). `nightly.yml`: new `drift-sweep` job, full size, both
   kernels. `tests/diff/test_drift_sweep_ci.py` checks the workflows, the env switch, the report
   script and that `docs/DRIFT.md` states the bounds. I could not run the workflows here.
