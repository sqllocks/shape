## Needs the lead

1. **Anonymeter cannot be installed through its extra next to Shape core.** Anonymeter 1.1.0 (the
   newest release) declares `numpy<1.27` and `pyarrow<22`; core requires `numpy>=2` (T-07), so
   `pip install 'sqllocks-shape-integrations[anonymeter]'` fails with `ResolutionImpossible`
   (evidence: `pip install --dry-run -e '.[dev]' -e 'plugins/shape-integrations[anonymeter]'`;
   the other five extras resolve). The library itself runs under NumPy 2.4.6 and pyarrow 25.0.1
   when installed with `pip install --no-deps` (plus `numba polars joblib scikit-learn`), and the
   integration tests ran that way. I kept the extra as the issue specifies (`anonymeter>=1,<2`),
   documented the limit and the `--no-deps` install in `docs/plugins/integrations.md`, and did not
   touch T-07. Decision needed: wait for an Anonymeter release for NumPy 2, keep the documented
   workaround, or drop the extra until then.
2. **The manifest has no column names and no failure flag.** Issue item 2 says "schema facets from
   the manifest's columns", but `RunManifest.tables[t]["columns"]` is a column *count*. I did not
   change the manifest. The schema facet is built from the schema of the table's output files
   (`file_paths`, relative to the manifest or absolute); a table whose files are gone gets no
   `schema` facet (tested). Likewise "FAIL when the run failed": the manifest records only
   `validation` (gate to bool), so a run counts as failed when any gate is recorded as failed.
   If a different definition is wanted, the change is in `manifest_view.load` and `lineage.plan`.
3. **Workflow change for the lead** (I cannot edit `.github/workflows/*`): see "CI diff" below.

## Deliverables (issue #84 "Wanted" list)

1. **Plugin skeleton** `plugins/shape-integrations` (`sqllocks-shape-integrations` 0.9.0, lockstep
   with core, pins `sqllocks-shape==0.9.0`), extras `openlineage` (`openlineage-python>=1.20,<2`),
   `mlflow` (`>=3,<4`), `presidio` (`presidio-analyzer>=2.2,<3`), `sdmetrics` (`>=0.18,<1`),
   `anonymeter` (`>=1,<2`), `ibis` (`ibis-framework[duckdb]>=12,<13`, `duckdb>=1.2,<2`).
   Importing imports no third-party library (tested in a subprocess); a missing library exits 2
   with `<name> needs the '<extra>' extra: pip install 'sqllocks-shape-integrations[<extra>]'`
   (`extras.py`; every adapter has a test that hides the library and checks the exact message).
   `scripts/check_plugin_skeletons.py` lists the new distribution (the only existing file touched
   besides docs and the `integration` marker in the root `pyproject.toml`).
2. **OpenLineage** `shape lineage emit` (`lineage.py`, `openlineage_events.py`): START plus
   COMPLETE or FAIL, UUIDv5 run id derived from the Shape run id (OpenLineage needs a UUID; the
   Shape id is in the facet), one output dataset per table with a `schema` facet, run facet
   `shape` (version, runId, engineVersion, reproducibility tuple and dataset id when present;
   schema in `src/shape_integrations/schemas/shape-run-facet.json`). `file://` appends NDJSON;
   HTTP: one POST per event, bearer token only from `--token-env`, no `--token` option (and
   argument abbreviations are off so `--token abc` cannot be read as `--token-env abc`), token only
   over `https` or to a loopback host, redirects are errors, exit 1 on an HTTP error with the status
   and never the token. Events are validated in the tests against copies of the OpenLineage 2-0-2
   and SchemaDatasetFacet 1-2-0 JSON Schemas (fetched unchanged once, in
   `tests/data/openlineage/`, with their origin) and against the facet schema. HTTP is tested
   against a local server.
3. **MLflow** `shape mlflow log` (`mlflow_log.py`): params (tuple), metrics from the verify report
   (`passed`, `gate.<name>.passed|errors|warnings`, numeric details), artifacts (manifest, profile,
   report), tags `shape.run_id` and `shape.dataset_id`; duplicate run id in an experiment refused
   (exit 1) unless `--allow-duplicate`. Tested against a real SQLite tracking store. A test found
   that putting the run id into MLflow's filter string misses a duplicate when the id contains a
   quote, so the id is compared in Python over the paged search instead.
4. **Presidio** detector `presidio` (`presidio_detector.py`): seeded bounded sample (200,
   `SHAPE_PRESIDIO_SAMPLE`), label table (documented, and a test checks that doc and code agree),
   unmapped `presidio:<TYPE>`, confidence = share detected x mean score. Values are never logged,
   printed or in an error (tested with debug logging on and a failing analyzer). Presidio
   downloads a 400 MB model on first use by default; the detector builds its engine without that
   step (pattern recognizers on a blank English pipeline; `SHAPE_PRESIDIO_MODEL` names an installed
   model, a missing one is an error). Name and place entities therefore need that variable.
5. **SDMetrics and Anonymeter** `shape evaluate sdmetrics|anonymeter` (`evaluate.py`,
   `sdmetrics_eval.py`, `anonymeter_eval.py`, `evaluation.py`): report
   `{"format": "shape-evaluation", "version": 1, "tool", "tool_version", "results"}`, `-o`, `--json`,
   `--tables`, `--control`, `--attacks`; exit 0 when it ran, 2 on bad input; no gate touched.
   Compatibility test: committed version-1 reports produced by the real commands
   (`tests/data/evaluation/`), plus refusal of a newer version, another format, a non-integer
   version and an unknown tool. Anonymeter notes: the singling-out attack is seeded, its baseline
   and the other two attacks are not (the first test version claimed otherwise and was corrected).
6. **DuckDB and Ibis** (`duckdb_source.py`, `ibis.py`): source `duckdb`
   (`duckdb://FILE.duckdb?table=T`, read-only, Arrow batches, any other option refused, identifiers
   quoted, missing file never created), and `shape_integrations.ibis.connect(DIR)`.
7. **Documentation** `docs/plugins/integrations.md` (one section per integration: install,
   command or API, what is sent or written, what is never sent), `plugins/shape-integrations/README.md`,
   a pointer in `docs/plugins/authoring.md`, and the `CHANGELOG.md` entry.
