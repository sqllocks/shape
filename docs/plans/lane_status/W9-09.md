## Wanted and implementation

1. Plain Avro `.avsc` and Protobuf `.proto` + `message` writes on both brokers,
   without a registry prefix. Protobuf uses the W5-06 parser and in-process
   descriptors. Schema/type mismatches name fields before sending that batch.
2. Both sources decode both local binary formats; Kafka Avro also resolves
   Confluent wire schema ids. Existing JSON decoding remains available.
   Malformed messages and incompatible pinned reader rows use existing counters.
3. Struct/list/map read/write mappings are retained. Derived registry Avro
   respects nullable collection children. Nested Protobuf keeps logical scalar
   conversions and original enum numbers/names.
4. Azure Schema Registry Avro writes and reads use the optional
   `[schema-registry]` extra and Entra credentials. The Owner approved this item
   in the issue comment. Offline encoder fakes cover both directions; live pending.
5. Writer schemas resolve by message id with per-read caches. Unpinned reads
   group writer ids into separate typed batches and preserve offsets; compatible
   numeric types promote. Explicit reader schemas reject rows that do not fit.
6. EMIT.md, CLI.md, both plugin READMEs, type tables and CHANGELOG updated.

No registry authentication beyond basic/Entra, no Event Hubs JSON Schema, and
no credential literal or URI credential was introduced. Oneof/recursive message
schemas and multi-file Protobuf declarations fail closed as documented.
No stable public module or persisted Shape format changed. Independent Avro
reading and a fixed Protobuf byte sequence provide wire compatibility evidence.
Requirement SHAPE-STREAM-009 has a conformance test for nested rejection without
lossy coercion. Existing nested-refusal coverage now retains its JSON Schema
refusal and adds full Avro/Protobuf nested roundtrip assertions.
