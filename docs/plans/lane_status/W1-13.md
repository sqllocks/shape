## Decisions inside the package

- Profiles record a type family (`integer`, `float`), not a width, so the profile engine never
  sees `int32` → `int64`; `detail.widening` appears where Arrow type names are present (the schema
  drift gate and any change record that names them). Documented in `docs/DRIFT.md`. No new
  drift kind and no change to what the engine reports.
- A planned entry of action `severity` fails the schema drift gate when its severity is `high`
  (as before) or when its class is at or above `fail_on` (new), so the gate is never looser.
- `shape.drift.compare` / `Drift` / `MonitorEvent.changes` carry the class too, so the same change
  is the same answer everywhere (an existing test requires `compare` and `diff` to agree).
- The text output goes to stderr (stdout stays one JSON line, as before).
- The verify configuration file beats `shape.yml` for `classes` and `fail_on`; a `--policy` file
  replaces the project's `classes` whole (the W1-04 rule for policies).
