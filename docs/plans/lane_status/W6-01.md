## Decisions where the issue is silent (please review)

1. **Verdicts follow the exit code**, shared by comment, badge and notification
   (`src/shape/cli/findings.py`): `fail` is any exit code but 0, `drift` is exit 0 with findings,
   `pass` is neither. Planned changes are not findings. The badge keeps the issue's own mapping
   (`unknown` for no result or exit 2).
2. **What `fail-on` does to `shape diff`.** The issue wants a `fail` verdict from a changed source and a
   distinct `drift`. `shape diff` fails only with `--fail-on-drift`, so the action passes that flag
   exactly when `fail-on: drift`: then drift is a `fail`; with `fail-on: fail` drift stays a (amber) `drift`
   and only a command that cannot run, or a failing gate, fails the job. The self-test therefore uses
   `fail-on: drift` for its failing case. The default (`fail`) does not block on drift, as the issue
   specifies; the table is in `docs/PR_BOT.md`.
3. **The action's result documents come from `shape diff --json -`** (`--json FILE` of `diff` keeps
   writing the command's own result, as W1-14 decided).
4. **`shape-version: installed`** (a value the issue does not list) skips the install, so the self-test
   can run the checkout's own Shape; a ref that is not a release number installs the latest release
   with a notice; anything else is refused.
5. **Escaping.** Names are HTML-escaped, Markdown punctuation is backslash-escaped, and an `@` is
   followed by a zero-width space so that it cannot become a mention (rendered text is the name).
6. **Comment author for `post-comment`**: the token's `/user`, or `github-actions[bot]` when `/user`
   is refused (the workflow token). Only a comment of that author that carries the marker is updated.
7. **`--max-findings` is one budget for the whole comment** (sources in the order given, most severe
   first within a source).
8. **`on:` in `shape.yml`.** YAML 1.1 reads an unquoted `on` as `true`; the loader puts the word back
   for notification entries (found by the tests).
9. **`drift` in `on`** fires whenever the result lists findings (verdict `drift`, or `fail` with
   findings), so a gated diff still alerts; `fail` fires on a non-zero exit; `--notify REF` targets
   are `always`.
10. **`notify test` with no project or no notifications exits 2** (nothing to test is not a pass).
11. Notification `findings` are capped at 200 (the counts hold the full number); `verify` lists its
    failed gates as findings, `fidelity` lists none (its exit code is the verdict).
12. A target that cannot be resolved (`env://` unset) is a delivery failure like any other: a warning,
    exit code unchanged.
13. The plugin template's package name is `NAME` itself (hyphens become underscores for the Python
    package); the plugin and entry-point name is `NAME`. The generated CI workflow uses version tags
    for `actions/checkout` and `actions/setup-python` (it is a template for the plugin author, not
    Shape's own workflow).
