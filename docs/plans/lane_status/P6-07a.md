## Python API for P6-13 (sinks, scale router)

All in `shape_fabric` (lazy imports; no Azure/ODBC library loads until used):

* `LakehouseWriter(folder, *, format="parquet|csv|jsonl", credential=None, filesystem=None)`
  `.write_table(table, batches, *, format, directory, file_name, schema) -> rows`, `.write_tables(mapping)`,
  `.write_manifest(path, dict)`, `.write_done_flag(path)`, `.landing_zone(...)`. Folder: local, `abfss://`, `onelake://`.
* `SqlDatabaseWriter(connection_string=None, *, credential, connection, connect, warehouse, schema_name)`
  `.write_table(table, batches, *, write_mode, batch_size, schema_name, columns, primary_key, schema)`,
  `.write_tables(mapping, order=, options={table: {...}}, **common)`, `.create_ddl(...)`, `.close()`.
* `WarehouseWriter(connection_string, staging_path, *, credential, ...)` — same modes; `chunk_rows` replaces `batch_size`.
* `EventhouseWriter(uri, *, token, credential, transport)` `.write_table(table, batches, *, write_mode, kql_table, max_request_bytes)`, `.row_count(t)`.
* `EventstreamWriter(uri, *, connection_string, envelope, partition_key)` `.write_table / .write_tables`.
* `shape_fabric.sinks`: `LakehouseSink`, `SqlDatabaseSink`, `WarehouseSink`, `EventhouseSink`, `EventstreamSink` implement
  `Sink.write(uri, table, batches, **options)`. **Not registered as entry points**, so P6-13 chooses names (`lakehouse`, `warehouse`,
  `sql_database`, `kql`) without a collision.
* Source: entry point `shape.sources: onelake` (`LakehouseSource`): `onelake://ws/lakehouse/Tables/t` (Delta) and `.../Files/p`, delegating to core's abfss/Delta sources.
* Also: `shape_fabric.onelake` (parse, `https()` for COPY INTO, landing-zone layout), `WriteResult`, `WriteError(.result)`, `AuthError`.
* Auth (for P6-07b): every writer takes `credential` = object with `get_token(scope)` or a function `scope -> token` (`shape_fabric._auth`).
  SQL scope `https://database.windows.net/.default`, storage `https://storage.azure.com/.default`, Kusto `https://<host>/.default`.
  `--auth` modes and `env://`/`kv://`/`file://` references belong to P6-07b: build a credential and pass it in.
* Option names: `write_mode` ∈ `create|append|truncate|replace` (Shape's own; default `create` never touches an existing table), `batch_size`, `staging_path`, `connection_string`, `schema_name`, `columns`, `primary_key`.

## Baseline defects found and fixed (owner's standing decision, 2026-10-01)

1. Default mode dropped and recreated existing tables (`DROP TABLE IF EXISTS` in the default write mode, also on the bulk path). Now `create` fails on an existing table; destructive modes are explicit.
2. Unescaped identifiers in SQL and KQL (`[{name}]`, `['{name}']`) — injectable. Fixed.
3. `COPY INTO` location string-built into the statement. Validated whitelist.
4. Bulk load: staged files leaked on failure (cleanup not in `finally`); loaded-row count could over-report (fallback `COUNT(*)` on append). Cleanup always runs; loaded must equal staged; before/after counting.
5. Silent fallbacks: schema-creation failure swallowed, bulk-writer init failure fell back to row inserts with a log line. Now errors.
6. Per-table failures collected and the run continued (callers had to inspect `errors`). Now fail fast with `WriteError.result`.
7. Eventhouse "rows written" counted queued (async) ingestion as success; a fixed 5 s sleep. Now synchronous streaming ingestion, counted only when accepted.
8. Manifest/done-flag writes were local-only; OneLake writes of data could leave a half-written blob. Control files go through the same storage layer; partial files are removed.
9. Unrecognised booleans silently NULL — N/A for typed Arrow input.
Also found in Shape's own P5-02 code: the Eventhouse JSON mapping command did not escape backslashes in its KQL literal, so a KQL engine would have turned `\"` into `"` and broken the mapping for every column. Fixed in `kusto.py` with a regression test (fails on the old code; verified).
New: batches of one table must have the first batch's columns in the same order (else values would land in the wrong columns).
