## Escalation 2 - GEN-IN at medium (4.7x-7.7x; gate 10x)

All four are sub-second (Shape 0.11-0.42 s) or near-sub-second workloads, the situation of P6-01a's Escalation 2.
Profile (cProfile, in-process, pulse and telecom at medium, warm): generation is 0.24 s whether run with 1 or
4 threads; there is **no domain-specific hot spot**. The time is spread evenly over shared native kernels and
engine steps (`philox_uniform`, `alias_sample`, `pool_take`, `template_strings`, Arrow `take`/`cast`/`fill_null`),
with two noticeable shared items: the Zipf foreign-key index (`_relational.zipf_index`: `numpy.searchsorted`,
about 23 of 270 ms for pulse's 500k trips) and the post-generation rule validation (`validate_rules`, about 30 ms).
Both are engine code that retail and the P6-01a domains also run, so I did not touch them here (the round-2
lane on lane/P6-01a owns engine-wide work). Per-row cost of the baseline here is 1.6-3.1 us, so 10x means
0.17 s (pulse), 0.05 s (real_estate), 0.07 s (supply_chain) and 0.33 s (telecom) for the whole run including
loading and writing. After the round-2 work lands, merge `origin/lane/P6-01a` and re-run
`bench.py --impl shape --domain D --scales medium --runs 5 --warmup 1`; this branch did not contain it when it was
measured.
