## Deliverables (issue #95 "Wanted" list)

1. **Source `semantic-model`** — `shape_fabric.semantic_source`, entry point `shape.sources:
   semantic-model`, `semantic-model://<workspace>/<model>/<table>` (percent-encoded parts).
   `schema()` from `list_columns` (no rows read, tested), `read()` via `read_table`, batches of at
   most `batch_rows` (default 65,536); options `columns`, `max_rows` (DAX `TOPN` through
   `evaluate_dax`; boundaries 0, 1, = row count, above it, and invalid values tested), `mode`.
   Tests: `plugins/shape-fabric/tests/test_semantic_source.py`. Passes the W1-05 kit
   (`kit.check_source`). `shape profile semantic-model://… -o` works through the host.
2. **Type map** — `TYPE_MAP` (Int64, Double, Decimal and Currency as decimal128(19,4), String,
   Boolean, DateTime as timestamp[us], Binary); unknown types read as string, warning once on
   stderr in the issue's wording; hidden columns included, `hidden: true` on the Arrow field and,
   from `profile-model`, in the profile's column metadata. A test keeps the docs table equal to the
   code map. **Gap:** a plain `shape profile semantic-model://…` of one table does not put
   `hidden: true` in the profile (the reference profiler drops Arrow field metadata; carrying it
   would change `shape.profile.reference`). `shape profile-model` does.
3. **`shape profile-model WORKSPACE/MODEL -o OUT.shape [--tables] [--max-rows] [--json]`** —
   `shape_fabric.commands:ProfileModelCommand` (+ `shape_fabric.semantic_profile`). Column
   statistics equal profiling the same rows from Parquet (tested). Relationships recorded with
   `evidence: "declared"`, `source: "semantic model"`, `type`, `active`; inactive kept with
   `active: false` (still a declared key); many-to-many recorded, not a foreign key. The "one" side
   becomes the table's primary key when the profile has none. `--json` is a bare flag (prints one
   JSON document). Tests: `test_profile_model.py` (also round trip and format/version of the saved
   `.shape`; the format is the existing `shape` / version 1, unchanged).
4. **sempy imported only on open** — a subprocess test shows `sempy` absent from `sys.modules`
   after importing the plugin and calling `can_open`; the missing-package and cannot-sign-in cases
   give the issue's one line, exit 2. Extra `semantic-link = ["semantic-link-sempy>=0.8"]` on the
   plugin only (a test checks the core `pyproject.toml` has none).
5. **Errors name the object** (unknown workspace, model, table, column; exact wording tested) and
   DAX names are quoted with `dax_table` / `dax_column` of `shape_fabric.semantic_model`. Result
   columns are aliased by position (`c0`, `c1`, …), so no name is used as an alias.
6. **Tests without Fabric** — `fake_sempy.py` (registered by `tests/conftest.py`; it parses the DAX
   strictly, so a name that escaped its quoting fails). Live test
   `test_live_semantic_model.py` (marker `live`; needs `FABRIC_WORKSPACE_ID`,
   `FABRIC_SEMANTIC_MODEL`) was **not run**.
7. **Docs** — `docs/plugins/cloud-sources.md` (section), `docs/plugins/fabric-commands.md`
   (`profile-model`), `integrations/fabric/RUNBOOK.md` (section 13), `CHANGELOG.md`.
