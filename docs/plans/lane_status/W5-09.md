## Decisions I made where the issue was silent (for the lead to confirm)

- **Registry location.** `--registry NAME` needs `--registry-root DIR` (there is no default root).
- **Registry content.** Registry mode takes raw profiles (`--allow-raw` commits, `.shape` or
  `shape profile export`) only. A safe profile is refused with exit 2: `shape.diff` on a safe
  document silently returns no changes, so using it would report a false "no drift".
- **Run dates.** Files: the first `YYYY-MM-DD` in the file name, else none. Registry: the commit's
  `business_date`, else its UTC commit date. `--since` keeps the commit before the cutoff as the
  first baseline and is refused with files.
- **`threshold` column.** The diff records carry no threshold, so it is the setting of the kind
  (`THRESHOLD_KEYS`; the upper bound when a ratio rose), read from the thresholds that applied to the
  column; a test keeps the table in step with `KIND_SEVERITY` and `DEFAULT_THRESHOLDS`.
- **Slices.** A measure is sliced only by the same table or one reached many-to-one; others, and
  slices with two relationship paths, are omitted and listed under `skipped` (retail's `order_line`
  measures by `customer.*` are skipped: two paths).
- **Plant bounds.** From the generator's `min`/`max`, `low`/`high`, a choice's values or a constant,
  inside the column's precision; none declared means 0 as the lower bound. A plant changes the final
  table only (a computed column is not recomputed); documented.
- **Float columns.** Sums of float columns are compared at the answer's places (inexact), counts,
  min, max and integer/decimal sums exactly.
- **Duplicate default measure names.** The exporter writes the same measure name on several tables
  (retail `Total Unit Price` on `product` and `order_line`), which a deployed model would reject. I
  did not change the exporter (the 1:1 harness pins it); queries qualify measures by table.
- `publish-report` is also registered as `shape fabric publish-report`, like the other commands.
- `check-answers` accepts a Power BI `executeQueries` response and a `query` column / id-keyed JSON
  for the single-file form (the issue says "one file" without a layout).

## Lead's decisions applied (second pass)

1. **Registry flags.** `--registry NAME` requires `--registry-root DIR`; no default root, no new
   environment variable; the existing errors and tests are unchanged.
2. **Profile safety.** Registry mode and file inputs read raw profiles only. A safe profile in either
   is refused with exit 2, naming the profile and telling the user to commit raw profiles
   (`--allow-raw`); a safe profile never reports "no drift". New: `file_sources` checks
   `is_raw_profile`; test `test_a_safe_profile_file_is_refused` (file path) next to the existing
   `test_a_safe_profile_in_the_registry_is_refused` (registry path). `docs/DRIFT_REPORT.md` says so.
3. **Skipped slices.** Still omitted and listed under `skipped` with the reason. New: `known-answer`
   prints `shape: N (measure, slice) pair(s) skipped; see `skipped` in answers.json` on stderr when
   N > 0; `docs/plugins/fabric-commands.md` says which pairs are skipped and why. Tests: the
   skipped-slice and two-path tests and the retail domain test assert the stderr line and that its
   N equals `len(answers["skipped"])` (retail at `fabric_demo` skips 125 pairs, nearly all
   one-direction ones: a parent table's measure by a child's or unrelated table's attribute).
4. **Run dates, `--since`, `threshold` column:** as built.
5. **As built:** plant bounds (none declared = 0 lower bound, documented); float sums at the answer's
   places, counts/min/max and integer/decimal sums exact; exporter default output unchanged;
   `shape fabric publish-report` alias and the `executeQueries` input stay.
