## Findings for the lead (not fixed here, out of scope)

1. **`shape/schemas/generation-spec-v1.schema.json` is stale on the merged tree.** `build_schema()`
   now includes `conditional_table`, `hierarchy` and `hierarchy_field` (strategies that reached
   `build/main-plan` before W1-06), the shipped file does not, so the existing
   `tests/generation/test_w1_06_spec_schema.py::test_the_shipped_file_is_what_the_builder_makes`
   fails. Fix (changes the shipped schema, so left to the lead): `python -m shape.generation.spec_schema`
   and commit. My pin (`published_schema()` equals the shipped file) holds either way.
2. **`SpecDocument.load(path)` does not preserve CRLF line endings** (`Path.read_text` translates
   them), so a CRLF file is not written back byte for byte; `loads(text)` is exact. The pinned
   behaviour is stated for LF files and for `loads`; the promise therefore does not cover CRLF files
   through `load`. Raise on W1-06 if it should (`read_bytes().decode()` would fix it; that is a
   behaviour change, so not done here).
3. Workflow change needed (cannot edit `.github/workflows/*`): none required; the check runs inside
   `pytest` (`tests/api/test_stable_api_compat.py`), which `make check` and CI already run. If the lead
   wants it as its own CI step, add `python scripts/stable_api_compat.py --check` next to the
   `plugin_api_compat.py --check` step.
