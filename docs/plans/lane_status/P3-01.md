## P3-01 — Stream runtime

Fixes: S3.

### What was built
- `src/shape/streaming/runtime.py`: `TumblingProfiler`, `SlidingProfiler`, `SessionProfiler`,
  `GlobalProfiler` (one `WindowedProfiler` base), `WindowProfile`, `restore_profiler`. Micro-batches
  (Arrow record batches) go through the kernel's bounded-mode `ProfileState` (P1-06/P1-07,
  numerics untouched); windows close on the watermark (`max event time - allowed_lateness`, advanced
  at batch boundaries); late rows are counted and dropped or sent to `late_sink`; `snapshot()` is a
  JSON-safe dict and `restore()` rebuilds the profiler. Sliding windows merge `gcd(size, slide)`
  panes; a one-pane window is not merged (it equals the batch profile of its rows).
- Kernel (both kernels, one byte format): `ProfileState.snapshot()` and
  `ProfileState.from_snapshot(schema, bytes)` for bounded mode (`rust/shape-kernel/src/profile.rs`,
  `sketch.rs` accessors, Python twin in `kernel/reference/profile.py`, `_kernel.pyi`). Existing
  numerics are unchanged.
- `profile/engine.py`: `table_entry()` split out of `profile_table` so a window's profile has the
  batch layout. No behavioural change.
- S3: `TumblingWindow.restore()` (`streaming/windows.py`); the module is now strict-typed and off the
  mypy ratchet list.
- `docs/specs/STREAMING_SEMANTICS.md`: Draft 2 (time, windows, watermarks, late data, snapshots).
- Tests: `tests/kernel/test_profile_snapshot.py`, `tests/streaming/test_runtime.py`,
  `tests/streaming/test_windows.py` (S3 regression: fails on the old code).

### Notes for the lead
- The two kernels add floating-point moments in different orders (Rust per row, the Python twin per
  batch), so equal input does not give equal snapshot *bytes* across kernels. Each kernel reads the
  other's snapshot, and a restored state continues exactly like an uninterrupted one in the same
  kernel (tests cut on batch boundaries for that reason).
- Gate G3 evidence in the test suite: `test_replay_of_d2_in_bounded_mode_equals_batch_bounded_profiling`
  (D2 generator at 60,000 rows, micro-batches of uneven size, bounded stream replay equals bounded batch
  profile, top values and quantiles equal, error models equal) and
  `test_results_are_identical_across_processes` (`PYTHONHASHSEED` 0, 1, random; both kernels).

## P3-02 — Keyed state

Fixes: S2, S5.

### What was built
- `streaming/keyed.py` (rewritten, strict-typed, off the mypy ratchet): `KeyedState` and
  `PartitionedKeyedState` keep their API; S2 fixed (the expiry heap is rebuilt from the live entries
  once it passes `2 * max_keys + 64`). New `KeyedSketches`: a sketch per key (event count; count,
  mean, variance, min, max of finite values; first and last event time; optional per-key HyperLogLog)
  in numpy arrays fixed by `max_keys`; LRU (chunked eviction), TTL (sweep every ttl/16, exact reads),
  `for_budget()`, JSON-safe `snapshot()`/`restore()`. A batch is a handful of array operations plus
  one dict lookup per *distinct key*, not per event.
- `streaming/dedupe.py`: `Deduplicator`, a vectorized windowed duplicate filter (sorted numpy runs, a
  small LSM): exact for integer keys, XXH3-64 identity otherwise; `max_keys` cap (oldest first-seen
  forgotten), optional event-time `ttl`; snapshot/restore.
- `streaming/vectorized.py`: S5, `deduplicate_ids` asks the set once per distinct id (`np.unique`),
  strict-typed.
- `Makefile` and `.github/workflows/ci.yml`: the heavy pytest step also covers `tests/streaming`.
- Tests: `tests/streaming/test_keyed_state.py` (24 fast tests + 1 heavy).

## P3-03 — Checkpoints and offsets

Fixes: S4.

### What was built
- `streaming/consumer.py`: `StreamConsumer(source, uri, profiler, store, ...)` reads a `StreamSource`
  (`read(uri, start)` of the plugin protocol) into a windowed profiler, commits a checkpoint (source
  offset, dedupe positions, counters, profiler snapshot) every `checkpoint_every` processed batches
  and at the end, resumes from a checkpoint, reconnects after `ConnectionError`/`TimeoutError` from the
  offset after the last processed batch, and deduplicates on offset (integer offset column, optional
  partition column, row level; or the `{partition: next offset}` map, batch level). Windows are
  yielded before the checkpoint that covers them is committed (at-least-once delivery of windows;
  identity `(kind, start, end)`); the profile state is exact. The reconnect bound counts consecutive
  connections that bring nothing new.
- `streaming/checkpoint.py` (strict-typed, off the ratchet): atomic JSON documents next to the old
  `StreamCheckpoint` API, `CheckpointError` for unreadable or mismatched checkpoints.
- `connectors/qualification.py` (strict-typed, off the ratchet): S4, `reconnecting_batches(connect,
  max_attempts)` resumes with `connect(start)` from the offset after the last yielded item (a
  zero-argument `connect()` is still accepted and skipped by position); the attempt bound counts
  consecutive failures, progress resets it.
- `docs/specs/STREAMING_SEMANTICS.md` section 6 (checkpoints, reconnect, dedupe on offset, delivery
  guarantees reported separately).
- Tests: `tests/streaming/test_consumer.py` (19 tests).

### Acceptance
- `test_across_100_forced_reconnects_the_output_equals_an_uninterrupted_run` (tumbling and global
  profilers): a source that fails 100 times, redelivers up to 10 rows before the resume point and cuts
  every reconnection into different batches; after deduplication on offset the windows equal the
  uninterrupted run's (counts and bounds exact, profile numbers within 1e-9), `c.reconnects == 100`,
  rows replayed and dropped > 0, every row reached the profiler once.
- `test_a_killed_consumer_resumes_from_its_checkpoint`: crash (non-transport exception) at 6 points,
  tumbling and sliding windows, `checkpoint_every` 1 and 4: the windows from the killed run plus the
  resumed run, keyed by `(kind, start, end)`, equal the uninterrupted output.
- S4 regression `test_s4_reconnect_does_not_replay_what_was_already_yielded` fails on the old code
  (output above).
