## Decisions where the issue is silent (please review)

- **Class of a column:** `CONFIDENTIAL` when the safe profile's personal-data gate fires (pattern, or
  nearly every value distinct) or a name/pattern PII proposal is at least 0.3; `INTERNAL` otherwise;
  a `classification` annotation in `shape.yml` can only raise it, unknown label = `CONFIDENTIAL`.
  Consequence: key-like columns (all values distinct) are `CONFIDENTIAL` too.
- **Numeric range is withheld** for `CONFIDENTIAL` and above (a minimum and maximum are values).
- **Generation spec schema:** W1-06 is not in this tree. The build skips `generation-spec-v1.schema.json`
  with a message and leaves `jsonValidation` out of the *packaged* manifest (`stage/package.json`);
  the committed `package.json` keeps the entry, so it works as soon as W1-06 lands and the build runs.
  `*.gen.json` validation is therefore **not exercised** in this lane.
- `npm run package` packages from `stage/` (what the tests also run), not the source folder.
- `shape.path` has `machine` scope (a repository cannot make the extension run its executable);
  workspace trust is "limited".
- Minimum `shape` version `0.9.0` (`MIN_VERSION`, the first with `shape cat`).
- `jsonschema>=4.18` added to the `dev` extra of `pyproject.toml` (the snippet and schema tests use it).
- The `.shape` custom editor opens the text document and closes its own tab (a custom editor needs a
  webview; the read-only text document is the real view).

```yaml
    runs-on: ubuntu-latest
    defaults: {run: {working-directory: editors/vscode}}

      - run: npm run package

        with: {name: shape-vscode, path: editors/vscode/shape.vsix, if-no-files-found: error}
```
