## Decisions where the issue is silent (please review)

- Envelope: the command's own keys stay at the top level next to `format`, `version`, `command`,
  `exit_code`. Text output is under `output` (and on stderr); a list is under `payload`; when a payload
  key is named like an envelope key (`generate` prints `format`) the whole payload is also under `payload`
  and the envelope wins at the top level. `error` carries the one-line message on exit 2.
- `--json FILE` (diff, check, profile, design) is unchanged; `--json -` prints the envelope.
- Messages in JUnit/SARIF never carry data values. Verify gate text is not included (gate errors can
  quote values); only counts. Leak-scan detail is never included. W1-11 and W1-12 are absent, so there
  is no `suppressed` or `planned` source yet; the code honours `change["planned"]` and `change["suppressed"]`.
- `--dry-run` validates arguments, that inputs exist, that outputs are not below a file, and the state
  `init`, `keygen`, `git-setup`, `jobs`, `profile registry`, `proposals` need. It does not parse the
  content of inputs. `generate`, `demo run`, `demo cleanup` keep their own `--dry-run`.
- `version` and `bridge` (server) get neither flag; reasons in the exemptions file. The walker treats
  `bridge` as a command because it runs without a sub-command.
- `ci.json` writes the envelope to a file for the five checking commands when no `--json` is given.
