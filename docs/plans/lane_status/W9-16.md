## Approved decision and scope

The lead approved issue #17's extra on 2026-10-08:
`pyiceberg[pyarrow,sql-sqlite,pyiceberg-core]>=0.9`. This resolves the previous
transform-dependency blocker. The partial tests-first implementation was committed
as `e1b87f063`; the finishing commit completes the Wanted list.
No dependency was added to the production base install. Only the optional
`[iceberg]` extra installs PyIceberg. Core test, minimum-version and zero-network CI
jobs explicitly install it so actual SQLite/file acceptance runs on every PR.
No dependency or setup change was made to the benchmark harness.

Named REST, SQL, Glue and Hive options are accepted, credentials are references,
and the local URI creates a SQLite catalog without configuration. Native types,
partition transforms, overwrite/append, snapshot micro-batches, fingerprints,
time travel, namespace profiles, CLI and additive bridge API 1.2 URI targets are
implemented. Native UUID adapters cover both PyIceberg 0.9 and current releases;
there is no upstream monkeypatch or dependency-floor increase.

Decimal precision is at most 38 and native Iceberg scale is in `[0, precision]`;
unsupported scales fail before catalog writes, naming the column. Nanosecond
truncation is explicit. String UUID metadata reads canonical UUID text. Schema and
partition evolution, MERGE, deletes, format 3 and maintenance remain out of scope.
