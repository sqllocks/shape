# W9-16 — Apache Iceberg sink and source

Status: implementation in progress. On 2026-10-08 the lead approved the issue #17
extra `pyiceberg[pyarrow,sql-sqlite,pyiceberg-core]>=0.9`. The previous dependency
question is resolved. This commit preserves the tests-first partial implementation;
remaining Wanted coverage and CI-compatible local checks follow before final push.

## Reproduction evidence

Installed the exact declared extra into an isolated temporary environment:
`pip install 'pyiceberg[pyarrow,sql-sqlite]>=0.9'`, exit 0, PyIceberg 0.12.0.
Calling each upstream transform's `pyarrow_transform` with a valid Iceberg type:

- `DayTransform()` and `MonthTransform()` with `TimestampType()`;
- `BucketTransform(16)` with `IntegerType()`;
- `TruncateTransform(4)` with `StringType()`.

All four raise `NotInstalledError`, naming
`pip install "pyiceberg[pyiceberg-core]"`.
Package metadata declares `pyiceberg-core<0.11.0,>=0.10.1` exclusively under
`extra == "pyiceberg-core"`.

Checked PyIceberg 0.9.1 separately: day and month are available, but bucket and
truncate raise `ModuleNotFoundError: No module named 'pyiceberg_core'`.
Its metadata declares `pyiceberg-core>=0.4.0,<0.5.0` exclusively under the same
extra. Selecting the older allowed version therefore does not satisfy Wanted 2.

The actual SQLite/file acceptance reproduces the four transform write failures;
the sink scrubs upstream errors rather than exposing storage credentials.
