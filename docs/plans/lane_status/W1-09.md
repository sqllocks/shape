## Separator rule (decided here)

- A **URL** (`scheme://`) is joined with `/`.
- A **local path** is joined with the platform's separator; a result never mixes the two.
  `run_gate.join_location` implements it; `_upload` and the generate gate use it, so
  `artifactUrl` / `contractUrl` for a local output equal `str(Path(output) / name)`.
- Paths a CLI **prints as relative** (for example `demo/make_data.py`'s file listing) use forward
  slashes (`as_posix()`), so the output reads the same on every platform.
- Tests assert these rules, not a platform accident.

## Spark on Windows: NOT fixed by code; needs a CI step

Every one of the 38 errors is the same, at `JavaSparkContext` creation:
`java.io.FileNotFoundException: HADOOP_HOME and hadoop.home.dir are unset` (`WARN Shell: Did not
find winutils.exe`). Spark 4's Hadoop client needs `winutils.exe` and `hadoop.dll` on Windows
(`HADOOP_HOME\bin`). Plan §2.3 records no Windows exclusion for Spark tests, and I did not add one.
I could not provision the binaries from here (downloading them was refused in this session, and I
would not fetch an unverified binary inside a test fixture anyway).

**Lead action:** in `fabric-demo-windows` (`.github/workflows/nightly.yml`, which this lane cannot
edit), add a step before pytest that installs a Hadoop 3.4.x `winutils.exe` + `hadoop.dll`
(pinned and checksum-verified) into a directory and sets `HADOOP_HOME` to it and prepends
`%HADOOP_HOME%\bin` to `PATH`. Then dispatch Nightly on `lane/W1-09`.
