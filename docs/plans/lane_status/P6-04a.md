### Built on Shape's pieces, nothing duplicated

* **Generation engine and domains:** the tables a simulator gets come from `Engine(...).generate()`
  (`shape simulate` and the tests); the simulators take any Arrow tables, a generation result or
  pandas frames.
* **Emit runtime** (`shape.streaming.emit`): `StreamEmitter` builds a counted, resumable event
  sequence (`TablesEventPlan`) and runs it with `EmitRunner`: pacing (`RateSchedule`, bursts),
  backpressure, retries, the sinks (`StdoutSink`, `FileSink`, `EmitterSink` through `open_sink`), the
  event fields `with_event_fields` writes (`_shape_table`, `_shape_seq`, `_shape_event_time`), the
  JSON conventions (`rows_of`) and the vectorised encoder.
* **Emitters:** any `shape.emitters` URI (`kafka://`, `eventhubs://`, `eventstream://`) is a stream
  sink with no code of this lane.
* **File sinks** (`shape.sinks`: parquet, csv, jsonl): `write_table` is the one writer of file drop,
  SCD2 drop and hybrid; it is also what `shape generate` and `shape pack run` write with.
* **Scenario packs** (`src/shape/scenario`): read in full. A pack's `file_drop`, `stream` and
  `hybrid` kinds *write the landing once* (one file per entity, one JSON Lines file per topic); they
  do not simulate a clock (`docs/SCENARIO_PACKS.md`), and the baseline's own pack runner does the same
  and never calls its simulators (checked: its `packs/runner.py` writes with its pandas writer).
  So the two are different features, not two implementations of one: there is no code to merge, and
  the pack runner already writes through the same sinks. The pack's timing fields stay descriptive
  (validation warns when they are on). I did **not** make `shape pack run` delegate to the simulators
  when a pack turns lateness, duplicates or a backfill on: that would change the output of packs the
  P6-14 parity harness (`pack_1to1`) checks against the baseline. It is a natural follow-up
  (additive: only when a pack opts in); `docs/SCENARIO_PACKS.md` and `docs/SIMULATION_FILES_EVENTS.md`
  point from one to the other. **Question for the lead:** do you want that delegation as its own work
  package?
* **Chaos** (`shape.chaos`): not used by these five (the baseline's five do not use it either);
  `shape emit --anomaly-fraction` already covers value faults in a stream.

## Design: how parity is possible, and what was deliberately not copied

The simulators are Arrow/NumPy ports that **draw their random numbers in the baseline's order**
(per entity: per slot lateness, then duplicates; then backfill, then restatements; the stream's
swaps first, then per event the jitter and the replay decision; per workflow step the transition,
the anomaly roll, the dwell time; the SCD2 draws in the order the changes are made, including the
draw a missing number makes in the baseline). The same seed on the same tables therefore gives
the same decisions, and the harness checks exact equality, not only distributions.

Names (D-13): `_spindle_table` / `_spindle_seq` become the runtime's `_shape_table` / `_shape_seq`
(plus `_shape_event_time`); the event envelope is the CloudEvents structure `shape.streaming.emit`
already writes (`specversion`, `id` = `<table>/<row>`, `source` = `shape`, `type` = `shape.<topic>`,
`shapetable`, `shapeseq`, `data`) with `topic`, `schemaversion`, `correlationid` and, on a replay,
`replay` and `replaytime` as CloudEvents extension attributes; the default event file is
`events.jsonl`; no option, alias or message names the baseline. The map is
`files_common.NAME_MAP` (recorded in the harness report).

## Baseline defects fixed (the allow-list)

Owner's standing decision (2026-10-01): a trust-harming baseline defect is fixed and recorded in a
narrow, named allow-list in the harness (`ALLOWED` of each `files_case_*.py`, in the report JSON).
Each entry has a **probe** that observes the baseline's behaviour and Shape's (an entry the baseline
no longer shows fails the run), and a **regression test** in `plugins/shape-simulation/tests/`
(`test_file_drop.py::test_late_rows_are_moved_not_lost_even_when_slots_collide` and
`test_scd2_file_drops.py::test_versions_chain_without_gaps_and_one_current_version_per_entity` were
run against a deliberately reverted implementation and fail there). Anything else that differs fails
the harness.

| ID | Defect (baseline) | Shape |
|---|---|---|
| FD-1 | `multi_file_enabled` raises (`'numpy.ndarray' object has no attribute 'empty'`): a multi-file drop cannot be made | split into near-equal files with SHA-256 and size in the manifest |
| FD-2 | late rows of two slots landing in one partition replace each other's `..._00900` file: rows silently lost (one harness job, 0.5 lateness probability over two years: 163 rows lost, `order` 954 written of 1,087 in range, `customer` 450 of 480), and the replaced path is listed twice | late rows of every slot share one file per partition; nothing lost; each file listed once |
| FD-3 | a column named like a date (`updated_count`, an integer) is the time column when pandas can parse it: every row lands in 1970 and the drop writes nothing, silently | only dates, timestamps and ISO text are time columns; otherwise round robin |
| FD-4 | an unknown cadence is treated as daily (the manifest says the unknown name); an end date before the start writes nothing without an error | `ValueError` naming the setting |
| FD-5 | JSON Lines timestamps are milliseconds (pandas `to_json` default): sub-millisecond precision silently lost, the file differs from its Parquet twin | full precision (the harness shows the baseline's jsonl differs from its Parquet in every file with such a column, Shape's never) |
| SCD-1 | the first time a record changes, its expired row has no `valid_from` (the state is built from the table, not from the snapshot) | the expired row keeps the version's `valid_from` (the initial date, or the insert day) |
| SCD-2 | an inserted entity has `valid_from`, `valid_to`, `is_current` null (copies a template that never changed): `is_current` is not true | insert: `valid_from` = the day, `is_current` true |
| SCD-3 | delta column order depends on the first row (`valid_to, is_current, _delta_type, valid_from` after the table's columns) | the snapshot's columns in the snapshot's order, then `_delta_type` |
| SCD-4 | a tracked integer column with nulls (pandas holds it as float) gets fractional values (an id of 889.73) | integers stay integers (rounded at each change) |
| SCD-5 | a text business key: the write fails with an Arrow conversion error after the snapshot is on disk | `ValueError` naming the key column before anything is written |
| (SCD-1/2 together) | applied over the snapshot, the baseline's versions have gaps and entities with two or no current version (the `customer` job: 617 versions without `valid_from`, 168 without a current flag, 814 gaps between versions, 533 entities without exactly one current version) | zero violations (the version-chain invariant) |
| SE-1 | `burst_windows` accepted and ignored | the runtime's rate schedule applies them (300 events at 100/s with a 3x burst for 1.5 s: Shape 1.01 s, baseline 3.31 s) |
| SE-2 | `sink_type="eventstream"` is the console sink: the events print on standard output and nothing is sent | `ValueError` (an emitter is named by its URI) |
| SE-3 | a new correlation id on every event | one `correlationid` per run (the hybrid simulator passes its run id) |
| SE-4 | the replay buffer survives between `emit()` calls: a second call replays events of the first (10 such replays in the probe) | the window starts empty at each call |
| HY-1 | the run id is only in the `_correlation_id` column; every manifest and event has an id of its own, so files and events cannot be joined on what the documentation claims | the run id is also each manifest's `correlation_id` and each event's `correlationid` |
| HY-2 | an unknown table in `stream_tables` / `batch_tables` is skipped silently | `ValueError` naming it |
| WF-1 | an entity whose initial state has no way out is summarised as starting and ending in the *first* initial state | its own initial state |
| WF-2 | event ids are new random UUIDs on every run (the same seed gives different ids) | UUIDs derived from the seed on a stream of their own: the same seed gives the same ids (a determinism rule, not a defect; no other draw moves) |

Differences that are **not defects** and that the harness treats as such (each is checked, not
tolerated): wall-clock fields (`created_utc`, event `time`, `replaytime`, `_restated_at`) and the
run's UUIDs are checked for form; Shape's events carry `_shape_event_time`, `shapetable` and
`shapeseq` beside the baseline's fields; the time column of an Arrow date type is understood
(pandas holds a date as text); a timestamp with a time zone is read as UTC instead of raising.
Cosmetic: `StreamEmitter` builds its sink when `emit()` runs, not in the constructor (so a bad
`sink_type` raises at construction but a file is not created until the first emit).
