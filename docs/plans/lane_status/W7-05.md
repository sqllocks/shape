## Decisions where the issue was silent (the lead may want to look)

- **Results that are whole documents** (`report_card`, `report_card_read`, `rules_mutate`, `rules_backtest`) are the document itself, spillable as a whole; `min_score` adds a `min_score` object (`required`, `met`) to the mutation report and nothing else.
- **`rules_mutate` cancel** needed a hook the engine did not have: `mutation_test(..., should_stop=None, on_mutant=None)` (raises `MutationCancelled`, holding the partial result). Optional, a finished run is unchanged.
- **History and `registry_diff` are safe by default** like `diff`: for a raw version, the `before`/`after` of a classified column and the `top_values` of its frames are `null` and `redacted: true` unless `options.include_raw_values`.
- **`chaos`** is cancellable only before its files are written (the engine has no finer hook). `start_date` is accepted but needs a batch date, which the bridge does not take (a landing option): alone it is refused with the CLI's reasoning; use `batch`.
- A proposal's rule `claim` is returned as is (the engine keeps rules for personal-data columns value-free); its `evidence` is redacted as for any proposal.
- `format_schema`: new names are since 1.2 (a 1.1 request does not see them) and `decisions` is version 2 for a 1.2 request, version 1 for a 1.1 one.
- A raw and a safe version of one name are refused by `registry_diff` (`input.invalid_value`); the CLI keeps printing `changed: null` for them as before.
