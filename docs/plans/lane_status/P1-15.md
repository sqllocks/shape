# P1-15 — Exact-mode profile on the fused kernel (lane/P1-15)

Status: **built; awaiting lead verification.** Equivalence holds; the speed gates are **not all met** (below). No gate or tolerance was changed.

## What was built
- `rust/shape-kernel/src/exact.rs` (new; `lib.rs` gets two lines): exact-mode column kernels, each with a
  numpy/pyarrow twin in `src/shape/kernel/reference/exact.py` (`SHAPE_KERNEL=python`):
  - `count_numeric`: sort-based distinct count, pandas-order top keys (count desc, ties by first appearance),
    sorted copy, unique keys and the all-whole test, for float64/int64/timestamp columns;
  - `numeric_stats`: mean, std (numpy pairwise sums, via `fit::pairwise_sum`, `fit.rs` untouched), the 11 quantiles
    with numpy's linear/`_lerp` arithmetic, 1.5xIQR outlier count;
  - `value_counts_str`: hash-partitioned parallel string counting in first-appearance order;
  - `top_indices` (stable descending top-k) and `temporal_counts` (hour/dow/month/year histograms).
- `profile/reference/column.py` calls these through `get_kernel()`; the 12-regex pattern sample is drawn once per length.
- `profile/reference/table.py` (orchestration): heaviest columns first; the correlation runs on its own thread
  overlapping the column work; the tables of a multi-table profile share one pool.
- Tests: `tests/kernel/test_exact_kernel.py` (Rust vs reference, bitwise on stats/ties/infinities; product profile identical in both kernel modes).
- py-spy (D2 csv, D3 parquet): no per-row Python on the profile path. Remaining Python-side per-value work is in rare paths only
  (`_refine_integers` text re-read for whole-number float CSV columns, `dtparse` for non-ISO date text).
