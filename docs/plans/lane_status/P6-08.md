## Notes for the lead

- **Baseline quirks reproduced for T-22 parity** (Shape matches them; say if you want them fixed):
  1. `null_rate`, `cardinality_ratio` and `is_unique` divide sample counts by the catalog row
     count, so for tables larger than the sample `is_unique` is never true.
  2. With no declared FKs, when the sampled data shows a relationship the baseline discards it and
     reports none (its heuristic result is dead code); name-based inference runs only when the data
     shows none.
  3. Name-inferred FKs set `detected_fks` and `relationships` but not the column's
     `is_foreign_key`.
  Documented neutrally in `docs/plugins/sqlserver.md` (sampling section).
- Core suites must run **without** the plugin installed: `tests/plugins/test_host.py` assumes no
  third-party plugin is present (with the plugin installed in the venv, 2 tests fail: this is an
  environment artefact, seen in both kernel modes: 1419 passed, 2 failed). Plugin tests need it installed; default `testpaths`
  is `tests`, so the two never mix.
- Real-server runs surfaced and fixed: a scenario column too narrow (`char(2)`), pooled sessions
  holding an open implicit transaction (autocommit now; harness disables pooling), `datetimeoffset`
  (pyodbc refuses it without an output converter; registered on every connection this plugin opens
  or is given).
- Container-level changes outside the repo (ephemeral): Microsoft apt sources, `msodbcsql18`,
  `mssql-server`, `libldap-2.5-0`, `pyodbc` in both venvs.
- Windows: nothing is deleted or replaced while open; harness connections are closed explicitly.
- Not run here: `heavy` tests, `tests/demo/fabric`, cargo checks (no Rust changed), the compose
  nightly job, macOS/Windows CI legs, live (Entra) auth: those modes are covered by contract tests
  with stand-ins only.
