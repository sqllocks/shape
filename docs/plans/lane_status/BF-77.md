# BF-77 — credential-reference import test depends on test order (#77) (lane/BF-77)

Status: **fixed.** Branch from `build/main-plan`. No PR.

## Reproduction (before the fix)

Fabric test requirements installed (pyspark / delta-spark could not be built here, so their
tests skip; `fabric-user-data-functions` brings in `azure.functions`; `unixodbc` needed for it).

```
pytest tests/demo/fabric tests/security/test_credential_refs.py
FAILED tests/security/test_credential_refs.py::test_core_imports_no_cloud_sdk_to_resolve_references
  assert not ['azure', 'azure.functions._abc', ...]
1 failed, 218 passed, 38 skipped
```

The test alone passes; it read `sys.modules`, which the Fabric tests had filled with `azure*`.

## Fix

`test_core_imports_no_cloud_sdk_to_resolve_references` now runs a subprocess (fresh interpreter) that
clears the resolver providers, resolves a `file://` and an `env://` reference exactly as before, and
prints the `azure*` / `boto*` / `google.cloud*` modules in `sys.modules`; the test asserts the list is `[]`.

Other `sys.modules` assertions reviewed: `test_writers`, `test_cli_tiers` (start-up stays light), `test_arrowkit`,
`test_profile_issues` already use subprocesses or monkeypatch; `test_recognising_a_reference_imports_nothing`
compares before/after sets, so earlier imports cannot fail it. None is order-dependent; no change.
