## P4-02 — engine

- `engine.py`: `calculate_row_counts`, `resolve_order` (Kahn, name-sorted queue), `dependency_levels`, `order_columns`, `Engine` (`generate`, `generate_chunk`, `iter_chunks`, `generate_table`, `key_pool`, `dry_run`, `validate`), `EngineContext` (the plugin API's `GenerationContext` plus `engine` and `column_def`), `KeyPool` (`RangeKeys`, `ArrayKeys`), `GenerationResult` (with `verify_integrity`), `DryRun`.
- `rng.py`: row-addressed Philox4x64-10 (`RowStream`); stream, key and word numbering documented as the contract the P4-03 Rust twin must reproduce (oracle: `numpy.random.Philox`). Null masks and rule repairs use it, so they are chunk independent.
- `compute.py` (compute phase), `rules.py` (business rules validate and fix on Arrow), `correlation.py` (Gaussian-copula post-pass).
- G2: `GenerationPlan.row_at` with `FirstPerParent` no longer depends on call order; `tests/generation/test_first_per_parent_g2.py` (4 tests, all 4 fail on the old `strategies.py`, pass now).
- `docs/GENERATION_ENGINE.md` is the stable interface for P4-03/04/06 and the other Phase 4 lanes (a test asserts every public name is documented); `docs/DETERMINISM.md` updated for G2.

Behaviours worth knowing (all tested):
- Output column order is the generation order (`order_columns`), as in the baseline; the baseline lists a key column that has another strategy twice, the engine lists it once at the first place (the baseline's frame does too).
- `computed` is engine-owned (placeholder, then compute phase); dtype of a back-filled sum of an integer column stays integer (the baseline's depends on whether every parent has children).
- Built-in strategies key by chunk, not row (kit note in P2-06), so they are not chunk independent; the P4-04 strategies must use `RowStream`. The engine tests use row-keyed test strategies, and one chunk-keyed control that the chunk test catches.
- Strategies P4-04 will need from the engine: `ctx.engine.key_pool(parent)` (FK), `ctx.engine.schema`, `ctx.engine.row_counts`, `ctx.columns` (same chunk).
