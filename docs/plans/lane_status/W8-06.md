## Design

- `shape.generation.identifiers`: the modes `reserved` and `realistic`, `check_identifiers` (an
  unknown value is a `ValueError` naming both modes) and `announce` (the one-line stderr notice).
- The switch reaches generation through the engine, not a global: `Engine(identifiers=...)` checks
  the value, overrides the schema's new top-level `"identifiers"` and writes the resolved mode into
  the engine's **copy** of the schema. `Engine.identifiers` is the mode in effect and
  `EngineContext.identifiers` carries it to every strategy. Anything that rebuilds an engine from
  `engine.schema.to_dict()` (the multiprocess `chunk_worker`, the Spark `spark_worker`, a scale job
  resumed from its request) therefore generates the same values. The plugin API's
  `GenerationContext` is unchanged (a plain context reads as `reserved`).
- Providers (`native` and `faker`): a column without `domains` / `range` takes `realistic` /
  `assignable` from a realistic run; a column's own key always wins. The Rust kernel is only used
  through `kernel_ops` for the same inputs, so both kernels give the same values (tested).
- A schema without the field reads as `reserved` and is written back without it; the published
  generation-schema and generation-spec JSON Schemas take `"identifiers": "reserved"|"realistic"`.

## Decisions and findings (nothing here changes a D-xx or T-xx)

- **`faker` output change and W1-15.** Item 4 changes the default output of the `faker` package's
  identifier providers. The lane first built it as `faker` generator version 2 (version 1 kept,
  commit 8310197e), as W1-15's `docs/GENERATION_STABILITY.md` required. `int/INT-18` then reverted
  W1-15 (bea22e4a, lead decision 2026-10-05: held for W8-04, #768), so at the final merge the
  versioning was removed with it: `faker` has no `generator_version` and no `generate_versioned`, and
  the reserved behaviour is the only one. **For the lead, when W1-15 is merged again:** W1-15's
  "every built-in is version 1" and its pinned `faker` id (the pinned spec uses `ipv4`, which is
  unchanged) still hold, but by its own rule `faker` should then become version 2 with version 1 =
  the package's raw values; the version-2 code and tests are in 8310197e
  (`tests/generation/test_w8_06_identifiers.py` at that commit:
  `test_the_faker_strategy_is_at_generator_version_2_and_keeps_1`,
  `test_faker_version_1_returns_what_the_package_makes`).
- **Bridge.** `generate` gains an optional argument in 1.2, which `docs/BRIDGE.md` allows ("minor
  versions only add ... an optional argument"); a 1.0 or 1.1 request gets `usage.unknown_argument`
  (tested). No result field and no warning code was added, so the 1.0 and 1.1 promises hold.
  `test_what_1_2_adds_to_a_1_1_command_is_marked_and_nothing_else_changed` asserted that no 1.1
  command gained an argument; it now lists `generate: {identifiers}` as the one addition and checks it
  is marked since 1.2 and optional (still exact for every other command). Schemas regenerated with
  `shape bridge schema --out docs/bridge/schema`; vectors with `python tests/bridge/make_vectors.py`
  (two `generate` cases added in `vectors_1_2.py`). The tool also rewrote unrelated registry fixtures
  and the bisect/timelapse/rules_backtest/registry_diff vectors with fresh timestamps and object ids;
  those were restored, only `generate.json` is committed.
- **Manifest key set.** `test_reproducibility.py` asserts the exact `reproducibility` keys; it now
  includes `identifiers` (the field is additive, `shape-run-manifest` stays version 1).
- **Where the notice is printed.** Each entry point announces once per run; `Engine` itself does not
  (workers and internal engines would repeat it). A plain `Engine(...).generate()` from Python does
  not print it.
- **"Plans"** in the issue is read as scenario runs (`shape pack run` and a GSL spec's `scenario`
  section), which write the run manifest. `shape plan` / `--dry-run` output (and the bridge `dry_run`
  result) was not given a new field, because the 1.0 bridge promise forbids adding result fields to a
  1.0 command; a dry run takes the flag and generates nothing.
- **Not changed:** the `locale` strategy (its phone numbers are always in fiction ranges), `ipv4`, the
  masking transform. The bridge `demo_run` and `scale_generate` commands did not get the argument
  (the issue names `generate` only); `scale_generate` requests accept `identifiers` through
  `scale.api.normalize` from the CLI.
- **CLI surface snapshot** (`scripts/cli_surface.py --check`): 0 breaking changes, notes for the
  new `generate --identifiers` and `pack run --identifiers`. `test_the_baseline_is_what_write_produces`
  requires the baseline to be current, so `tests/cli/cli_surface_v1.json` was refreshed with
  `cli_surface.py --write` (28 added lines: the four `--identifiers` flags, nothing removed).
- **VS Code extension.** `editors/vscode/schemas/generation-spec-v1.schema.json` is a copy of the
  published spec schema (`test_bundled_schemas_equal_the_packages`); it was copied again.
