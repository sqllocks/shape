## Notes for the lead

1. **Release step.** SQL files carry `-- Generated by Shape v<version>`, so the corpus's SQL hashes
   change with every version bump: a release runs `python scripts/golden_bytes.py --update`
   (the failing test prints that hint when the corpus's `shape_version` differs). Documented in the
   page.
2. **pyarrow.** CSV/TSV formatting is Arrow's; the promise is stated for the pyarrow CI checks
   with (documented under "not covered"); a pyarrow release that changes bytes fails the corpus
   test in CI.
3. **Pre-existing mypy errors on `int/INT-18`** (not in files this lane touches; identical on the
   base): `src/shape/drift/engine.py:1078,1081` (assignment types) and
   `src/shape/contracts/v1.py:559` (`gaps` redefined). Left for the owning lanes.
4. Equivalence verifiers (`benchmarks/vs_refengine/run.py --quick`) not run: `$REFENGINE_ROOT` is not
   present in this session. This lane does not change generation (dataset ids, pinned fixtures and
   golden writer files are unchanged and tested), only writer line ends on Windows.
