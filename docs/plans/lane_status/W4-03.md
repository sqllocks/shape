# W4-03: basic locale packs (issue #74, lane/W4-03)

Status: **partly built. The mechanism, tests, docs and the data that could be sourced are done; names,
streets and some phone ranges for the other countries are not shipped, because no source with a
licence we could read was reachable.** Awaiting lead decision on the gaps below. No gate, tolerance,
D-xx or T-xx decision was changed; no test was skipped, disabled or loosened; §11 and §2.3 were not
edited; `$SPINDLE_ROOT` was cloned at the pinned commit (§1.2) and not modified by this lane.

## What was built

* `{"strategy": "locale"}` (`src/shape/builtins/strategies/locale_pack.py`, registered in
  `builtins/catalog.py`): `locale` is `US`, `CA`, `GB`, `DE`, `FR`, `IN` or `AU` (also `fr_FR`,
  `fr-FR`, `fr`); `provider` is `city`, `region`, `postcode`, `phone_number`, `first_name`,
  `last_name` or `name`. Row addressed (a test checks chunking and seed). Place columns of a table
  with one `group` agree; another `group` is an independent address. The existing US pools and
  `test_shape_pools_are_the_baselines` are untouched (the US names reuse the existing pools).
* Data, in `src/shape/builtins/strategies/locales/` with `MANIFEST.json` (source URL, licence,
  read date 2026-10-03, upstream SHA-256, file SHA-256), rebuilt byte for byte by
  `scripts/build_locale_data.py`:
  * places and postcodes for GB, CA, DE, FR, IN, AU from GeoNames postal codes (CC BY 4.0, text
    quoted from its readme); one place per code. The German file is cut to places (GeoNames lists
    company postcodes under company names; rows with no accuracy value or an organisation word are
    left out); French rows with `CEDEX` are left out. GB and CA codes in the file are partial, so
    the rest is drawn at random (documented);
  * French first names (top 1,000 since 1950) from INSEE's Fichier des prénoms (Licence Ouverte 2.0,
    page statement quoted);
  * phone numbers: US and CA `555-0100` to `555-0199`; FR the six audiovisual roots of Arcep's
    numbering plan (read from the PDF, text quoted). Every other country raises a `StrategyError`
    saying no reserved range is shipped; the strategy never falls back to numbers that may be real.
* No national identifier for any country: `ssn`, `nino`, `nir`, `aadhaar`, `tfn`, ... raise
  `StrategyError` (tested for every country).
* Docs: `docs/LOCALES.md` (including "What is not shipped"), a pointer in
  `docs/GENERATION_STRATEGIES.md`, `CHANGELOG.md`; notices in `THIRD_PARTY_NOTICES.md` (a test
  checks that every manifest source and licence URL appears there).
* Tests: `tests/generation/test_w4_03_locales.py` (46 cases), written before the code.

## What is not delivered, and why (needs a lead decision)

The issue asks for names, addresses and phone formats for seven countries. Not shipped:

| Gap | Why |
|---|---|
| Surnames: every country but US | No openly licensed list found that could be fetched. |
| First names: CA, GB, DE, IN, AU | CA, IN: `canada.ca`, `data.gov.in`, Statistics Canada hosts unreachable from the sandbox. GB: the ONS dataset page for the files was not found by search, and its download hosts were not tried successfully. AU: the Queensland and NSW name files are CC BY 3.0 on their portals, but the file hosts return an empty or 504 response through the sandbox proxy (the portal API answers). DE: city open-data portals list name files, but their licences vary per portal and no national list was found. |
| Streets | The sources list places and postcodes only. |
| Phone ranges: GB, AU | The Ofcom and ACMA pages are not reachable from the sandbox (403, no response). The ranges are well known but were not read this session, so they are not shipped. |
| Phone range: DE | The Bundesnetzagentur page was reachable but the list of numbers for film and television was not found from it. |
| Phone range: IN | No range reserved for fiction known; stated in the docs instead of guessing. |
| CA phone area codes | Any NANP area code 200 to 999 is used with the `555-01xx` line (the lines are reserved plan-wide); nanpa.com loaded but the statement was not located in it, so this rests on the same rule the existing US provider uses. |

Each gap is data only. To fill one: add `<cc>_first_names.txt` or `<cc>_last_names.txt` to `locales/`
(the `name` and `first_name` providers pick the file up by name), extend `build_locale_data.py` and
the notice, and the manifest test covers it. A range for a country needs a branch in `_phone`.
