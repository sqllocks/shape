## Differences from the baseline (all confirmed not to change any compared output)

- Ported to Shape's own schema types; no baseline name appears in `src/` or `docs/` (`check_user_facing` clean). The command's banner says "Shape DDL import".
- The file Shape writes is the full schema (`GenSchema.to_dict`), so it **includes the inferred business rules and derived counts**. The baseline's command counts them in its summary but writes `"business_rules": []` and no derived counts. Equality with the baseline is on the in-memory schema (stricter) and, restricted to the fields its file carries, on its file.
- Default output name `FILE.gen.json` (the baseline: `FILE.refengine.json`); the plan names no Shape suffix.
- Generators are deep copies (the baseline shares nested dicts between columns); a bad scale count is a `DdlError` (a traceback in the baseline); an unterminated quoted column name is skipped (an exception in the baseline).

## Baseline behaviours kept (equality is the acceptance); open items for the lead

1. A **column-level `REFERENCES`** (`customer_id INT REFERENCES customer(id)`) is not read. The naming convention then guesses `customer.customer_id`, which does not exist when the parent key is `id`: `GenSchema.validate()` reports an error for `e2e_cli__inline`. `verify.py` prints these as notes; the docs tell users to declare `FOREIGN KEY (...)` constraints. Fixing it would make Shape's output differ from the baseline's; say if you want that.
2. `VARBINARY(MAX)` is not recognised as binary (the type pattern needs digits), so it becomes a text column; `VARBINARY(100)` is skipped.
3. Name matching oddities carried over: `discount_pct` is a quantity (it contains "count"), a `state` string column becomes a status enum, a `status` column keeps the parser's three-value enum (it is not a placeholder), `gender CHAR(1)` stays a pattern.
4. CR-08 (a parent total summed over its children) is skipped, as in the baseline.
