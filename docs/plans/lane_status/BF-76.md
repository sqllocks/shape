# BF-76 — issue #76 (numpy 2.5 test failures): round 2

Status: **done on this branch; one ci.yml change for the lead to apply (below).**

## Findings (round 1, confirmed in round 2)

The three failures of #76 are not numpy-dependent. They are raised by the tests' own pyarrow calls on
pyarrow < 25 (observed on 19.0.1) and pass on pyarrow 25.0.1 with numpy 2.4.6 and 2.5.3:

- `tests/kernel/test_hashing.py::test_one_and_one_point_zero_hash_equal`: `pa.array([1.0], type=pa.float16())` raises
  `ArrowTypeError: Expected np.float16 instance`.
- `tests/kernel/test_hashing.py::test_rust_equals_reference_on_a_million_values[float16]` (marked `heavy`):
  `pc.if_else` has no halffloat kernel.
- `tests/iss_gaps/test_landing_and_batches.py::test_file_sinks_take_path_template_and_batch_date`:
  `pq.read_table` on a file under `ingest_date=.../` infers a dictionary partition column.

## 1. Tests made independent of the pyarrow version

Only how the tests build or read data changed; every expected value and assertion is unchanged.

- one-point-zero test: the float arrays are built from numpy scalars (`np.float32/64/16`), which every
  pyarrow accepts, instead of Python floats with `type=`.
- million-values test: null masking for float16 uses `pa.array(values_numpy, mask=null_at)`; other types still use
  `pc.if_else` with the same mask values (same RNG draw, now held as a numpy bool array).
- file-sinks test: `pq.read_table(parquet, partitioning=None).equals(t)`.
