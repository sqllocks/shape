conversion and an `if_else` kernel that older pyarrow lacks). The third is `pq.read_table` on a
single file inside a hive-style `ingest_date=...` directory inferring a partition column in older pyarrow.
Shape's own writer output is unchanged. (`pyproject.toml` allows `pyarrow>=14.0.1`.)

The issue text's "Expected np.float16 instance" and "dictionary-typed ingest_date" strings are exactly the
pyarrow-19 symptoms above, so the reporter's environment most likely had pyarrow < 25, e.g. a resolver or
extra (here: `tests/demo/fabric/requirements.txt` pulled pyarrow 19.0.1 into my first full run) downgrading it.
