## Decisions where the issue is silent (please review)

- `shape diff` prints only JSON on stdout, so the "text output" marks `(planned: ID)` and the expiry
  warning go to stderr. `shape verify` prints `(planned: ID)` in its normal WARN lines.
- `action` defaults to `expect`. First matching entry in file order wins.
- An entry with `source` matches only when that source is in use (no source: no match).
- `severity` action: in `diff`, reported if the original or the new severity reaches `min_severity`
  and counted if the new one does; in `check` and the verify gate it fails only at `high`.
- `verify` applies entries only to the schema drift gate (the only gate with drift kinds:
  `table_added/removed`, `column_added/removed`, `dtype_change`) and does not report
  `planned_not_observed` (most entries are not schema kinds).
- Rolling-window baselines: the planned report is the first run's, kept to entries still matching
  after the intersection.
- `ack --all` skips changes already planned. Ack ids are `ack-DATE-COLUMN-KIND`, made unique.
- `add`/`ack` append text (PyYAML cannot keep comments); a file whose `changes:` is not the last
  top-level key is refused for writing, exit 2.
- Dates in the file are read as text (not YAML timestamps), so an impossible date is a problem of its key.
- Contract rule names accepted in `kinds`: the `shape check` rule and violation names, plus `not_null`
  (matches `nullable`).
