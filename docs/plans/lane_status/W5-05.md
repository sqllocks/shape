   the count in `test_twenty_seven_modules_listed`) the way PF-03 did for `integrations`, and

Smaller choices (inside the deliverables):

* **Scenario format.** "A pack or generation spec plus an answer key" cannot express targeted
  defects (a pack's chaos is random), so each scenario is `scenarios/<id>/scenario.json` (format
  `shape-scenario`, version 1: domain, scale, seed, gates, defects or a drift plan) plus
  `expect.json` (`shape-scenario-expect`). That makes **four** persisted formats, not the three the
  issue lists; all four declare `format` and `version` and have compatibility tests. No PyYAML
  needed. Library scenarios run through `shape pack run library:NAME`, not through `PackRunner`.
* **Only one built-in domain exists** (`retail`), so all ten scenarios use it.
* `tiny` is not a retail preset: it is defined as 100 rows per table wherever a scale is taken by
  the library, the plugin and `shape seed` (`shape.scenario.library.scale`).
* **W1-01 is not in this branch**, so `format` / integer `version` / newer-version refusal are done
  in `shape.scenario.library.formats.check_header`. When W1-01 lands, swap it for the shared helper.
* **Seeding and transactions.** The database sinks commit after every table, so "one transaction
  where the sink supports it" is one transaction **per table**; none supports a transaction across
  tables. A failure part way leaves the earlier tables and the error names them (documented).
  `create` checks every table first (`exists_sql` and the connection hooks of the shape-databases
  sinks; for the `sqlserver` sink through its `_parse`, `_connection_string` and
  `shape_fabric.sqldb.SqlConnection`, because the sink has no public existence check), so a
  refusal writes nothing. A sink that cannot say what exists refuses `create`. The command line has
  no password option (the sinks read their environment variables; the SQL Server sink also takes
  one in the URI); `seed_target(..., sink_options=...)` takes `password`, `user` and so on.
* Tests that need the retail domain use `pytest.importorskip("shape_domains")`, as the existing
  pack CLI tests do; one test is `skipif` pandas is not installed (the dev extra installs it).

## Deliverables (issue #81 "Wanted" list)

1. **`rename_column` drift event** — `src/shape/generation/drift_plan.py`: on/off with an optional
   `end`, no ramp; `column` may be `"table.column"`; reflected in `schema_at` (position kept; primary
   key, relationships, foreign keys that point at the column and correlations follow it); unknown
   table or column and a rename onto an existing name raise `DriftPlanError` (a `ShapeError`)
   naming both names, on every day; a column named by a rule or another column's generator is
   refused. `expected_changes` gives one record (`kinds: ["column_removed"]`, `rename` with the new
   name and `added_kinds`); the diff sees a dropped and an added column (tested). Tests:
   `tests/generation/test_drift_rename.py` (11).
2. **Starter library** — `src/shape/scenario/library/` (`index.json`, ten `scenarios/<id>/`, two
   `suites/`); `shape pack list --library`, `shape pack run library:NAME`, `shape pack validate
   library:NAME`. Scenarios: `clean_baseline`, `nulls_injected`, `duplicate_rows`,
   `orphaned_foreign_keys`, `late_arriving_data`, `schema_add_column`, `schema_rename_column`,
   `schema_drop_column`, `schema_retype_column`, `schema_evolution_schedule`. Answer keys were
   written by hand before the first run and all met on the first run; a test checks every drift key
   against `DriftPlan.expected_changes`. Tests: `tests/scenario/test_library.py` (each scenario at
   `small` and `tiny`; wrong-key cases; format, version, unknown-key, malformed cases; defect
   boundaries), `tests/cli/test_suite_cli.py`.
3. **Suites** — `shape suite run NAME|FILE [--scale small] [--seed N] [-o DIR] [--json]`;
   `smoke` (five scenarios, about 1 s at `small`; a test holds it under 60 s) and
   `schema-evolution`. Exit 0 / 1 (scenario, expectation and observation printed) / 2 (malformed
   suite, unknown scenario, suite or scale; nothing runs). A deliberately wrong key exits 1 (tested
   through the CLI and the API).
4. **pytest plugin** — `shape.testdata.pytest_plugin`: `shape_dataset` factory (Arrow tables,
   `as_pandas()`, cached per session by spec digest, scale and seed), `@pytest.mark.shape_scenario`
   with the `shape_scenario` fixture, `--shape-seed`; nothing written outside `tmp_path_factory`.
   `pytester` tests in `tests/testdata/test_pytest_plugin.py` (fixture, marker, `--shape-seed`,
   caching, not loaded with `-p no:shape`, entry point, no stray files).
5. **`shape seed`** — `shape.testdata.seed`, `src/shape/cli/seed.py`: foreign-key order, modes,
   `--dry-run` (connects to nothing; tested with a sink that fails on any access), `sql://DIR`
   scripts named `NN_table.sql` (also `?dialect=`), byte-identical `truncate` reruns, a postgres
   dialect script set loaded into SQLite in order. Tests: `tests/testdata/test_seed.py`,
   `test_seed_cli.py` (in-memory sink; main CI), `plugins/shape-databases/tests/test_seed.py`

   `plugins/shape-databases/tests/test_seed_emulator.py` and
   `plugins/shape-fabric/tests/test_seed_sqlserver_emulator.py` (written, **not run**: no Docker,
   and `sqllocks-shape-fabric` cannot be installed offline here).
6. **Docs** — `docs/SCENARIO_LIBRARY.md`, `docs/TESTING_WITH_SHAPE.md`; `docs/SCENARIO_PACKS.md`
   (library names), `docs/DRIFT.md` (rename), `docs/CLI.md`, `CHANGELOG.md`.
