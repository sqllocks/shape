## Decisions made inside the package (details in the docs)

- `flatten` defaults to `"struct"` for `json` and `jsonl` (jsonl behavior is unchanged).
- XML attributes are `@name` columns, element text with attributes or children is `#text`, values are strings.
- X12: `position` is 1-based inside the interchange; the 835 `PLB` and `SE` segments have `loop_id` `summary`
  and no per-loop table; repeated segments in one loop instance use `__n` column suffixes.
- HL7: `fields` is `list<list<list<string>>>` (fields, repetitions, components); subcomponents are not split.
  `segments="tables"` also writes `hl7_message` (the parent for the relationships) and tables are `hl7_<id>`.
- The depth check for a `.json` file is a new whole-document function (`check_json_document`) because the
  existing check counts per line. Both are in `shape.security.jsondepth`.
- Entry points: core `json` and `xml` (also in `catalog.py` and `docs/plugins/builtins.md`), plugin `x12` and `hl7v2`.
- Persisted formats: none added. The `shape.nested.*` Arrow schema metadata keys on flattened tables are not a
  persisted format (nothing reads them from disk) and are documented as such.

## Not done (outside the Wanted list)

- `shape profile PATH` does not pick up `.json` or `.xml` files by suffix (`file_kind` and the profile reader are
  unchanged). Use `read_tables` and profile each table, or `x12://FILE` for X12 (which the profile reader already
  passes to plugin sources).
- Only `Delimiters` from `x12/core.py` is reused by the reader; the writer's segment builder has no reading role.
