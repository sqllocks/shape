## Behaviour notes / deliberate differences

- `shape mask` without a key is unchanged for existing inputs, except e-mail domains: only
  example.com/.org/.net (the base branch made this same change; the `mask_1to1` harness needed no
  allow-list change, since it checks formats, not domains).
- Keyed mode masks email, phone, first/last/name, ssn, zip and date-of-birth per value. Other types
  (address, city, state, ip, username, card, iban) and floats use the existing generators seeded from
  the key: deterministic for the same key and data, but not stable per value across different data.
  This is stated in `docs/MASK.md`.
- `shape.masking` was added to the import-linter source modules in `pyproject.toml`
  (a test requires every top-level module to be listed).
