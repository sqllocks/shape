# P4-01c — `from-ddl` bug fixes (lane/P4-01c)

Status: **built; awaiting lead verification.** Owner decision of 2026-10-01: "Fix the bugs. Those are not acceptable and would harm user trust in Shape." No gate, tolerance or decision was changed; §11 and §2.3 of the plan were not edited; no test was skipped or xfailed; the pinned baseline checkout (`$SPINDLE_ROOT`) was only read.
Environment: Python 3.11.15, `~/.venvs/shape` (`pip install -e ".[dev]"`, Rust kernel built), pinned baseline built by `setup_spindle.sh` into `~/.venvs/spindle`.

## What was built

- `src/shape/generation/ddl_names.py` (new): `snake`, `words`, `word_pattern`. Names are split into words (CamelCase and snake_case) and a rule matches a whole word or run of words (plural allowed; `x_` a prefix word, `expir*` a stem), never part of a longer word.
- `src/shape/generation/ddl.py`: column-level `REFERENCES` (fix 1), binary types and `MAX` (fix 2), one-character codes and `gender`/`sex` (fix 4).
- `src/shape/generation/ddl_infer.py`: every name rule now matches whole words (fix 3); CR-08 implemented (fix 5).
- `benchmarks/vs_spindle/ddl_1to1/`: `differences.py` (the named, explained allow-list), `verify.py` (uses it), `extra/fix_cases.sql` (new input that exercises every fix) and its baseline output `fixtures/expected/fix_cases.{smart,plain}.json` (written by `dump_ddl.py` in the baseline venv).
- Tests: `tests/generation/test_ddl_fixes.py` (new), `tests/benchmarks/test_ddl_import.py` (equality apart from the allow-list, plus negative controls), `tests/generation/test_ddl.py` (one test that assumed `state` is a status).
- Docs: `docs/GENERATION_ENGINE.md` ("Reading SQL DDL"), `CHANGELOG.md`.

## Acceptance, item by item

**1. Column-level `REFERENCES` is a foreign key.** `customer_id INT REFERENCES customer(id)` is a `foreign_key` column with `ref` `customer.id` and a relationship (`parent_columns ["id"]`), in every spelling tested: plain, `NOT NULL`, `ON DELETE CASCADE ON UPDATE NO ACTION`, `CONSTRAINT name`, SQL Server (`[dbo].[customer] ([id])`), MySQL backticks, quoted, lower case, after `DEFAULT`, and with the parent key left out (`REFERENCES customer` means its single-column primary key; one the parent does not have is not read). A column-level self-reference is `self_referencing`. `CONSTRAINT` is also cut from the type text, so `INT CONSTRAINT fk REFERENCES ...` is an integer. The `e2e_cli__inline` schema validates (`GenSchema.validate()` has no error; `verify.py` fails otherwise) and generates keys that are all parent ids (`test_the_inline_fixture_validates_and_generates`). Tests: `test_a_column_level_references_is_a_foreign_key` (22 cases) and 8 more.
**2. Binary types.** `VARBINARY(MAX)`, `BINARY(MAX)`, `VARBINARY`, `VARBINARY(100)`, `BINARY(16)`, `IMAGE`, `BYTEA`, `BLOB`, `BLOB(n)`, `TINYBLOB`, `MEDIUMBLOB`, `LONGBLOB`, `BINARY VARYING` are left out (smart and plain). Root cause: the type pattern needed digits, so `(MAX)` made the base type `varbinary(max)`; `MAX` is now a length (none) for strings too (`NVARCHAR(MAX)` is a string column; the baseline read it as an unknown type). Tests: `test_binary_columns_are_left_out` (28 cases), `test_max_is_a_length_for_strings_too`.
**3. Whole-word names.** `discount_pct` is a percentage (`ND-PERCENTAGE`, `BR-07`), not a quantity; a `state` string stays the parser's `state_abbr` value, not a status enum. All the other name rules were reviewed and converted (column semantics, table roles, key distributions, row ratios, measurement hints, categorical profiles, correlations, business rules). Substring bugs found and fixed besides the two named: `parent_*` money ("rent"), `current_value` money ("rent"), `feedback_score` money ("fee"), `model` a category ("mode"), `hotel` a phone ("tel"), a `catalog` or `login` table a log ("log"), `overdue_date` an end date ("due_date"), `preorder_date` a transaction date, `last_update` a transaction date in a transaction table ("date" in "update"), `network_*` a "net" column and `taxi_*` a tax column in the correlation rules, `device_attr`-style names a date ("_at"), `flagship` a flag, `username` a name, `security_*` a URL ("uri"), and `margin_pct`/`tax_rate` money instead of percentages (percentages are checked before money and quantity). CamelCase is split for the correlation, business-rule and table-name rules as it already was for the column semantics. Test: `test_names_match_whole_words` (37 names, legitimate matches included) and the tests around it (state, model/catalog, log tables, measurement hints, correlations, percentage rule: 13 cases).
**4. Coded single-character columns.** A one-character string column gets a `weighted_enum` by the words of its name: `gender`/`sex` M 0.49 / F 0.51; status words A/I/P; flags (`is_`, `has_`, `flag`, `active`, ...) Y/N; any other code A/B/C. A `gender`/`sex` column of any length is M/F. The values fit the column (generation test: one character each). Longer codes (`CHAR(3)`) are unchanged. Tests: `test_a_one_character_code_gets_a_value_set` (64 cases) and 6 more cases.
**5. CR-08.** In smart mode a parent's monetary total (`total`, `subtotal`, `grand_total`, `order_total`, `total_amount`) becomes `computed` / `sum_children` over the child's monetary amount column (`line_total`, `line_amount`, `amount`, `total`, `subtotal`, `extended_amount`), annotated `CR-08`. Guards: single-column parent key that the child points at, exactly one key between the two tables, a basic generator on the total, monetary columns, no chain of totals (the compute phase fills tables in schema order). Generated data: the total equals the sum of the child rows to 2 places, and 0 for a childless parent (`test_the_generated_parent_total_equals_the_sum_of_its_children`). Tests: 8.
**Regression tests fail before the fix:** with the two source files restored to the P4-01b version, 144 of the 189 tests in `test_ddl_fixes.py` fail (the other 45 pin behaviour that must not change); all pass with the fixes.
**`verify.py` lists each changed behaviour as a named, explained, narrow allow-list.** `differences.py` holds `FIXES` (F1 to F5, each explained) and `ALLOWED`: 115 entries, each one input, mode and field (a column's generator or a relationship/rule/count by name; never a whole table) or one annotation key (rule id, table, column). Every other field, annotation and `--explain` line must still equal the baseline. An entry that matches no difference fails the run, and a fix that no case shows fails it. `verify.py` prints, per case, which fixes it saw. Result: **26/26 equal to the baseline apart from the listed differences** (13 inputs x 2 modes: the 12 of P4-01b and `extra/fix_cases.sql`). Negative controls in `tests/benchmarks/test_ddl_import.py`: with one fix's entries removed, exactly the inputs that show that fix fail; a stale entry fails.
**User docs.** `docs/GENERATION_ENGINE.md` "Reading SQL DDL" describes column-level keys, the binary types, whole-word names, one-character codes and CR-08; the "declare keys as `FOREIGN KEY (...)` constraints" workaround is gone.

## Baseline behaviours still kept (not in the owner's list; for the lead)

- A key the DDL does not declare is guessed as `<table>.<the column's own name>`, so `customer_id` with no constraint points at `customer.customer_id`, which does not exist when the parent key is `id` (the schema then fails `validate()`). The docs now say to declare the key. Pointing the guess at the parent's primary key would be the same kind of fix; say if you want it.
- A `status` column keeps the parser's three-value enum (not a placeholder); a `CHAR(2)`/`CHAR(3)` code keeps the six-digit pattern.
- A name written without separators (`catalogitem`, `orderdate`) is one word and matches no rule, where the baseline's substring match found "log" or "date" in it.
- `CustomerId`-style keys the DDL does not declare are still not guessed (the convention needs `_id`).

Status: **built; awaiting lead verification.** Owner: "Fix those too if they harm user trust"; the lead chose F6 to F8. No gate, tolerance or decision changed; §11 and §2.3 not edited; no test skipped or xfailed; the pinned baseline (`$SPINDLE_ROOT`) was only read. Environment: fresh container, so `setup_spindle.sh` rebuilt `~/.venvs/spindle` and `pip install -e ".[dev]"` built `~/.venvs/shape` (Python 3.11.15, Rust kernel). After merging `origin/build/main-plan` (it added `rust/shape-kernel/src/gen/relational.rs`) the extension was rebuilt.

## What was built

- `src/shape/generation/ddl.py`
  - F6/F8: the `<table>_id` convention now reads `snake(name)` (so `CustomerId`, `CustomerID` and `customerId` end in `_id`), also tries the candidate without underscores (`order_item` to table `OrderItem`), and points the key at the parent's single-column primary key (`<parent>.<key>`); with no single-column key nothing is guessed (the column keeps its type generator), so no reference to a missing column is made.
  - F7: `fit_string_lengths(schema)` (new, idempotent) runs at the end of parsing, after smart inference, and after `apply_scale`. For each string column with a length: a `pattern` whose longest value (literals, `{seq:w}` widened to the digits of the table's largest row count in any scale preset incl. derived counts, `{random:w}`) exceeds it becomes `{random:<length>}`; a `weighted_enum` keeps only the values that fit (weights renormalised), or, if fewer than two fit, becomes the code set of the column's name (single letters). Faker and native text is already cut at `max_length` by the strategy (`providers._truncate`), so it is left alone. `_code_generator` became a module function so the fit pass can use it.
- `benchmarks/vs_spindle/ddl_1to1/`: `differences.py` (F6 to F8 explained in `FIXES`, entries in `ALLOWED`), new input `extra/fix_cases_round2.sql` and its baseline output `fixtures/expected/fix_cases_round2.{smart,plain}.json` (written by `dump_ddl.py` in the baseline venv; the 26 existing baseline files are unchanged).
- Tests: `tests/generation/test_ddl_fixes.py` (blocks 6 to 8). `test_longer_codes_are_unchanged` pinned the six-digit pattern for `CHAR(3)`, which F7 changes on purpose; it is replaced by `test_a_longer_code_without_a_name_rule_keeps_its_pattern` (`CHAR(8)` keeps `{seq:6}`).
- Docs: `docs/GENERATION_ENGINE.md` ("Reading SQL DDL": the guess now points at the primary key, CamelCase keys, no guess without a single-column key, strings never exceed the length; the "declare the key" workaround is gone), `CHANGELOG.md`.

## Acceptance, item by item

**F6.** `customer_id INT` with a parent `customer (id INT PRIMARY KEY)` (or `customers`), smart and plain, is a `foreign_key` to `customer.id` with relationship `parent_columns ["id"]`, and `validate()` has no error; a parent whose key has another name (`cust_no`, `cid`) is named correctly; a parent with a composite key or none is not guessed (no relationship, not a `foreign_key`, still validates). Generation: every child value exists in the parent. Tests: `test_a_guessed_key_points_at_the_parents_primary_key` (4), `..._whatever_it_is_called`, `..._not_made_when_the_parent_has_no_single_column_key` (4), `test_a_guessed_key_generates_only_parent_keys`.
**F7.** Short codes (`country_code CHAR(2)`, `currency_code CHAR(3)`, `region_code NCHAR(2)`, `product_code VARCHAR(5)`, ...) get `{random:n}`; `_type`/`status` value sets longer than the column keep the values that fit or become a code set. Checked by generating (2000 rows) 22 short string columns in smart and plain, longest value `<=` the length and not empty (`test_short_fixed_length_columns_get_values_that_fit`), plus unit tests for the pattern, the value-set filter, the code-set fallback, the row-count widening (`{seq:6}` at 999,999 rows, `{random:6}` at 1,000,000) and that columns that already fit are unchanged. Every string generator the import produces was checked against the column length: `pattern` and `weighted_enum` (the only ones that can overflow) are fitted; faker text is truncated by the strategy; the others (numbers, dates, uuid, sequences, keys) are not strings of declared length.
**F8.** `CustomerId`, `CustomerID`, `customerId`, `Customer_Id` are keys like `customer_id` (with the F6 parent-key rule); `SalesOrderId` finds `SalesOrders` and `OrderItemID` finds `OrderItem`; `Id`, `ID`, `Idea`, `Paid`, `Valid` and `orderdate` are not keys. Tests: `test_a_camel_case_id_is_a_key_like_customer_id` (8) and 3 more (24 cases with the name test).
**Every DDL fixture generates data that fits and whose keys exist.** `test_every_ddl_fixture_generates_data_that_fits_and_whose_keys_exist` (14 inputs x 2 modes): `validate()` has no error, every string column's longest value is within its length, every relationship's child values are in the parent. It runs the built-in `pattern`, `weighted_enum`, `uuid`, `temporal`, `sequence` and `distribution` strategies; the default registry has no `foreign_key`/`self_referencing` strategy (as in round 1's tests) and no `faker` package is installed, so those three are stood in for (a key drawn from the parent's pool, a self-reference to an earlier key, and 400-character text cut by the strategy's own `_truncate`).
**Fail before the fix.** With `ddl.py` restored to the round 1 version, 27 of the 249 tests in `test_ddl_fixes.py` fail (F6: 10 key tests; F8: 9; F7: 5 unit tests, 2 short-column generation tests, and the fixture test on `ddl_parser__comment_ddl`, where `state_code CHAR(2)` got six digits, smart and plain); all pass with it.
**`verify.py` allow-list.** `FIXES` gains F6 to F8, each explained; `ALLOWED` lists the changed fields by input, mode and field only (a column's generator, a relationship, a scale or derived count of one table, one annotation key; never a whole table). `verify.py` prints per case which fixes it saw and fails if a fix is never seen or an entry matches no difference. Result: **28/28 equal to the baseline apart from the listed differences** (14 inputs x 2 modes). Seen: F6 in `fix_cases_round2` (smart, plain); F7 in `fix_cases_round2` and `ddl_parser__comment_ddl`; F8 in `fix_cases_round2` and the existing `quoted_and_exotic` (`Sales Order.CustomerID` is now a key, with its row-count and distribution consequences listed). The negative controls of `tests/benchmarks/test_ddl_import.py` cover F6 to F8 (removing a fix's entries fails exactly the inputs that show it).
