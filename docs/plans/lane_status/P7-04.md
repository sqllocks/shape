## Method
1. Read the code surface by surface (not only tools): four independent read-only passes covering
   (a) SQL/KQL/command injection and generated code, (b) path traversal and unsafe writes,
   (c) parsing and denial of service on untrusted input, (d) secrets, deserialization and execution.
   Each reviewer had to reproduce a finding with a snippet before reporting it; I re-checked every
   fix against the code and with a test that fails on the old code.
2. Wrote the fuzzer, ran it with several seeds (it found F9 and F10 below on its first run).
3. `bandit -r src` and on every plugin; grep gates for `yaml.load`, `pickle`, `eval`, `exec`,
   `shell=True`, `os.system`, `mktemp`.
4. Fixed every confirmed high and medium finding with a regression test; low findings are fixed when
   the fix was a few lines, otherwise recorded with a reason.

Scope reviewed: the emit runtime and emitters (file, jsonl, Kafka, Event Hubs, Fabric), `shape stream`
and checkpoints, live fidelity, scenario packs and GSL YAML, chaos, `shape mask`, incremental,
profile registry and local registry, generation inside pipelines (Fabric, Synapse, ADF notebooks, the
Fabric UDF, the ADF Batch gate), the SQL Server plugin, contracts, the `.shape` container and signing,
`shape git-setup`/`cat`, the SQL/Delta/CSV/Excel/Parquet sinks, DDL and schema parsers, reference
datasets, quality gates. No high-severity finding was found at HEAD. `plugins/shape-mcp` and
`plugins/shape-simulation` are empty skeletons (nothing to review yet; revisit when they gain code).

### Low findings recorded and not fixed (with the reason)

- **L1 (R3). Spreadsheet formula injection in CSV/Excel sinks.** Values beginning with `= + - @` are
  written as they are. Synthetic data is the product; prefixing would change the values (and break
  round-trips and the equivalence verifiers). Documented in the threat model; an opt-in escape is a
  feature request, not part of this review.
- **L2 (R6). URIs echoed with userinfo/query** in `shape stream` stdout and checkpoint files and in an
  error message. Credentials belong in the environment or an options file (documented); changing
  the stdout JSON field is a user-facing format change. Checkpoints are written 0600.
- **L3 (R2). A profile or schema may ask for an unreasonable scale** (`row_count: 10**12`; an
  `OverflowError` traceback for 10**400 on `--dry-run`). The row count is the user's chosen scale;
  no gate decides what is reasonable. Deployment limits apply.
- **L4. Postgres string literals double `'` but not `\`.** Safe with the default
  `standard_conforming_strings=on`; the sink emits scripts, it does not connect.
- **L5. Some outputs (`-o`, `--html`, `--json`, `SHAPE_METRICS`, `domains.save`, run manifests) are
  plain `open(..., "w")`**: they follow symlinks, overwrite silently, are not atomic. The path is
  chosen by the user running the command; hardening, not a vulnerability.
- **L6. `read_artifact` limits are generous** (512 MiB per member, 1 GiB total, ratio 200). They
  are API parameters; lowering the defaults would change the artifact spec's behaviour for large
  legitimate profiles. Escalation-free: noted here, no change.
- **L7. GSL `schema.path` and pack paths may be absolute or contain `..`** (`resolve_path`): the
  spec file author names files the run reads. Read-only; the reader is only reached by a user who
  chose to run that spec.
- **L8. Azure JSONL source stream** (`builtins/sources/azure.py:163`) is read by pyarrow without the
  depth check (the stream is not a local file). The source is user-chosen and remote; follow-up when
  pyarrow ships a depth limit.
- **L9. CI**: actions are pinned by tag, `pypa/gh-action-pypi-publish@release/v1` by branch;
  `release.yml` grants `id-token: write` at workflow level. Pinning to SHAs needs the owner's
  decision on update tooling (supply-chain policy, §9); no code change here.
- **L10. `load_private_key` does not check file permissions**; `write_keypair` creates 0600.
- **L11. Envelope signatures** (`artifact/secure.py`) are not domain-separated from artifact
  signatures; the messages cannot collide (the artifact message starts with a fixed prefix, the
  envelope signs a JSON header starting `{`). Changing the envelope would change the artifact
  spec: left for the lead.
- **L12. bandit lows** (below).

No decision (D-xx/T-xx), gate, tolerance or the artifact spec was changed or needs to change.
