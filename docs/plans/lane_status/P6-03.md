## What was built

- `src/shape/builtins/transforms/` — the `mask` built-in of the **`shape.transforms`** group (`Mask`: `apply` returns the
  tables, `mask` also returns which columns were masked and as what). `mask.py` (classification, per-type mappings,
  typed output, defense-in-depth check that no masked cell keeps its original), `_mask_values.py` (types, name
  matching, format-preserving generators). Registered in `pyproject.toml` and `shape.builtins.catalog` (one line each).
- **Column classification** uses Shape's profile engine (`shape.profile.reference.profile`, a dataset profile): value
  `pattern` (email, phone, ssn, ip_address, iban, postal_code; uuid is not personal data), `dtype`, `is_foreign_key`,
  `fk_ref_table` and the table's primary key. CSV values are read as text (so unmasked columns are written back as they
  were read) and classified against the profile of the typed read.
- `src/shape/cli/mask.py` — **`shape mask PATH -o DIR [--format csv|parquet] [--seed N] [--exclude COL] [--pii COL=TYPE] [--json]`**.
  Its own module; `main.py` has the two additive hunks (parser, dispatch) as `learn` has. The command reaches the
  transform through the plugin registry (the import contract forbids `shape.cli` importing `shape.builtins`).
  Exit 0 done, 2 input error. It refuses an output directory that would overwrite its input.
- Docs: `docs/MASK.md`, a row in `docs/plugins/builtins.md`, `CHANGELOG.md`.
- Tests: `tests/builtins/test_mask.py` (27). Harness (internal): `benchmarks/vs_refengine/mask_1to1/{verify,checks}.py`.
- D-13: nothing user-facing names the baseline (`check_user_facing` clean); the harness and this file are outside that scope.

## Deliberate differences from the baseline (owner decision 2026-10-01: fix defects that harm user trust)

The harness's `ALLOWED` table names each; a difference that is not listed fails the run, and so does a listed one that
did not occur. Each has a regression test in `tests/builtins/test_mask.py` that fails on the baseline's behaviour.

| ID | Baseline defect (observed on D2 or the `cat` case) | Shape |
|---|---|---|
| MASK-A1 | Name matching is by substring and ignores the values: `last_login` (timestamps) is replaced with user names (`login` is a username phrase); `description` would match `ip`, `business` would match `sin`. | Names match by whole word (`ZIP4`, `shipZipCode`, `customeremail` for a short list of fused words); a match is ignored when the column's type or values cannot hold the type (timestamps, booleans; numbers only as `zip`/`phone`/`ssn`/`credit_card`). |
| MASK-A2 | Replacements ignore the original's format: `(387) 306-3453` becomes `+1-210-343-3218x1960`, ZIP+4 `68307-9188` becomes `84026`, integer columns become text. | Digits/letters are replaced in place (punctuation, country code, width, case kept); card numbers stay Luhn-valid, IBANs keep country and check digits, dates stay in the original range and format; integer columns stay integers. |
| MASK-A3 | `ip_address` matches the `address` phrase first (dict order), so IPv4 addresses are replaced with street addresses. | The longest matching phrase decides: `ip_address` is an IP address. |
| MASK-A4 | `first_name` matches `name` first: a full name is written into a first-name column. | Longest phrase: `first_name`. |
| MASK-A5 | Replacements are drawn from a pool without excluding the original: about 1 cell in 50 keeps its state (observed on the `cat` case). No check that an identifier column's replacements are not original values or are distinct (D2 e-mail: 49,419 distinct values became 45,389). | A replacement always differs from its original; for identifier types it is no original value of the type and is distinct from every other (unique stays unique); impossible requests fail loudly. |
| (design) | A foreign key is remapped only when the profile flags it and the parent *primary key* was masked; unmapped child values keep their original (`fillna`); a same-valued column elsewhere gets different fakes. | One mapping per type over all tables: the same original value gets the same replacement everywhere; a column that is a detected foreign key to a masked key is masked with it whatever its name; orphans are masked, never kept. Not seen in a harness case (D2 has one table); covered by unit tests. |

## Notes for the lead

1. **Hyphens and quoting in CSV output.** Arrow's CSV writer quotes every string value (`"a@x.com"`); the content is
   unchanged and re-reads identically, but the bytes of unmasked columns differ from the input. The harness compares values.
2. The baseline also rewrites unmasked integer columns that hold nulls (`10` becomes `10.0`); the harness treats numerically
   equal values as equal for the baseline and exactly equal for Shape.
3. Free text is not searched (an e-mail address inside a `notes` column stays); the docs say so. `--exclude`/`--pii` adjust the choice.
4. D2 has one table, so the multi-table behaviour (consistent mapping, foreign keys, orphans) is covered by unit tests only,
   not by a baseline-parity case.
