   (`shape emit` to a console or file sink, `--auth sql` to an event destination, `--connection-string` to a
   non-SQL sink, `--auth` on a local profile).
4. **Secrets never appear in logs, errors, reports or recorded fixtures — with a test that fails if they do.**
   `check_clean` in `test_auth_cli.py` scans standard output, standard error, every file in the job store and
   the captured log (DEBUG level) after: a successful SQL-login run, a run whose driver echoes the whole
   connection string in its error, a failing run and its `jobs resume`, `jobs status|list`, and each Entra mode.
   `test_nothing_is_logged_with_a_secret`, the sign-in-failure scrubbing test (`_Guarded`: the original
   exception is not chained), the Key Vault error tests (HTTP status only, never the body or token), and
   `test_the_committed_tapes_of_these_scenarios_hold_no_secret` plus the existing scan of every tape
   (`test_no_tape_holds_a_secret_or_token`). The tape recorder now also blanks the `value` of a Key Vault
   response (`recording._hide_vault_value`), so a live recording could not store a secret either.
5. **A connection string's secrets are redacted wherever it is printed**: `shape.security.redact` (13 cases
   incl. brace-quoted `PWD={a;b}}c}`, `AccountKey`, `SharedAccessKey`, SAS `sig`, bearer, JWT, PEM, URL user:pass)
   applied in the CLI's error printer, job errors and log lines, `SinkError`, the sink registry's log lines
   and `shape_fabric._tsql.redact` (which every writer's `destination` and `WriteError` use);
   `test_a_connection_string_with_a_login_is_redacted_wherever_a_writer_shows_it`. Job records keep the
   references (`env://...`), never the string with a password (`redact` of sink settings was already there).
6. **`file://` refuses world-readable secret files on POSIX: refuse, not warn** (documented in
   `docs/plugins/fabric-auth.md` and `credrefs`'s docstring). Any group or other permission bit (0644, 0640,
   0604, 0660, 0666, 0750, 0601 tested) is an error that says `chmod 600 PATH`; 0600/0400/0700 pass; the check
   is done **before the read** (tested: no read happens). Public keys opt out with `private=False`. Windows: no
   check (the operating system's ACLs), stated in the docs.
7. **`sql` auth never puts the password on a command line**: (a) the option takes references only — a literal
   `--sql-password`, `--client-secret`, a `--connection-string` or `--sink-config ...connection_string=` holding
   `PWD=`/`Password=`/`AccountKey=`/`SharedAccessKey=` exits 2 without repeating the value and writes nothing
   (6 parametrised cases); the parser has no `--password`-style option (test). (b) The code path starts no
   process: `test_sql_sign_in_never_runs_a_process` makes `subprocess.*` and `os.system/exec*/spawn*/popen`
   raise while a full SQL write runs. The password goes into the in-memory ODBC string only (`{...}`
   quoting: `;`, `=` and `}` in a password cannot inject attributes — tested).

## Baseline defects found and fixed (owner's standing decision 2026-10-01: fix and record)

1. **A `file://` secret was read from any file, whoever could read it** (and only its first line kept):
   the baseline's resolver never checks permissions. Shape refuses a group/other-accessible file.
2. **`raw passthrough`**: the baseline's resolver returns any string that is not a reference as the secret,
   so `--client-secret hunter2` is accepted (and lands in the process list and history). Shape's
   secret options accept references only.
3. **Credential errors could carry the secret**: the baseline logs the exception text of a failed sign-in
   (`logger.warning("Connection attempt ... failed: %s", exc)`) and puts `f"Connection failed: {e}"` into the
   write result's errors, with no redaction; a driver error can include the connection string (the tests make
   a fake driver do exactly that). Shape redacts every such message, and re-raises a service-principal
   sign-in failure without chaining the original.
4. **Key Vault**: the baseline built `https://{vault}.vault.azure.net` from unchecked text (a vault name
   with a dot or slash changes the host or path). Shape validates vault, secret and version names first.
5. `device-code` in the baseline printed the prompt to **stdout** (mixing it into command output such as
   `--json`); Shape prints it to stderr.

## Design choices inside the work package (§0.3, none touches §2)

* **`kv://` discovery**: a provider table in core's `credrefs` (`kv` -> `shape_fabric.keyvault:resolve`),
  imported only when a `kv://` reference is resolved and only if the plugin is installed — not a new
  entry-point group, because `check_plugin_skeletons` (rightly) accepts only plugin-API groups and a new group
  would be a plugin API change (§2). `register_resolver("kv", fn)` still wins.
* `kv://` reads with the ambient Entra identity (environment, managed identity, Azure CLI), not with the
  `--auth` credential: the `spn` secret itself may be a `kv://` reference.
* The job store keeps `auth` as references so `shape jobs status|cancel|resume` sign in again without flags.
  Tokens are never stored.
