## Decisions the lane made (the issue left them open; all are documented in `docs/PROFILING_NOTES.md`)

* **"Profile output for unsampled runs must stay byte-identical."** Read as: every statistic and field the profile held before is
  unchanged. The issue also requires `sampling` (with `method: none`) and `type_inference` on every table and column, so the
  profile necessarily gains those keys. `tests/profile/test_w2_07_compat.py` pins it: the profiles of a CSV, a Parquet file, an
  Arrow table and a dataset, with the three new keys removed, equal `tests/profile/data/unsampled_golden.json`, which was made by
  running the code of the base commit (not by hand). The safe profile's allow-list is unchanged (test).
* **`confidence` of a text column that is mostly one type.** The readers type a column as an integer only when every value is an
  integer, so a CSV column that is 97% integers with 3% stray text is a `string` for them, and "the share of values that parse as
  `type`" would always be 1.0 for it. The acceptance item ("3% non-numeric values in an integer column reports confidence 0.97")
  is met by reporting, for an inferred text column that is at least half one narrower type, that type as `candidate` and its
  share as `confidence` (0.97), with `parse_shares.integer` 0.97; `shape types` reports it (`low_confidence`). Which types the
  readers infer is unchanged (out of scope).
* **A `declared` column's declared type** is recorded as `type_inference.declared` (the profile's `dtype` of a Parquet `string`
  column of integers is already `integer`, so the declared type would otherwise be lost). `inferred` is the narrowest type every
  value parses as.
* **`head` records its seed** (the one given, default 42) although it does not use it; a table read whole has `seed: null`.
* **Foreign keys under a dataset sample** are detected on the sampled child rows against the parent's whole key column; two
  independent samples of a parent and a child share few keys and would hide the relationship (test: without this the FK is lost).
* **Reference-pair checks always read the whole table** (not the caller's sample); they have their own internal sample above a
  million rows.
* **`type` proposals are opt-in** (`--kinds type`); `propose()` and `shape proposals propose` default to the three earlier kinds,
  and `DecisionFile.update(kinds=None)` means those kinds, so a default run never withdraws a pending `type` proposal. The
  decision file stays version 1 (a file without `type` proposals reads and writes unchanged: fixture written by the base code).
* **Applying an accepted `type` decision** (generation, plans): integer to `string` keeps the digits as text with their width;
  `datetime`/`date` and `integer`/`float` relabel; text to a number needs the profile to list every distinct value; anything else
  is a `DecisionError` that says to re-profile with `--decisions`.
* **`shape diff` `notes`** is present in `to_dict()`/`--json` only when there is a note (existing outputs are unchanged).
* **Two internal samples the issue did not list** were found by the guard test and are recorded: `pattern_rates` (a text column
  of more than 50,000 distinct values) and `kendall_tau` (a numeric association of more than 500 rows).
* **Profile registry diff** does not call a missing `adequacy`/`type_inference` (an older profile) a change.
