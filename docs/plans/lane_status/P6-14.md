## Allow-list of intentional differences (owner's standing decision, 2026-10-01)

Narrow and named in `pack_common.py` (`ALLOWED`); anything else that differs fails the harness. "Probe"
means the harness runs a small pack in both tools and asserts the baseline shows the defect and Shape
does not; "test" means `tests/scenario/test_defects.py`.

| ID | Defect in the baseline | Shape | Evidence |
|---|---|---|---|
| PK-1 | manifest `tables.*.file_paths` match by substring: `order` lists `order_line`'s file; a directory named like a table matches all | exactly the table's own files | probe, test |
| PK-2 | `spec_hash` is always empty (it hashes the spec's directory) | SHA-256 of the spec file | reference specs, test |
| PK-3 | `outputs` is always empty | kind, file and event counts, root | reference inputs |
| PK-4 | an unknown gate passes; a failed gate still reports SUCCESS | unknown gate fails; a failed gate without chaos fails the run (exit 1) | probe, test |
| PK-5 | an absolute or `..` landing root or topic name writes outside the output directory | rejected by validation; a symlinked landing directory is refused at write time | probe, test |
| PK-6 | an empty or non-mapping file, or a wrong-typed value, crashes or is misread | a `PackError` naming the key (exit 2) | probe, test |
| PK-7 | a pack's `chaos` section is parsed and ignored by the runner | applied with `shape.chaos`; counts per category in `chaos` | chaos spec, test |
| PK-8 | unknown keys and enabled-but-unsimulated features pass silently | one warning each | test |
| PK-9 | stream files hold datetimes as epoch milliseconds (pandas `to_json`) | ISO 8601 | test |
| PK-10 | GSL `chaos.config` nested as in the tutorial is stored as one setting called `config`; the tutorial's `cfg.get('warmup_days')` prints `None` | the nested settings are the chaos configuration | chaos spec, test |
| ID-1 | identity fields: `engine_version`, `sbom` values, timestamps, `run_id` | Shape's own | n/a |

Report: `pack_1to1_report.json` lists which entries the reference inputs and probes exercised
(`PK-8` and `PK-9` only by tests).

## Choices worth the lead's eye

- `pack run` of a spec with chaos exits 0 when gates fail (the failing gates are the result chaos is
  for); without chaos a failing gate exits 1. The run is one chaos day (`chaos.day`, else the later of
  `chaos_start_day` and `breaking_change_day`); all six categories can fire, counted in the manifest.
- Timing fields of a pack (cadence, rates, lateness, replay, done flags) are descriptive; the runner
  writes the data once and does not simulate a clock (as the baseline). Validation warns when
  `lateness`, `duplicates`, `backfill` or `failure_injection` is enabled. Stated in the docs.
- The baseline's table order in the manifest is the engine's table dictionary order; Shape's equals
  it (the harness compares the order).
- `eventstream` outputs of a spec are not sent (warning; `shape emit` does that).
