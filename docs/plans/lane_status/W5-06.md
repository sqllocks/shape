## Decisions made inside the package

- **Where a shared schema becomes a table.** An object that is a `$ref` to a named schema is that
  schema's table once; a property pointing at it is a foreign key column on the owner, an array of
  it a nullable foreign key column on the referenced table. An inline nested object or array of
  objects is a child table with a foreign key to its parent. (Item 2 states the inline case; the
  named case follows from "`$ref` between schemas becoming relationships".)
- **Cycles.** The engine refuses a cycle of foreign keys (`CircularDependencyError`), and schemas
  with mutual references or a child that is also referenced produce one. The importer breaks each
  cycle at one reference (preferring a nullable reference between named schemas), makes that column
  a plain integer column and lists it in the report as not imported. Found by generating the Avro
  fixture.
- **`write_tmdl(design, dir, source=...)`.** The derived `SchemaDesign` carries no additivity (it
  is plain tables), so the function takes the `DesignInput` as an optional `source`; the command
  passes it. Without it only the row counts are written. A measure with no declared additivity gets
  no sum (the lint already warns about it).
- **TMDL has no date or uuid type.** A date column is `dateTime` with the `Short Date` format and
  the importer reads that format back as `date`; uuid and time come back as strings (stated in the
  round-trip test). A date table is keyed by its `date` column in TMDL, so the importer keys it by
  the column its relationships point at.
- **TMDL import and keys.** A table's key is the column its relationships point at, else its
  `isKey` column, else a generated `id`; a date or other non-key-type column is never made a key
  (generated dates would not be unique), so the calendar table gets a generated `id`.
- **`--tmdl` without `-o`** does not print DDL (the DDL is still written with `-o`).
- **Partitions** are written as Lakehouse M with the two `{workspace_id}`/`{lakehouse_id}`
  placeholders `semantic_model.py` uses; `write_tmdl` also takes `source_type` `warehouse` and
  `sql_database`. No CLI flag for it (not on the Wanted list).
- **Measures and partitions on import** are reported as not imported (structure only), so
  `--strict` fails on any real semantic model, including one this repository exported.
- `tests/importers/test_w5_06_*.py` import `import_fixtures.py` through a `conftest.py` that adds
  the directory to `sys.path` (the suite runs in importlib mode), as `tests/generation/conftest.py`
  does.
