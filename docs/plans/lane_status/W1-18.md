## Deliverables

1. **Allow-list file.** `src/shape/plugins/trust.py` (`load_allowlist`), schema
   `src/shape/schemas/plugin-allowlist-v1.schema.json`, time capsule `tests/plugins/data/capsule_v1/`
   (JSON and YAML allow-list, public key, signed distribution), `tests/plugins/test_trust.py`,
   `tests/plugins/test_trust_compat.py`.
2. **Activation.** `SHAPE_PLUGIN_ALLOWLIST` (wins), `plugins.allowlist` through
   `PluginHost(project_config=...)` / `resolve_allowlist_path`. **Gap:** `shape.yml` (W1-04) is not in
   this branch's base, so nothing reads the file yet. When W1-04 lands, `default_host()` needs one
   line: pass the parsed `shape.yml` as `PluginHost(project_config=...)` (relative path resolved against
   the project file first). Built-ins are always allowed.
3. **Enforcement before import.** `PluginHost` (`status: blocked`, `PluginBlockedError`, never
   imported); CLI exit 2 with the specified message; `run_command` returns 2 for a blocked command.
4. **Installed-file check** (`record_sha256`, every hashed file in RECORD, first changed file named).
5. **Signatures.** `shape plugins sign|verify`, `require_signature`, `trusted_keys`, fail-closed
   without `cryptography`. Signed list excludes RECORD, the signature, INSTALLER/REQUESTED/
   direct_url.json and paths outside the install folder, so a wheel's signature holds after pip
   installs it (tested with a real `pip install --target`). `sign` refuses wheels with a `.data` folder.
6. **Visibility.** `shape plugins list` (allowed/blocked, `--json` `allowed`/`reason`), `doctor`
   (separate `blocked` list; exit 1 only for a listed plugin failing version/file/signature),
   `shape plugins allowlist init [-o] [--pin-hashes] [--json]`.
7. **Statement of reach.** `docs/plugins/trust-model.md` (checks vs non-checks, per-plugin table);
   `tests/plugins/test_trust_reach.py` checks the table against plugin source (env var names, fixed
   hosts, no subprocess/socket). Also `docs/plugins/host.md`, `CHANGELOG.md`.

## Decisions and notes

- Version specifiers need `packaging`, which is not a core dependency: without it a plugin with a
  `version` entry is blocked (fail closed) with a message. I did not add a dependency.
- Existing code touched: `host.py` (additive), `doctor.py` (adds `blocked`), `cli.py`, `cli/main.py`
  (parsers). `PluginRecord.as_dict()` is unchanged.
- Files not in RECORD, and RECORD rows without a hash (e.g. `.pyc`), are not covered; documented.
- Workflow changes for the lead: none needed.
