## 2. Decisions the issue left open (all recorded in `docs/EMIT.md`)

None changes a D-xx/T-xx decision. Where the text of the issue allowed more than one reading, the
choice made and the reason:

1. **A ramp holds its `TO` after it ends** (and the multiplier is 1 before the first ramp), so two
   ramps with a gap make a plateau. The alternative (revert to 1) would make a "warm-up" impossible
   to express with one ramp.
2. **`--daily-curve` with `--speed`** scales the replay speed at an event by the curve's multiplier
   at that event's UTC time of day (wall due time = integral of 1/(speed x multiplier) over event
   time), so a busy hour delivers more events per second of wall time. Every multiplier must then
   be above 0. With `--realtime` the curve starts at the local time of day when the run begins
   (`curve_origin` in the dry-run plan).
3. **`--day-seconds S`** gives each day S seconds and spreads its events evenly over it; the day sets
   the pace, so it cannot be combined with `--rate`, `--burst`, `--ramp`, `--daily-curve` or
   `--arrivals` (`--max-rate` still caps it). To tell an explicit `--rate` from the default, the
   `--rate` default is now resolved in `run()` (10 for `shape stream`, 100 for `shape emit`); the
   help text and behaviour are unchanged.
4. **`--rows` is accepted only with `--drift-plan`** (exit 2 otherwise).
5. **The plan's SHA-256 is of the plan file's bytes** (what `sha256sum` prints), so a whitespace-only
   edit is another plan to a checkpoint (the safe direction).
6. **A dead-letter record on an emitter** also carries `_shape_table` and `_shape_seq` (equal to
   `table` and `seq`), because an emitter takes its transport key from them; the dead-letter message
   is therefore keyed by the original event's key. A table target stores the records in the table
   `dead_letter`. `body_encoding` is present only for `"base64"` (absent means text).
7. **Which Kafka errors are per-message** (rejections): `MSG_SIZE_TOO_LARGE`,
   `_MSG_SIZE_TOO_LARGE` (the client's own refusal), `INVALID_MSG`, `INVALID_MSG_SIZE`,
   `INVALID_RECORD`, `CORRUPT_MESSAGE`, `RECORD_LIST_TOO_LARGE`, and only when non-retryable. Every
   other error (authorisation, brokers down, unknown topic) still stops the run after `--retries`.
   Other emitters (Event Hubs, Eventstream, Eventhouse) do not raise `RejectedEvents` yet; they
   behave as before.
8. **Avro and Protobuf mapping choices** (documented in the plugin README): uint64 is an Avro `long`
   (a value above 2^63-1 is a rejection), decimals are strings in Protobuf and JSON Schema, a
   Protobuf timestamp is microseconds since the epoch (UTC, or wall clock for no time zone), a float
   column is always nullable because non-finite floats are sent as `null`, Protobuf messages carry
   the message-index byte `0` as Confluent's serializers do. A table whose columns change during a
   run (a drift plan adds a column) registers a new schema under the same subject; the registry
   decides whether that is a compatible version.
9. **`--dry-run` and credential references**: `env://` and `file://` references are resolved (this
   machine only), so a missing variable is refused as at run time; a `kv://` reference is only
   checked for the form `kv://VAULT/NAME` (a lookup is a connection), so its malformed-form message
   is the dry run's own. `--auth` credentials are not created in a dry run.
