- **The domain's contract** (`domain_contract`): the contract format v1 that a domain's schema implies, per
  table: exact planned row count, every column required, no extra columns, the profiler's `dtype` where the
  declared type decides it, `nullable: false`, `max_null_rate` (the schema's rate plus five standard errors),
  `unique` for a single-column sequence key, `allowed_values` for enumerated string columns. It expects the
  rows the schema and scale **plan**, not the rows that were written, so a short table fails it.
  - No `dtype` is stated for `decimal` columns (whole-number decimals profile as `integer`) or for string
    columns other than non-numeric enumerations (digit-only text profiles as `integer`, `"true"/"false"` as
    `boolean`): a rule the profiler contradicts on correct data would be a false failure. Found by running
    the contract against retail (3nf and star, six seeds): the first draft failed on `address.zip_code`,
    `promotion.discount_pct`, `order_line.discount_percent`.

## Findings for the lead (not fixed here)

1. **`shape.check` passes a multi-table (`{"tables": {...}}`) contract vacuously against a single-table
   profile**, and `shape profile <folder>` reads a folder as **one table** (named after the folder). A pipeline
   that profiled a folder of generated tables with the CLI and checked a domain contract passed on damaged data
   (found by my damage test). The ADF script therefore profiles in process as a dataset and refuses a profile
   that does not hold exactly the generated tables. `shape.contracts.v1` should probably raise when a contract
   has `tables` and the profile is not a dataset (outside this work package).
2. The PF-05 image carries no domain. The ADF generation gate needs a derived image (recipe in the runbook).
3. Artifact folders are named by the second (`<outputDir>/<name>/<timestamp>/`, from PF-02/DM-05): two runs in the
   same second share a folder, so a baseline taken in the same second is overwritten. Tests copy the baseline.
4. One existing test changed: `tests/demo/fabric/test_pipelines.py::test_bind_replaces_every_placeholder` binds
   two more notebooks (`shape_generate`, `shape_profile_domain`) because the committed pipelines now hold their
   placeholders; it still asserts that no placeholder remains.
5. `generateSample` runs the whole domain at its default scale per call (0.12 s measured with the Rust kernel for
   retail small; the pure-Python kernel was not timed); the 240 s function limit is not a concern at that scale, but a domain whose
   default scale is large would be slow. Not measured in Fabric.
