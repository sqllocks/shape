## What was built

- **Retail as the first `shape.domains` entry** (`plugins/shape-domains`): `shape_domains.retail.RetailDomain`
  (entry point `shape.domains: retail`) with `data/retail/schema.json` (the baseline's retail dump, imported

  [--check]`. Added the `[domains]` extra (T-08), the plugin install to `make bootstrap` and the CI test job.
- **`shape.generation.domains`** (core): `load_domain(name)` finds the plugin, registers its reference data
  for `reference_data` / `record_sample`, returns the parsed `GenSchema`; `domain_names()`,
  `DomainNotFoundError` (`docs/GENERATION_ENGINE.md`, "Domains").
- **Harness**: `generate.py --impl shape` is now the product path (domain plugin + `Engine` + `write_engine`),
  `bench.py --warmup N` (T-19: discarded fresh-process runs), `bench.py` reports an overlapped impl correctly.
- **Strategy**: `temporal` takes `unit` (`s|ms|us|ns`): the baseline's uniform dates are `timestamp[ns]` and
  T-21 (a) needs the same Arrow type; `derived` dates follow their source.
- **Performance work, outputs unchanged** (the as-found product path was 2.8x at medium; see "Where the time
  went"):
  - `Engine.generate()` runs the chunks of a dependency level on `SHAPE_THREADS` threads (default: every core;
    `1`: one), in chunks of 32k-131k rows; it hands tables to a writer as they are final
    (`generate(on_table=, on_batch=)`: a table no post-pass can change streams chunk by chunk, the others after
    the last rule repair that can change them) and `write_engine` uses that to overlap writing with generation
    and the post-passes. Output is identical for any thread count and chunk size (tests below).
  - `shape.generation.keypos` + two native kernels with reference twins, `dense_rows` and `group_sums`
    (`rust/shape-kernel/src/gen/relational.rs`, `kernel/reference/relational.py`, `docs/GENERATION_KERNEL.md`):
    the row of a key in a parent whose primary key is a sequence is `key - start`, found in one pass; the compute
    phase's `sum_children` / `count_children` are one pass in row order (bit-equal to Arrow's grouped sum;
    `avg_children`, `min`, `max` and non-sequence keys keep the Arrow path). Used by `lookup`, the compute phase
    and the business-rule repair; the `constrained_by` foreign key reads a direct-address table.
  - Business-rule repair is split into `fix_rule` steps so a table is handed over after its last repair, before
    the final validation.
  - `shape.generation.runtime.generation_memory`: Arrow's system memory pool for the duration of `generate()`
    (switch off with `SHAPE_MEMORY_POOL=default`).
  - Parquet sink: row groups of up to 1,048,576 rows (was one per 64k batch) and `dictionary_pagesize_limit`
    128 KiB (see deviations).

## Deviations, decisions made inside the work package, things for the lead

1. **Parquet writer tuning within T-17.** T-17 says snappy and dictionary encoding on; both are kept. Two
   properties are tuned: row groups of up to 1,048,576 rows (was one per input batch, so 64k) and
   `dictionary_pagesize_limit` 128 KiB (pyarrow's default is 1 MiB): a column whose dictionary outgrows 128 KiB
   (about 16k distinct 8-byte values, so keys and amounts) stops using it early instead of hashing a megabyte of
   dictionary first. Write CPU for the retail medium tables fell by about a quarter (617 ms -> 453 ms in a
   single-threaded probe), files are about 3% larger (37.6 MB against 36.4 MB). Both are options of the sink
   (`row_group_rows`, `dictionary_page_bytes`). If the owner reads T-17 as forbidding this, setting
   `DICTIONARY_PAGE_BYTES` back to 1 MiB costs roughly 0.05 s at medium.
2. **Arrow system memory pool during generation** (`generation_memory`). Arrow's default pool (mimalloc) maps
   and decommits memory for every large array; on this VM that doubled run time in half of the runs (system time
   0.4 s or 1.3 s, bimodal). Switching to the system pool for the duration of `Engine.generate()` fixes most of it
   (medium median 1.17 s -> 0.90 s in an A/B). `ARROW_DEFAULT_MEMORY_POOL=system` set before `pyarrow` is
   imported does slightly better again (about 0.1 s) because C++ code that does not follow the Python-level pool
   (the Parquet encoders) then uses it too; I did **not** set it in the harness or in `shape/__init__`, since
   that would be a process-wide change for every Shape path (profiling's G1 numbers were measured with the default
   pool) and, for the harness, a change to how the baseline runs. The CLI of P4-10 can set it before its lazy
   imports; the lead may want to.
3. **Harness changes** (all in `benchmarks/vs_refengine/domain_1to1/`, outside the package): `generate.py`'s
   shape runner loads the `shape.strategies` and `shape.sinks` plugins before the timer (T-19: imports excluded
   for both; the baseline's import loads every strategy and writer), reports `rows` in generation order (the
   verifier compares table order) and has no `write_s` (generation and writing overlap); `bench.py --warmup` and
   an overlapped-impl summary line. `run.py`'s generate workloads still use `IMPL` = `reference_port` and
   `results.json` is not updated: recording `shape` generation there is the gate run's job (G4), the numbers
   above come from `domain_1to1/bench.py` directly.
4. **`temporal.unit`** is a new optional key of an existing strategy (default `us`, nothing changes without it);
   the retail schema sets `ns` on `customer.signup_date` and `promotion.start_date` (their `derived` end date
   follows). Documented in `docs/GENERATION_STRATEGIES.md`, tested.
5. **The plugin must be installed for the retail tests.** CI's main test job and `make bootstrap` now install
   `plugins/shape-domains`; `tests/plugins/test_host.py`'s `_third_party()` filter now also leaves out
   `sqllocks-shape-*` distributions (it assumed no first-party plugin is installed; same intent, no assertion
   changed). `tests/generation/test_retail_domain.py` needs the plugin; without it `load_domain` raises
   `DomainNotFoundError` naming the package.
6. **Retail 3NF only.** `retail_star` is not shipped here (the plan puts `--mode` in P4-10 and the other
   domains in P6-01); `Domain.definition()` has one schema.
7. **For P4-10 (GEN-CLI) and START:** `import shape.generation` imports pandas (0.3 s) through
   `generation.certificate -> capture -> profile.reference.readers`. In-process GEN-IN excludes it (imports
   are before the timer), but a CLI that imports `shape.generation` eagerly pays it in GEN-CLI and START.
8. **Measurement noise on this VM.** Page-fault cost is bimodal and the page cache matters (I dropped caches
   before each timed session: `echo 3 > /proc/sys/vm/drop_caches`); RefEngine's own medium median moved between
   8.2 s and 9.2 s across the sessions above. The ratios (11.6x, 13.5x at medium) are from complete,
   independent bench runs; a lead run on a different 4 vCPU machine may differ by a point or two either way.
9. `pytest -m heavy` as written collects `tests/demo/fabric`, which needs `nbformat` (not installed in the
   venv); like the other suites it was run with `--ignore=tests/demo/fabric`.
