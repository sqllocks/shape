## 2. Interfaces

**Source (plugin API v1, `src/shape/plugins/api/v1.py:105`):**

```python
class SnowflakeSource:
    name = "snowflake"; schemes = ("snowflake",)
    def __init__(self, connect=None): self.sink = SnowflakeSink(connect=connect)   # as W9-01
    def can_open(self, uri: str) -> bool            # scheme only; never validates (fail-fast later)
    def schema(self, uri: str, **options) -> pa.Schema
    def read(self, uri: str, **options) -> Iterator[pa.RecordBatch]
    def profile_database(self, uri: str, **options) -> Profile
```

Options (same names as W9-01, validated before any connection; anything else is
`ShapeError("unknown source option: ...")`): `password`, `credential`, `token_scope`, `connect`,
`connection`, `batch_size` (default 65,536), `sample_rows` (default 1,000; `0` catalog only),
`tables` (non-empty list), `name`; Snowflake also `private_key`, `private_key_passphrase`;
Databricks also `token`, `client_id`, `client_secret` (exactly the sinks' `resolve_auth`).

**URIs.** `snowflake://<user>@<account>/<db>/<schema>?warehouse=WH&role=R[&table=T]` and
`databricks://<host>/<http_path>?catalog=C&schema=S[&table=T]`. Parsed with the sink's
`parse_target` (so every refusal the sink has, the source has): password in the URI, a
secret-looking key, a missing account/user/host/path. `table` present: one table; absent: the
whole schema. A `table` or `schema` name goes through `_sql.check_identifier(..., dialect)`.

**Reads.** Snowflake: `cur.execute(select)` then `for tbl in cur.fetch_arrow_batches(): yield
from tbl.to_batches(max_chunksize=batch_size)`; session `warehouse`/`role` from the URI, as the
sink's `connect_params`. Databricks: `cur.execute(select)` then `while (tbl :=
cur.fetchmany_arrow(batch_size)).num_rows: yield from tbl.to_batches()`. The `SELECT` names
every column quoted (`_sql.quote`); a VARIANT/ARRAY/OBJECT column is selected as
`TO_JSON(col)` (Snowflake) and a STRUCT/ARRAY/MAP as `to_json(col)` (Databricks) so it arrives
as JSON text. Each batch is cast to the catalog schema (`pa.Table.cast`) so the connector's
own Arrow types (Snowflake returns `decimal128` for `NUMBER` columns and `int64` for small
integers depending on the connector's settings; Databricks returns `timestamp[us]` with or
without zone) never leak into the profile; a cast that fails names the column.

**Type maps (item 2), documented in the README.** Snowflake `INFORMATION_SCHEMA.COLUMNS`
(`DATA_TYPE`, `NUMERIC_PRECISION`, `NUMERIC_SCALE`, `CHARACTER_MAXIMUM_LENGTH`, `IS_NULLABLE`):
`NUMBER(p,0)` → `int8` (p ≤ 2), `int16` (≤ 4), `int32` (≤ 9), `int64` (≤ 18), else
`decimal128(p,0)` (p = 38 → `decimal128(38,0)`); `NUMBER(p,s)` with s > 0 → `decimal128(p,s)`;
`FLOAT` → `float64`; `BOOLEAN`; `DATE` → `date32`; `TIME(p)` → `time64("us")`;
`TIMESTAMP_NTZ(p)` → `timestamp("us")` (nanoseconds cut, said in the docs); `TIMESTAMP_TZ(p)`
and `TIMESTAMP_LTZ(p)` → `timestamp("us", tz="UTC")`; `TEXT`/`VARCHAR(n)` → `string`
(`shape.sql_type` keeps the length); `BINARY` → `binary`; `VARIANT`, `ARRAY`, `OBJECT` →
`string` with `shape.encoding=json` (W9-06 makes them nested); `GEOGRAPHY`/`GEOMETRY` and
anything else → text with one warning naming the column (as W9-01). Databricks
`information_schema.columns.full_data_type`: `TINYINT`/`SMALLINT`/`INT`/`BIGINT` → `int8`..`int64`;
`DECIMAL(p,s)` → `decimal128(p,s)`; `FLOAT` → `float32`; `DOUBLE` → `float64`; `BOOLEAN`;
`DATE`; `TIMESTAMP` → `timestamp("us", tz="UTC")`; `TIMESTAMP_NTZ` → `timestamp("us")`;
`STRING` → `string`; `BINARY`; `ARRAY<..>`/`STRUCT<..>`/`MAP<..>` → JSON text; `INTERVAL`,
`VARIANT` and anything else → text with a warning.

**Whole-schema profile (item 3).** Same document shape as W9-01's `profile_database`:
`Profile({"tables": {...}, "relationships": [...], "sampling": {...}}, name=...)`, each table
from `profile(sampled, name=table, joint=False).tables[table]` with `row_count` (catalog),
`primary_key`, `sampled_rows`, `sample_method`, per column `declared_type`, `nullable`,
`is_primary_key`, and `is_foreign_key`/`fk_ref_table`/`fk_evidence="declared"` on child
columns; relationships `{"name", "parent", "child", "parent_columns", "child_columns",
"type": "one_to_many", "evidence": "declared"}`. Catalog queries: Snowflake
`INFORMATION_SCHEMA.TABLES` (`TABLE_TYPE='BASE TABLE'`, `ROW_COUNT`), `SHOW PRIMARY KEYS IN
SCHEMA`, `SHOW IMPORTED KEYS IN SCHEMA` (ordered by `key_sequence`); Databricks
`information_schema.tables` (`table_type='MANAGED'|'EXTERNAL'`), `SELECT COUNT(*)` per selected
table (`row_count_source: "count"`), `table_constraints` + `key_column_usage` for
`PRIMARY KEY`, plus `referential_constraints` to pair the FK with its referenced table.
Sampling: `sample_rows` ≥ catalog count → whole table (`sample_method: "whole_table"`);
Snowflake `SAMPLE ROW (n ROWS)` (`"sample_rows"`); Databricks `TABLESAMPLE (n ROWS)`
(`"tablesample_rows"`); `0` → `"catalog_only"` with the W9-01 null fields.

**Provenance (item 5).** `result._provenance = {"format": "shape-database-source",
"version": 1, "dialect": "snowflake", "account": <account>, "warehouse": <WH or null>,
"role": <R or null>}` and for Databricks `{"dialect": "databricks", "host", "http_path",
"catalog"}`; never a credential. `shape.save` writes it to the manifest (outside the content
id, as the Delta version is). Check that W9-01's dispatch returns the plugin's `Profile`
unchanged (it does: `return cast(Profile, plugin.profile_database(...))`).

**Credentials (item 4).** `plan.secret` and `plan.auth` from the sink's `resolve_auth`; every
error through `scrub(str(exc), [plan.secret, *auth secrets])`; `test_bridge_rejects_uri_credentials_without_job_file_leak`
(W9-01) parametrised over the new schemes; the private-key PEM must never appear in a message
(`_auth._PEM` already masks it; test it).

## 5. Decisions already taken, and the one to record

- Databricks row counts come from `SELECT COUNT(*)` because Unity Catalog's
  `information_schema.tables` has no row count; recorded in the profile as
  `row_count_source: "count"` (W9-15 uses the same key for Oracle's `"statistics"`). Record it in
  the lane status; it does not change a decision in §2.
- Snowflake and Unity Catalog keys are informational: both are recorded with
  `evidence: "declared"` (the issue says so for Snowflake; say it for both in the README).
- Snowflake `TIMESTAMP_NTZ(9)`: microseconds, nanoseconds cut, documented (the Delta sink's
  rule, §2.3 2026-10-03).
- Out of scope (issue): Synapse, writing, nested beyond JSON text, Databricks clusters (SQL
  warehouses only). Do not add a `profile-db`-style command.
