## 2. Interfaces

**Decoder contract (core).**

```python
# src/shape/streaming/codecs.py
class DecodeError(ValueError): ...
Decoder = Callable[[StreamMessage], dict[str, Any]]          # raises DecodeError for a bad body
def arrow_schema_from_avro(avsc: Mapping) -> pa.Schema       # records→struct, arrays→list, maps→map, unions with null→nullable, logical types as formats.py documents
def arrow_schema_from_proto(proto: ProtoFile, message: str) -> pa.Schema   # messages→struct, repeated→list, map<k,v>→map, optional/oneof→nullable
def avro_encoder(schema: pa.Schema, avsc: Mapping) -> Callable[[pa.RecordBatch], list[bytes | EncodeError]]
def avro_decoder(avsc: Mapping) -> Decoder                   # fastavro.schemaless_reader
def protobuf_encoder(schema: pa.Schema, proto: ProtoFile, message: str) -> ...
def protobuf_decoder(proto: ProtoFile, message: str) -> Decoder
def check_table_against_schema(table: str, schema: pa.Schema, target: pa.Schema) -> None   # refuses before the first message, naming the field
```

`decode_messages(messages, *, schema=None, decoder=None, ...)`: with a `decoder`, each
message body goes through it; a `DecodeError` (or a decoder exception) counts as `undecodable`
exactly as a non-JSON body does today, with the same `on_error` rules; nested values arrive as
Python dicts/lists and become Arrow struct/list/map columns instead of JSON text (W9-08's
`nested` flag already names the two behaviours for headers; reuse the name).

**Write without a registry (item 1).** Kafka: `--event-format avro --sink-config
kafka.schema_file=orders.avsc`; `--event-format protobuf --sink-config
kafka.schema_file=orders.proto --sink-config kafka.message=Order`. The message value is the
plain Avro binary (`schemaless_writer`, no magic byte, no id; documented as "plain Avro,
not the Confluent wire format") or the plain Protobuf bytes. Headers and the D-12 key are
unchanged. `schema_registry_url` and `schema_file` together are refused (exit 2). A table whose
Arrow schema does not fit the file's schema is refused before the first message, naming the
field (`check_table_against_schema`); a nullable Arrow column needs a `["null", T]` union /
`optional`. Event Hubs: the same options under `eventhubs.`; content type `avro/binary` /
`application/x-protobuf`; properties unchanged.

**Read (item 2).** Both sources: `format=avro` with `schema_file=<.avsc>`, or with
`schema_registry_url=` for the Confluent wire format (Kafka: schema by the 4-byte id, cached;
`schema_registry_username`/`password` as a credential reference, as `registry.py` requires);
`format=protobuf` with `schema_file` + `message`. Reject-and-count rules are JSON's: a body
that fails to decode is `undecodable`; a row that does not fit a pinned `schema` is `rejected`.

**Nested (item 3).** Type table (README, both plugins): Avro `record` ↔ `struct`, `array` ↔
`list`, `map` ↔ `map<string, T>`, `enum` ↔ dictionary(string) on read / string on write,
`fixed` ↔ `fixed_size_binary`, logical `decimal`/`date`/`time-*`/`timestamp-*`/`local-timestamp-*`/`uuid`
as `formats.py` documents today; Protobuf `message` ↔ `struct`, `repeated` ↔ `list`, `map<K,V>`
↔ `map`, `enum` ↔ int32 with the names in field metadata, `oneof` members nullable,
`google.protobuf.Timestamp` ↔ `timestamp("us", tz="UTC")`. `_kind`'s refusal is lifted for
these; anything still unmappable (`Any`, extensions: out of scope) is refused naming the column.

**Azure Schema Registry (item 4, approved).** Event Hubs only. Options
`schema_registry_url=<namespace>.servicebus.windows.net`, `schema_group=<group>`; sign-in with
the emitter's existing `credential` / `DefaultAzureCredential` (`entra` extra). Write:
`AvroEncoder(client, group_name=group, auto_register=False).encode(row, schema=avsc_text,
message_type=EventData)`; the encoder stamps `content_type = "avro/binary+<schema_id>"`.
Read: `AvroEncoder.decode(event)` resolves the id from the content type (cached by the SDK);
Shape caches the Arrow schema per id. Everything is behind the `[schema-registry]` extra and
imported only when used, with the `pip install` command in the error.

**Schema evolution on read (item 5).** Per-message schema resolution (Confluent id or Azure
id) cached in a dict; without a reader `schema`, the batch schema is the first message's and a
later message with a different writer schema is read through Avro schema resolution
(`schemaless_reader(buf, writer_schema, reader_schema)`); with a reader `schema` option (an
`.avsc`/`.proto` path or the pinned Arrow schema from a checkpoint) every row must fit it or is
`rejected`.

## 5. Decisions to record in the lane status (proposed; the lead confirms)

- **D1, where the codecs live.** Two plugins need the same Avro/Protobuf ↔ Arrow mapping and
  a plugin may not import another plugin. Proposed: a core module `src/shape/streaming/codecs.py`
  with lazy imports and **no new core dependency** (`fastavro`/`protobuf` stay plugin extras;
  the `INSTALL` hint names the plugin extra that is installed, or both). This keeps T-07 (core
  carries no client libraries) and leaves `sqllocks-shape`'s dependency floors untouched. The
  alternative (copy the mapping into both plugins) duplicates 300 lines. If the lead prefers
  the mapping in `shape_kafka.formats` as today, then `shape-eventhubs` must depend on
  `shape-kafka`, which no plugin does today (escalate rather than do it).
- **D2, Event Hubs extras.** `shape-eventhubs` gains `avro`, `protobuf` and `schema-registry`
  extras mirroring Kafka's; the `schema-registry` extra is the one the Owner approved.
- **D3, plain-binary content types.** `avro/binary` and `application/x-protobuf` on Event
  Hubs; Kafka carries no content type (headers unchanged). Documented.
- **D4, base.** Build on `lane/W9-08` (every file overlaps); if W9-08 lands first, on the
  release. Record the base SHA.
- Out of scope (issue): JSON Schema on Event Hubs, Protobuf `Any`/extensions, registry auth
  beyond basic and Entra, Kafka Connect/ksqlDB conventions. The Eventstream emitter inherits
  the options (W9-08's note) and gets no test of its own here.
