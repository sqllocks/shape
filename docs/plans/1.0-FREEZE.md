# Shape 1.0 format and CLI contract freeze

Status: Owner approved on 2026-11-14; frozen at 1.0. Prepared against
`origin/main` at `12bdfd5`. Approval freezes the compatibility baseline for 1.0;
it does not declare 1.0 released or change the current early-access behavior.

## Recommendation presented to the Owner

> Freeze the existing persisted formats, canonical vectors and stable CLI contracts for 1.0.
> Support all frozen format versions throughout 1.x; preserve their recorded 0.9.0 minimum reader.
> Require JSON on core command leaves and dry-run on writers/senders, with only the three existing exemptions.
> Preserve native dry-run plans, server protocols, exit codes and JSON shapes; allow compatible additions in minors.
> Enforce the baseline in CI; revise this document for reviewed additions and reserve incompatible changes for a major.

The Owner answered **“1”**, then **“1 — Approve.”** The decision is recorded in
[OWNER_DECISIONS.md](OWNER_DECISIONS.md#one-zero-freeze).

The artifact rules in [SHAPE_ARTIFACT_SPEC.md](../specs/SHAPE_ARTIFACT_SPEC.md) remain normative. |

Existing vectors remain immutable; new format versions get additional vectors without replacing old expectations. |
| CLI flags and exemptions | Existing stable parser contracts in `tests/cli/cli_surface_v1.json`; core-wide machine-flag coverage in `tests/cli/test_ci_flags_coverage.py`; exact reviewed exemption file `tests/cli/ci_flags_exemptions.json`. |
| Exit codes | Existing command/outcome mappings in `shape.cli.exitcodes.CODES` and `docs/EXIT_CODES.md`: 0 ok; 1 a check failed; 2 bad input; 3 and above a command's own verdict. Preserve documented numeric verdicts, native dry-run failure 1, scale interruption 130 and closed-pipe 141. |
| JSON output shapes | `shape-result` v1 and `shape-dry-run` v1 envelopes, payload placement and existing stable command payload keys/types. Preserve path-valued `--json FILE` report payloads and `--json -` stdout behavior. Preserve existing native plan shapes. |

**Minimum support window: the entire 1.x series.** Every 1.x reader accepts every
frozen pair, including legacy declarations and implicit versions where specified.
Keep the first-reader floor for an existing format version unchanged; do not raise
`min_shape_version` merely because a newer Shape release wrote the file. The writer's
`shape_version` continues to identify the actual writer release.

An additive optional field in an existing version cannot require a newer reader.
A new incompatible format version must name its real first reader, refuse safely
in older readers, add an offline migration and retain all older readers throughout
1.x. No claim is made that a 1.0 reader understands a future incompatible version.
Direct reading may end only in a new major, after at least one prior release's
deprecation notice and with an offline `shape-migrate` path retained. No frozen
version is scheduled for removal. This is format compatibility, not maintenance
of old binaries: the Owner's latest-release-only security support and no-backports
decision remains in force. There is no new calendar-duration support commitment.

## What "every command" means

The coverage boundary is the core command leaves walked by
`shape.cli.introspect.core_commands()`, including separately built profile parsers
and `bridge schema`. Group-only help parsers and global options are not operations;
plugin-added commands retain their separate plugin policy.

Every covered leaf exposes `--json`, except the exact JSON exemptions below.
Commands that can write files, change local state, or send to a target expose
`--dry-run`, except the exact dry-run exemption below. The writing classification
is the checked `WRITE_OPTIONS` and `STATE_WRITERS` inventory, reconciled with
`machine.SPECS` and native handlers. Read-only leaves have no `--dry-run`: there is
no operation to preview. New commands and new write paths must join this coverage.

| Flag | Exact exempt path | Reason frozen from the exemption file |
|---|---|---|
| `--json` | `version` | already prints exactly one JSON document and has no other mode |
| `--json` | `bridge` | a long-running server: its standard output is the JSON protocol, one document per line (`bridge schema` has --json) |
| `--dry-run` | `bridge` | a long-running server: there is no run to preview (`bridge schema --out` has --dry-run) |

Do not inject a one-document CLI envelope into the bridge's line-oriented server
protocol or replace starting the server with a preview. `bridge schema` remains
covered. `version` is read-only, so its lack of dry-run follows the general rule
and is not a fourth exemption.

Native handling is **not an exemption**. `generate`, `demo run`, `demo cleanup`,
`seed`, `composite`, `canary make`, `gameday run` and `registry prune` keep their own
dry-run handlers. `emit` and `stream` keep their native dry-run JSON documents
with `actions` and their additional `plan`; they are not double-wrapped. Preserve
native validation, planning output and exit codes rather than normalizing them.

## JSON and exit-code details

`shape-result` v1 has `format` (string, `shape-result`), `version` (integer, 1),
`command` (string) and `exit_code` (integer). Object payload keys are retained at
the top level; a non-object payload, or an object colliding with an envelope key,
also survives under `payload`. Expected errors can add an `error` string. Human
text moves to stderr and is retained under `output` when it is the payload.

`shape-dry-run` v1 has `format` (string, `shape-dry-run`), `version` (integer, 1),
`command` (string) and `actions` (array). Each action has string `action` and
`target`; action values are `write`, `create`, `delete`, `send`. Failed planning
adds `error` and leaves `actions` empty. Preserve secret redaction and zero writes
or connections during planning. Native command-specific `plan` keys stay intact.
The machine document reader rejects unsupported versions and malformed headers.

For stable commands, existing payload keys keep their names, types and meanings;
JSON key order, human prose, timings and environment-specific values are not frozen.
Optional keys may be added. Native file-report JSON remains the existing payload
rather than gaining a stdout envelope. Parser errors and protocol-server output
retain their existing paths; approval does not promise envelopes where none exist.
Existing command-specific JSON and exit-code tests remain part of enforcement.

## Allowed and forbidden after approval

Allowed in additive minors: optional fields, optional flags, commands/subcommands,
new choice values and explicitly versioned formats with migrations and old readers
retained. Update this document's enforcement baseline and explain the addition in
the same reviewed PR. Preserve frozen vectors and corpus generations; append new
fixtures for new versions. Documented bug fixes may correct behavior to the contract.

Forbidden within 1.x: rewriting canonical bytes or vector expectations for an
existing version; removing old format readers or legacy declarations; raising an
existing version's minimum reader; reinterpreting existing fields; removing,
renaming or changing the type/meaning of stable JSON keys; changing an existing
outcome's exit code; removing or narrowing stable flags; adding required arguments;
silently broadening exemptions; changing server semantics to satisfy flag coverage.
A breaking change requires a major release and the applicable deprecation/migration
process. Editing this document alone does not authorize a breaking 1.x change.
Experimental payloads retain their existing experimental status; the core-wide
machine envelope and flag-coverage requirement still apply to them.

## Options

| Option | Consequence | Recommendation |
|---|---|---|
| Literal flags on every parser, including servers and read-only operations | Requires runtime changes, meaningless previews and server protocol decisions. | Reject for this documentation/test-only freeze. |
| Freeze current eligible-command coverage and exact exemptions; retain every frozen reader through 1.x | Preserves behavior, makes the roadmap wording testable, and gives a clear major-version support window. | **Approve.** |
| Defer the freeze, or use a rolling last-N-minors reader window | Leaves sign-off unresolved; a rolling window weakens the existing read-old promise. | Choose only if the Owner requests a revised policy. |

## Enforcement

The freeze tests read a versioned baseline recorded in this document. They pin the
vector file's SHA-256, exact exemption file (including reasons), existing parser
snapshot, reader metadata and command/exit mappings. Check the live parsers and
reader registry against that baseline, so changing both implementation and its
ordinary regenerated fixture still fails until this document is revised.

Exercise emitted JSON envelopes, error documents, dry-run documents and native
plans for their frozen fields/types; retain command-specific payload tests.
Reader-window tests cover every frozen kind/version, its original first reader,
stamping and readable legacy/implicit forms, plus refusal of a future version.
Hash the normative state/CLI contract sections to require an explicit baseline
revision when their text changes. Additions remain possible through reviewed
document revisions; historical expectations are not silently regenerated.

Validation: `make bootstrap`, then `uv run --locked` for `pytest tests/state
tests/cli`, Ruff checks and formatting checks. One independent smaller-agent review
must prove each guard fails after a throwaway local mutation, restore every probe,
and confirm the diff contains documentation/tests only. Open one ready PR with its
complete description, DCO-sign every commit, require green hosted checks and merge
through the PR merge API. No version bump, tag or release is part of this decision;
the existing release runbooks and release gates remain in force.

explain the addition here and update this digest in the same reviewed PR.
Never regenerate historical vector values to make a failure pass.
