# SQL and Delta type fidelity

Status: experimental.

## Preserve declarations rather than guessing from rows

SQL writes use Arrow integer widths, decimal precision/scale, float32 and temporal units.
Unsigned integers widen to a suitable signed type; uint64 needs 20 decimal digits.
Undeclared strings are unbounded, not VARCHAR(255) or the first batch's longest value.
Zoned timestamps preserve the instant to microsecond precision and normalize to UTC;
the original zone name is not retained. Zone-less values remain zone-less in SQL.
See the [dialect table](SINKS.md#sql-type-fidelity-on-write) for exact declarations and limits.

This local exercise needs the [locked example environment](contributing/EXAMPLES.md),
including the databases plugin and Delta extra. Start in an empty directory with
`SHAPE_DOCS_REPO` pointing to the checkout. The
[complete source](../examples/docs_type_fidelity.py) prints a PostgreSQL script without a connection,
then writes a real local Delta table, reads its decimal type back and rejects a negative append.
Assertions verify that the rejected append keeps the existing Delta version.

```bash {.runnable-reference}
python "$SHAPE_DOCS_REPO/examples/docs_type_fidelity.py" --delta
```

## Generate SQL constraints

`--sql-constraints keys` is the generation default: primary, foreign and declared unique keys.
`all` adds supported structured CHECK and literal DEFAULT clauses from generation schemas
and JSON/YAML contracts. `none` omits derived declarations; `keep` is its compatibility alias.
These defaults apply to generation, not every emit, seed or scale workflow.
The example's amount minimum becomes a CHECK. A remote-looking URI in a dry run does not
connect, authenticate, generate values or write rows. The emitted DDL is the resolved plan.

<!-- example: 1 -->

```bash {.runnable-reference}
shape generate orders.gen.json --to postgresql://user@unreachable/db --dry-run --sql-constraints all --contract amount.contract.json
```

??? info "Output (exit 0)"

    ```text {.expected}
    ALTER TABLE "orders" ALTER COLUMN "amount" SET DEFAULT 12;
    ```

PostgreSQL, MySQL, DuckDB, SQL Server and Fabric SQL database enforce foreign keys,
UNIQUE and CHECK, with literal defaults. Warehouse foreign/unique keys are informational
and CHECK/DEFAULT are unsupported. Snowflake keys are informational and CHECK is unsupported.
Databricks Unity Catalog primary/foreign keys are informational; CHECK uses ALTER TABLE,
while UNIQUE/DEFAULT are unsupported. Unsupported declarations are reported explicitly.
DuckDB creates parent-first inline foreign keys.

Existing database writes verify requested catalog declarations before mutation. Supported
PostgreSQL/MySQL dataset truncation reruns coordinate enforced references. Unsafe replacement,
external incoming references or incompatible chunk commits fail with a named constraint when
integrity cannot be preserved. MySQL replacement DDL cannot offer transactional rollback.
Raw SQL checks, arbitrary expressions, triggers, sequences and deferred constraints are outside
this feature. [Sinks](SINKS.md#generated-sql-constraints) describes the supported vocabulary.

## Nested values and refusals

Native nested storage is the default: PostgreSQL scalar arrays/JSONB, MySQL JSON,
DuckDB recursive containers and Databricks ARRAY/STRUCT/MAP. Snowflake uses VARIANT;
`nested=typed` selects ARRAY/OBJECT. Use `nested=json` explicitly for JSON text storage,
including in Delta. JSON is a representation choice, not automatic recovery of Arrow types.
Strict restoration requires a caller-supplied original Arrow field and refuses duplicate object
keys, non-finite numbers, malformed values and temporal precision loss.

Unsupported native shapes fail before connecting and name the column and JSON alternative.
T-SQL and Warehouse string keys require an explicit indexable `max_length`; Shape refuses
missing widths rather than guessing. Invalid or incomplete decimal dimensions are refused.
PostgreSQL supports decimal256 and some scales that other dialects refuse; unusual scales
require PostgreSQL 15+. Details are in [Sinks](SINKS.md#native-nested-database-values).

## Delta features

Delta supports `table_properties`, not-null/structured check `constraints`,
`column_mapping="name"`, `deletion_vectors=true`, `generated_columns` and `timestamp_ntz=true`
through verified delta-rs APIs. Opt-ins raise the reader/writer protocol union; dry-run reports
that union and doctor reports the actual protocol and feature lists. Capability refusals name
the installed and verified versions. Deletion vectors enable protocol metadata, not row-delete
actions; renaming and upsert are outside this package.

Native nested timestamps normalize to UTC and microsecond precision; submicrosecond data
is not retained. `timestamp_ntz=true` preserves zone-less timestamps. Native timestamp-NTZ
maps combined with name column mapping are refused before storage because the combination
is not verified; use UTC rewriting or JSON text. Validation names the failed rule or generated
column. Adding checks validates existing rows; opt-in validation can materialize pending
batches in a temporary local table. Budget memory accordingly for large batches.
See [Delta feature options](SINKS.md#delta-table-features-opt-in) for the supported settings.
