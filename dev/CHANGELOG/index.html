    Changelog¶

    Status: available.

    Early access 0.9.3. Profiling, contracts and drift are available and supported. Generation from a profile is available and is being hardened. Other surfaces are experimental unless labelled available. The 1.x promises describe future policy.

    Unreleased¶

    Docs: README and Quickstart link to the Shape Playground (a recorded 0.9.3 session in the browser).

    Integrations: the anonymeter extra of sqllocks-shape-integrations is withdrawn; Anonymeter 1.x requires NumPy < 1.27 and Shape requires NumPy >= 2, so the extra could not be installed. The adapter stays and explains this when Anonymeter is missing.

    Fix: shape diff now refuses safe profiles instead of reporting no changes (they cannot be diffed, as docs/PROJECT.md states).

    0.9.3¶

    0.9.2 was published to TestPyPI only and was never released to PyPI; its changes are part of 0.9.3.

    Added¶

    • Synapse dedicated SQL pool live test. The Fabric plugin ships a live test that writes to a real Synapse dedicated SQL pool, driven by SHAPE_TEST_SYNAPSE_URI, SHAPE_TEST_SYNAPSE_STAGING and the service-principal settings SHAPE_TEST_SYNAPSE_TENANT_ID, SHAPE_TEST_SYNAPSE_CLIENT_ID and SHAPE_TEST_SYNAPSE_CLIENT_SECRET. The fabric-live workflow resumes the pool before the tests and pauses it afterwards.
    • --source-config KEY=REF (global option). Passes an Azure read credential to a command by reference. KEY is token, account_key, sas_token or connection_string; REF is an env://, file:// or kv:// reference. A literal secret is refused, and the value lives only for that command.
    • --lakehouse-schema NAME on shape generate --scale-mode fabric_spark and shape demo init. Writes the tables into a schema of a schema-enabled Lakehouse.
    • --table-prefix now works with the Delta sink and with the database and Fabric destinations (PostgreSQL, MySQL, Snowflake, Databricks, SQL Server, Warehouse, Synapse, SQL database, Lakehouse, Eventhouse). Where a destination cannot honour a prefix, the command stops before writing and says so, instead of ignoring the option.
    • Two timeout settings for Fabric SQL writes. SHAPE_SQL_QUERY_TIMEOUT (whole seconds, default 900) limits each SQL statement of the Warehouse, SQL database and Synapse writers, so a stalled load fails instead of waiting forever. SHAPE_WAREHOUSE_INSERT_SECONDS (whole seconds, default 600) limits how long the slower row-by-row Warehouse fallback may take per table. A value that is not a whole number is ignored and the default applies.

    Verified¶

    • Kerberos sign-in. Shape 0.9.1 --auth kerberos was verified on 2026-10-12 against a lab Active Directory domain with SQL Server 2022 (Windows authentication only), from an Ubuntu 24.04 client: 21,750 rows in 9 tables, exit 0, and the server recorded auth_scheme = KERBEROS. A keytab with mode 644 and a wrong principal both exit 2. No code changed for this.

    Fixed¶

    • Nested columns (issue #1). shape profile now profiles Parquet, Delta and JSON Lines tables that hold list, struct or map columns, where it stopped with unhashable type: nested Arrow column. The profile records the column's exact Arrow type, its null rate and, for a list or a map, the distribution of its lengths; the other columns are unchanged. diff, check, inspect and generate --from work on such a profile, and generate writes the column with the same Arrow type. generate stops with an error that names the column for a union, extension, run-end encoded or view type inside a nested column, and shape fidelity refuses a nested column by name. An error whose message holds a backtrace is now one shape: error: line.
    • Local Delta tables no longer hang at exit. shape profile (and every read of a local Delta table) could hang, or abort with terminate called without an active exception, as the process ended after a failed read (for example a damaged data file or a nested column). A local table is now read through Arrow's own file system.
    • shape profile-model / semantic-model://. A table the semantic model cannot read stops with one error naming the model and table and suggesting a refresh, instead of the raw sempy/ADOMD error.
    • Warehouse and Synapse primary keys. Fabric Warehouse rejected a primary key written inside CREATE TABLE (error 24584). Shape now creates the table first and then adds the key with ALTER TABLE ... PRIMARY KEY NONCLUSTERED ... NOT ENFORCED. SQL Server and Azure SQL keep their enforced keys.
    • Time ranges stay text. A column of values such as 18:00-18:59 is no longer read as a UTC offset when profiling; it stays text.
    • Profiling a database with zoned text dates. shape profile-db no longer stops at a sampled text column that holds dates with a time zone. The column keeps its SQL type and statistics, is left out of relationship inference, and carries a profiling_note saying so.
    • Schema-enabled Lakehouses. Tables are written under Tables/<schema>/<table>, where the SQL endpoint and semantic models can see them. Shape asks Fabric which kind of Lakehouse the target is, uses dbo unless you give a schema, refuses a schema for a classic Lakehouse, and, when it cannot tell, stops and tells you to set schema_enabled=true|false. Before, the Delta sink assumed a classic Lakehouse and wrote the tables where schema-enabled Lakehouses could not see them. Writing uses one extra read call to Fabric. This needs a credential; with only a raw storage token, give the schema in the path (.../Tables/dbo).
    • Missing Delta tables are reported as no Delta table at <path>, with credentials removed from the path.
    • The abfss:// sink writes into a Fabric Lakehouse. It used to fail with OperationNotAllowedOnThePath, because it checked for the Lakehouse with a request OneLake refuses on an item folder. It now finds the Lakehouse in the workspace listing. A Lakehouse given by GUID is no longer checked up front; a missing one is reported by the first write.
    • MySQL without TLS. The caching_sha2_password sign-in crash is replaced by a message that says to use verified TLS (ssl_ca=PATH&ssl-mode=VERIFY_CA) or ask the administrator for a supported authentication method. Shape does not fetch an untrusted key.
    • Azure storage credentials. Storage environment keys are now used in a fixed order: explicit options, then AZURE_STORAGE_ACCOUNT_KEY, AZURE_STORAGE_SAS_TOKEN, AZURE_STORAGE_CONNECTION_STRING, then the Fabric or Synapse notebook identity, then DefaultAzureCredential. An ambient account key no longer overrides the identity you selected for OneLake. A sign-in error that cannot succeed on retry (a tenant mismatch or a disabled account, for example) now fails once with one clear message; timeouts and throttling still retry.
    • Warehouse loads when COPY INTO fails. When OneLake cannot supply the storage token (SQL error 13840), the load falls back to parameterized INSERT in batches of 5,000 rows, keeping keys, write modes, rollback and the loaded-row check. The fallback is slower and is no longer silent: it prints a WARNING on stderr, records the note in WriteResult.notes and summary(), and fails with a rollback past SHAPE_WAREHOUSE_INSERT_SECONDS. Batched inserts now size text columns from the whole batch, not the first row, so they no longer fall back to one round trip per row. Emptied OneLake staging folders are removed after a load.
    • Fabric notebook deploy. Fabric sometimes answers with a long-running operation address on a regional *.analysis.windows.net host. Shape now polls the Fabric API for that operation instead of refusing it, and never sends your token to the other host.
    • Fabric errors say what happened. Errors show the HTTP status and Fabric's code and message, with secrets removed. A failed Spark job keeps Fabric's error code and details, or says Fabric gave no reason.
    • Fabric portal connection strings. The ADO.NET-style string from the Fabric portal (Data Source=...;Initial Catalog=...) is accepted by the SQL writers and shape profile-db.
    • Semantic models for service principals. If Fabric's direct lookup fails for a service principal, Shape lists models over REST and warns that it did.
    • Synapse. The dedicated-pool writer sends its DDL in autocommit, stages timestamps in Parquet as INT96, and writes NaN and infinite values as NULL.
    • Fabric Git sync test. The nightly job and fabric-live use FABRIC_GIT_WORKSPACE_ID (the Git-connected workspace) in place of FABRIC_WORKSPACE_ID; tenant, client and remote are variables, the client secret and Git token stay secrets. This affects people who run the live tests, not users of the package.
    • shape profile validate --safe and wide or multi-table profiles. Multi-table --dataset profiles and single wide tables now validate clean. A profile records which columns an internal sample covered as positions, sampling.internal[].column_indexes, in place of names (columns). The profile format version is unchanged, and profiles written by 0.9.1 still load and report the same findings until you profile again. Profile content ids change for the same data.
    • Privacy. A scenario pack's stream topic emits only its payload_fields columns, and pack validate rejects a field that is not a column. A pack run creates its manifest exclusively, so two runs in the same second keep their own manifests. shape chaos --input and shape incremental --input skip the ground-truth logs of an earlier chaos run and name a file that cannot be read as a table. shape registry ROOT commit runs its leak scan on any JSON document with tables, so removing redaction_manifest no longer lets a leaking profile through. shape.yml gates.NAME.mode also accepts the four gates only shape verify runs (reconciliation, timeseries_quality, memorization, utility). shape fabric setup names shape fabric notebook in its next steps.
    • VS Code "Compare with Git HEAD". The comparison document now opens; the custom editor had claimed it and no diff appeared.

    Changed¶

    • Default Lakehouse name for shape fabric setup is shape_lakehouse (was shape-lakehouse). Fabric rejects the hyphen with HTTP 400. Names must begin with a letter and use only letters, digits and underscores (at most 123 characters); Shape now checks this before any request.
    • Replaced the 49 bundled AMA CPT procedure values and descriptions with synthetic SP-01 through SP-49 and Synthetic procedure NN. The letters and hyphen distinguish these five-character codes from CPT formats. Arrow schema, row count, charges and selection weights are unchanged. Healthcare examples and exact writer fixtures now use synthetic procedures and a two-character synthetic sample modifier (S0), with local FHIR code systems. The extra sample procedure outside the catalog is SP-50.
    • Replaced bundled GICS sector codes/names and industry names with a generic synthetic taxonomy (SA through SK, Synthetic sector A through Synthetic sector K, and synthetic industry labels), including company classifications. Schemas, identifiers and cardinalities are preserved. Legacy reference aliases remain readable.
    • Seeded output changes: healthcare and capital-markets generation produces new procedure/classification labels and dataset ids with the same seed. Regenerate fixtures for those domains. GENERATION_STABILITY.md, API_STABILITY.md and RELEASE_POLICY.md reserve cross-release compatibility promises for future 1.x releases and exclude domain reference data from the generator content promise; this early-access patch changes no generator algorithm or format version. Exact affected writer fixtures were regenerated.
    • Owner decisions: the synthetic replacements follow the Owner's decisions recorded in docs/plans/OWNER_DECISIONS.md (GICS taxonomy and the 49 CPT codes replaced by synthetic values in 0.9.2), and resolve the healthcare and capital-markets upstream-source owner notes in THIRD_PARTY_NOTICES.md. Other domain owner notes remain unresolved.
    • Core and all twelve first-party plugins advance together to 0.9.2. Exact SQL headers and documented artifact/registry digests were regenerated for the new writer version.

    Internal and CI (no change to the package or CLI)¶

    • The regression comparison that the benchmark and nightly parity jobs run now uses the recorded output of the published Shape 0.9.1 release as its baseline; the old comparison engine is no longer installed. docs/PERFORMANCE.md joins the documentation site. Nothing you install or run changes.
    • The macOS bounded-memory tests measure the live heap peak instead of resident size, with the same inputs, floor and 10% tolerance. Test change only.
    • The documentation site gains the "Published receipts" pages (Owner-run evidence for the documented examples) and the decisions page.
    • The Fabric test fakes now enforce Warehouse DDL rules and both Lakehouse table layouts, and the live tests run unattended in the fabric-live workflow. Test and workflow change only.

    0.9.1¶

    Release date: 2026-10-11

    Fixed¶

    • CI provisions the executable documentation's pinned environment and released plugins, and restores the Fabric talk kit and its unmeasured live-timings placeholder.
    • Safe-profile validation handles JSON row counts larger than a floating-point number without crashing, while retaining the minimum cohort check.
    • Bounded CSV profiling avoids CPU-scaled decoded read-ahead buffers.
    • Bounded profiling reclaims freed allocator pages after each batch, including on macOS; its RSS regression test fixes Arrow's serial-reader executor sizes to avoid allocator scheduling noise.
    • Fabric setup reports portable source paths, and Synapse derives table labels from Windows paths.
    • Eventhouse emitters and writers synchronize streaming schema caches before ingesting into newly created or changed tables.
    • Eventhouse truncate and replace wait for streamed rows to be sealed, using a configurable command timeout instead of the shorter ingestion timeout.

    • Eventhouse replacement resets rows and column types while preserving table identity, avoiding stale streaming routes after dropping and recreating a table.

    • shape share-bundle verify bounds every member of a bundle before reading it (#684): at most 10,000 members, 8 MiB for attestation.json and manifest.json, 2 GiB per data file and 8 GiB in total, and no member or total that inflates more than 100 times once past 16 MiB (the Excel reader's zip-bomb guard). The limits are checked against the declared sizes and again while inflating, so a header that understates a size is caught too. A bundle over a limit exits 2 naming the member and the limit and leaves nothing extracted; before, a 40 KB bundle could inflate to more than a gigabyte. See docs/SHARE_BUNDLE.md.

    • shape-databases: a credential option (Microsoft Entra sign-in to Azure Database for PostgreSQL or MySQL) now asks for a token for https://ossrdbms-aad.database.windows.net/.default, the scope Microsoft documents for both servers. The default was https://ossrh-postgresql.azure.com/.default, which Entra does not know, so credential= failed unless token_scope was also given (#339). token_scope still overrides the default, for example for the US Gov or China clouds.
    • The leak scan (shape registry ROOT commit, shape profile validate --safe) no longer reads a whole value that is a valid ISO 8601 date or timestamp, such as a datetime column's minimum or maximum (2026-07-08 00:01:07), as a phone number. Daily profiles of a timestamp column were refused when the hour made the digits look like a phone number (F-12). A phone number anywhere else, including after a timestamp in the same value, is still refused.
    • Release engineering (P8-04, docs/RELEASE_CHECKLIST.md): scripts/check_versions.py checks that every place a release version is written agrees (core and plugin versions, every first-party == pin, __version__, the kernel's Cargo.toml and Cargo.lock; --tag, --expect, --release), and scripts/set_version.py changes them all at once. scripts/build_release_dist.py builds the pure wheel, the core sdist and every plugin's wheel and sdist, and checks a full release set (every T-04 platform wheel). scripts/release_sbom.py writes a CycloneDX 1.6 SBOM per archive (with the kernel's Rust crates for the archives that carry it), SHA256SUMS, and the resolved SBOM of sqllocks-shape[all]. scripts/release_index_check.py checks that an index serves exactly the built files, and scripts/release_smoke.py installs sqllocks-shape[all] from TestPyPI, PyPI or a directory and runs the smoke suite. scripts/check_release_workflows.py enforces the release workflows' trusted publishing, SBOM and attestation rules. The packaging lockstep test now also checks the sqllocks-shape-healthcare-* pins, which its pattern had missed.

    • Generated values are the same bits on every CPU and platform (W8-04b, #768), so W1-15's pinned fixtures (#92) and W8-04's byte-identical files (#567) hold on Linux, macOS and Windows alike. numpy's float64 log, exp, log1p, power and cos round differently on AVX-512 CPUs and between the C libraries of each platform; every logarithm, exponential, power and cosine that makes a generated value is now computed with shape.kernel.pmath (fdlibm's algorithms with IEEE basic operations only; native kernel functions pm_log, pm_exp, pm_pow and pm_cos_turns, with numpy twins that give the same bits; docs/GENERATION_KERNEL.md, "Portable math"). This covers the normal draw itself (philox_normal, which now agrees between the kernels bit for bit), every continuous distribution family, the tables of the discrete ones, empirical's interpolation, fan-out weights, skewed foreign keys and lead times. The distributions are unchanged; the last bits of some values changed once: the pinned ids of distribution, normal and the beta, exponential, gamma, log_normal, normal, pareto, power_law_cutoff and weibull families, 77 files of the golden byte corpus, and the hr and healthcare domain outputs, and the vault test's profile-fitted CSV digest (the implementation tests lists old and new ids). Those ids already differed between CI's machines before; now they are the same on Linux, macOS (arm64) and Windows. formula expressions keep numpy's np_log, np_exp and float powers (they equal numpy's own evaluation), and specs fitted to a profile are not covered (docs/GENERATION_STABILITY.md).

    • shape pack run (PackRunner.run) refuses a domain name that is a path (a separator, .., a drive, : or another name is_safe_name refuses) with unsafe domain name '<name>': it must be a plain name, not a path, before anything is generated or written, not even the output directory; it no longer turns such a name into a safe run id (lead decision E2, #281). A scale name keeps the earlier behaviour: its part of the run id is made plain. The registry's raw-profile check (is_raw_profile, profile_capture) refuses a .shape container whose manifest no Shape reader accepts, for example one above the manifest size limit, with RegistryError: not a Shape container: ..., without inflating it (lead decision E1, #283, #396).

    • Registry pruning (#566, docs/REGISTRY.md "Pruning"): shape registry ROOT prune --before DATE [--name NAME ...] [--keep-last N] [--dry-run] [--json] and LocalRegistry.prune(before, *, names=None, keep_last=1, dry_run=False) remove log entries committed strictly before the cutoff and then the objects no remaining entry, ref or tag of any name points at. Every entry a ref (latest, promoted refs) or tag points at, and the newest keep_last entries of each name, are kept; files under objects/ that are not content ids are left alone and reported. The report (format shape-registry-prune, version 1) gives the entries removed and kept per name and why, the objects removed and the bytes freed (under --json, the payload of the shape-result document); --dry-run changes nothing. Logs are replaced atomically and objects deleted only after every log, so an interrupted prune leaves a working registry and a second prune finishes it. A prune holds prune.lock; commits, tag and promote refuse to run while it is held, and a prune waits for commits already writing. Exit 0 done, 2 bad input. Pruning cannot be undone.

    • Test suite (AUD-tests): tests no longer depend on the order they run in (shared Spark session and JVM, shared generation case schemas, a cached test module, the process-wide sys.modules and PYSPARK_PYTHON; #77, #328, #329, #330, #335); the Python-kernel Spark executor test now runs the Python kernel (#328); the suite passes on pyarrow 19.0.1 (#333); a benchmark-harness test no longer writes $BENCH_OUT_DIR (#332); only the delta-fallback tests that read through DuckDB need its downloaded extension (#331). New tests cover shape.quality.evaluate, shape.privacy.assess_summary, contract save/load, the GeoNames and Gazetteer loaders and DatetimeProfile merge.

    • Test coverage counts code the tests run in a child Python process (#337): [tool.coverage.run] patch = ["subprocess"], and the dev extra requires coverage>=7.10. shape.quality.evaluate fails a range rule whose observed value cannot be compared with the bound, instead of raising TypeError.

    • Changed (#721): the Fabric User Data Functions withhold the raw values of classified columns by default, as the bridge's profile, check and diff do. In the results of profileLakehouseFile, profileLakehouseTable and profileDataFrame a column the safe-profile gate classifies (pii_gate_fires: a personal-data pattern such as email or SSN, or nearly every value distinct) has "min": null, "max": null, "redacted": true; the violations of checkProfile and the changes of diffProfiles about such a column have observed (or baseline and current) withheld the same way, in the result and in the raised error. A new optional parameter includeRawValues (default false; include_raw_values in shape.integrations.fabric.udf) returns the raw values. Unclassified columns, existing calls and the .shape file written to outputPath are unchanged.

    • One switch for realistic identifiers (W8-06, #766, docs/GENERATION_STRATEGIES.md). Reserved identifiers stay the default; shape.generate(..., identifiers="realistic"), --identifiers realistic on shape generate (with --from and --scale-mode too), shape composite, shape demo run and shape pack run, a scenario spec's scenario.identifiers, the bridge generate command's optional identifiers argument (1.2) and a schema's top-level "identifiers" turn realistic e-mail addresses, URIs, phone numbers and SSNs on for a whole run. A column's own domains or range wins, then the run switch, then the schema, then reserved; any other value is refused. A realistic run says so once on standard error, and pack run records the mode in the run manifest (reproducibility.identifiers; a manifest without it reads and replays as reserved). The same seed and mode give the same values in both kernels and in the multiprocess and Spark workers; the default output is unchanged. The faker package's e-mail, URL, host and phone providers (the faker strategy) are reserved by default too: faker is at generator version 2, and a spec pinned at faker 1 keeps the package's values (docs/GENERATION_STABILITY.md).

    • shape seed --mode append refuses, before anything is written, a generated primary key that is already in its table (exit 1, the table and the key named; use --mode truncate to replace the rows). It used to write the tables before the clashing one and fail on the database's key (Duplicate entry '1' for key 'customer.PRIMARY' on MySQL). The shape-databases sinks gain keys_sql.

    • A floating column declared integer (the DDL makes it BIGINT) reaches the PostgreSQL and MySQL sinks as int64, and a value that is not whole is refused with the column named (PostgreSQL's COPY refused 3.0 for order_line.quantity in shape seed).

    • The sql writer's format_version is 2 (it was 1): a PostgreSQL literal with a backslash is now an E'...' literal (#285), which changes the bytes of such a script for the same input (docs/GENERATION_STABILITY.md); the golden byte corpus is rewritten.

    • Security fixes (SEC-high, the high-severity findings open at Gate G7): SQL scripts cannot gain a statement from data: in the contract and design DDL a table, schema or column name with a control character is refused and a T-SQL text value with a line break is written as N'a' + NCHAR(10) + N'b'; the SQL sink keeps the T-SQL rule above (a name with a line break is refused, a value is split only at a GO line); a PostgreSQL literal with a backslash is an E'...' literal that reads the same whatever standard_conforming_strings says (#724, #285); the single-table Excel sink stores =... and #N/A text as text, drops characters XML cannot hold and makes the sheet name valid (#629); the Fabric API, OneLake and Eventhouse transports follow a redirect only on the request's own origin, so the bearer token never reaches another host (#275); an abfss:// URI gets a storage credential only on an Azure Storage or OneLake host (#276); the bridge withholds the values, message and detail of a diff change or check violation about a classified column, joint-analysis entries included, and leaves the actual extreme of a classified column out of verify messages (#533, #535; a column that is not classified keeps the frozen, documented 1.1 message text); the demo comparison page shows no value of a classified column (#663); the shape-fabric tape scrubber redacts quoted, braced and JSON secrets, and a tape that holds a secret is refused on load as well as on save (#411); release_for suppresses small cells inside the joint block when nothing is above the target (#650); and a safe-profile column with fewer non-null rows than its k releases no value statistic, which shape profile validate --safe reports as small-cohort-statistic (#395); the safe-profile parity harness names that difference and checks it on both sides (the column is below k by the raw counts, the product holds null, the baseline's mean and std are the raw profile's).

    • shape diff on the terminal is bounded; --json FILE writes the file only (#308). On a terminal, a change's baseline/current list or mapping of more than 20 entries (a new_categorical_values change of a column with thousands of values) prints its first 20, with the count left out under values_omitted and a line on stderr; a pipe still gets the complete result.
