    Failure modes¶

    Status: experimental.

    The ways data goes wrong, how each one looks, which Shape check catches it and a scenario that plants it. Print an entry with shape failure-modes show ID; plant one with shape pack run library:SCENARIO; check the whole catalog against what Shape reports with shape suite run failure-modes.

    Checks are written drift:KIND (a change kind of shape diff), rule:RULE (a rule of shape check) or gate:NAME (a validation gate of shape verify). Every check listed here fires for the entry's scenario; the suite fails when one does not. An entry no check catches says so.

    Id Severity Detected by
    late-arriving-records medium rule:min
    out-of-order-events medium no Shape check
    timezone-offset-shift high rule:max
    dst-boundary-timestamps low drift:day_of_week_change, drift:hour_of_day_change
    encoding-corruption medium drift:pattern_change
    unit-change-mid-series high drift:distribution_shift, drift:mean_shift, drift:range_change, drift:spread_change, rule:max
    column-added medium drift:column_added
    column-renamed high drift:column_added, drift:column_removed, rule:required_column
    column-dropped high drift:column_removed, rule:required_column
    column-retyped high drift:dtype_change, rule:dtype
    class-imbalance-shift medium drift:category_shift
    concept-drift high drift:dependency_broken
    duplicate-keys high gate:uniqueness, rule:unique
    truncated-strings medium drift:length_change
    null-flood critical drift:null_rate_change, gate:null_check, rule:nullable
    referential-orphans high drift:range_change, gate:referential_integrity, rule:max
    volume-spike high drift:row_count_change, gate:uniqueness, rule:row_count.max
    empty-load critical drift:row_count_change, gate:row_count, rule:row_count.min

    numeric-distribution-shift medium drift:distribution_shift

    late-arriving-records¶

    Late-arriving records (severity: medium)

    Symptoms:

    • Rows carry event times earlier than the rest of the batch.
    • Daily totals for a closed period change after the fact.
    • The earliest timestamp of a feed moves backwards.

    Common causes:

    • A source system replays or backfills records after the batch window closed.
    • A mobile or edge device uploads when it regains a connection.
    • A queue consumer fell behind and then caught up.

    Detected by: rule:min

    Reproduce: shape pack run library:late_backfill

    out-of-order-events¶

    Out-of-order events (severity: medium)

    Symptoms:

    • Event times do not follow arrival order.
    • A window closes before every event that belongs to it has arrived.
    • Sequence-dependent logic (sessionisation, running totals) gives different answers per run.

    Common causes:

    • Parallel producers or partitions deliver independently.
    • Retries re-send older events behind newer ones.
    • Clocks on the producing hosts disagree.

    Detected by: no Shape check. Every value is still present and in range, so no Shape check that looks at a column's statistics can see a change of order. Compare event time with arrival time in the pipeline itself.

    Reproduce: shape pack run library:out_of_order_events

    timezone-offset-shift¶

    Timezone offset shift (severity: high)

    Symptoms:

    • Every timestamp is a fixed number of hours earlier or later than before.
    • Events land on the wrong calendar day near midnight.
    • The newest timestamp lies in the future.

    Common causes:

    • A writer switched between local time and UTC.
    • A database driver or session setting changed its time zone.
    • Naive timestamps were converted twice.

    Detected by: rule:max

    Reproduce: shape pack run library:timezone_offset

    dst-boundary-timestamps¶

    Daylight-saving boundary timestamps (severity: low)

    Symptoms:

    • Many rows sit on the hour that does not exist in spring or happens twice in autumn.
    • Hour-of-day and day-of-week mixes change on two days a year.

    Common causes:

    • Local times were stored without an offset.
    • Jobs scheduled in local time run twice or not at all at the clock change.

    Detected by: drift:day_of_week_change, drift:hour_of_day_change

    Reproduce: shape pack run library:dst_boundary

    encoding-corruption¶

    Encoding corruption (severity: medium)

    Symptoms:

    • Accented characters turn into two-character sequences such as a tilde-A followed by a symbol.
    • Text matches by value stop matching.
    • Email or name patterns no longer parse.

    Common causes:

    • UTF-8 text was read as Latin-1 (or the reverse).
    • A file lost its byte-order mark handling in a new reader.
    • A database collation changed.

    Detected by: drift:pattern_change

    Reproduce: shape pack run library:encoding_corruption

    unit-change-mid-series¶

    Unit change in the middle of a series (severity: high)

    Symptoms:

    • A numeric column jumps by a constant factor from one point on.
    • Means, spreads and maxima move together.
    • Totals and averages look sound in each half and wrong across the join.

    Common causes:

    • A feed switched from dollars to cents, kilograms to grams, or seconds to milliseconds.
    • Two source systems with different units were merged.

    Detected by: drift:distribution_shift, drift:mean_shift, drift:range_change, drift:spread_change, rule:max

    Reproduce: shape pack run library:unit_change

    column-added¶

    Column added (severity: medium)

    Symptoms:

    • A column appears that the consumers never saw.
    • Positional readers shift by one column.
    • Strict loaders reject the file.

    Common causes:

    • A source system released a schema change.
    • A transformation started to pass a new field through.

    Detected by: drift:column_added

    Reproduce: shape pack run library:schema_add_column

    column-renamed¶

    Column renamed (severity: high)

    Symptoms:

    • One column disappears and a new one appears with the same content.
    • Queries and joins on the old name fail or return nulls.

    Common causes:

    • A source column was renamed in a release.
    • A transformation changed its aliases.

    Detected by: drift:column_added, drift:column_removed, rule:required_column

    Reproduce: shape pack run library:schema_rename_column

    column-dropped¶

    Column dropped (severity: high)

    Symptoms:

    • A column that downstream code reads is missing.
    • Reports show nulls or fail.

    Common causes:

    • A source system removed a field.
    • A projection was narrowed.

    Detected by: drift:column_removed, rule:required_column

    Reproduce: shape pack run library:schema_drop_column

    column-retyped¶

    Column retyped (severity: high)

    Symptoms:

    • A column changes type, for example a true or false text becomes an integer.
    • Comparisons and casts behave differently.

    Common causes:

    • A source system changed a column's type.
    • A loader inferred a different type from a new sample.

    Detected by: drift:dtype_change, rule:dtype

    Reproduce: shape pack run library:schema_retype_column

    class-imbalance-shift¶

    Class-imbalance shift (severity: medium)

    Symptoms:

    • The mix of a category column moves: a rare value becomes common or the reverse.
    • No value is new or missing.
    • Models trained on the old mix degrade.

    Common causes:

    • A campaign, outage or policy change altered behaviour.
    • A filter upstream began to drop one class.

    Detected by: drift:category_shift

    Reproduce: shape pack run library:class_imbalance_shift

    concept-drift¶

    Concept drift (a changed relationship between columns) (severity: high)

    Symptoms:

    • Each column looks as before but pairs of values no longer go together, such as a city with the wrong state.
    • Models that rely on the relationship lose accuracy.

    Common causes:

    • A join or lookup started to attach the wrong rows.
    • The process that produced the data changed its rules.

    Detected by: drift:dependency_broken

    Reproduce: shape pack run library:concept_drift

    duplicate-keys¶

    Duplicate keys (severity: high)

    Symptoms:

    • Primary keys repeat.
    • Row counts grow without new business events.
    • Joins multiply rows.

    Common causes:

    • A job ran twice without an idempotent write.
    • Two sources feed one table with overlapping keys.
    • A merge key was chosen wrongly.

    Detected by: gate:uniqueness, rule:unique

    Reproduce: shape pack run library:duplicate_rows

    truncated-strings¶

    Truncated strings (severity: medium)

    Symptoms:

    • Text values stop at a fixed length.
    • Emails and names lose their endings.
    • Pattern checks fail.

    Common causes:

    • A column was loaded into a narrower one.
    • A fixed-width export cut long values.

    Detected by: drift:length_change

    Reproduce: shape pack run library:truncated_strings

    null-flood¶

    Null flood (severity: critical)

    Symptoms:

    • A large share of a column is null where it never was.
    • Joins and aggregates silently drop rows.

    Common causes:

    • A source column stopped being filled.
    • A mapping pointed at a field that no longer exists.
    • A failed lookup returns null.

    Detected by: drift:null_rate_change, gate:null_check, rule:nullable

    Reproduce: shape pack run library:null_flood

    referential-orphans¶

    Referential orphans (severity: high)

    Symptoms:

    • Child rows point at parents that do not exist.
    • Inner joins lose rows; left joins show nulls.

    Common causes:

    • Parents and children load in the wrong order.
    • A parent was deleted or filtered out.
    • A key was transformed on one side only.

    Detected by: drift:range_change, gate:referential_integrity, rule:max

    Reproduce: shape pack run library:orphaned_foreign_keys

    volume-spike¶

    Volume spike (severity: high)

    Symptoms:

    • A table holds many times its usual rows.
    • Keys repeat because rows were sent again.

    Common causes:

    • A retry loop re-sent a batch.
    • A backfill ran against the live table.
    • A join fan-out multiplied rows.

    Detected by: drift:row_count_change, gate:uniqueness, rule:row_count.max

    Reproduce: shape pack run library:volume_spike

    empty-load¶

    Empty load (severity: critical)

    Symptoms:

    • A table arrives with no rows although the job succeeded.
    • Everything that references it breaks.

    Common causes:

    • An upstream filter matched nothing.
    • A source outage returned an empty result.
    • A path or partition was wrong.

    Detected by: drift:row_count_change, gate:row_count, rule:row_count.min

    Reproduce: shape pack run library:empty_load

    partial-load¶

    Partial load (severity: high)

    Symptoms:

    • A table holds far fewer rows than usual.
    • Parents are missing for the children that did load.

    Common causes:

    • A job was cut short by a timeout or a kill.
    • A page limit stopped an extract early.

    Detected by: drift:row_count_change, rule:row_count.min

    Reproduce: shape pack run library:partial_load

    placeholder-values¶

    Placeholder or junk values (severity: medium)

    Symptoms:

    • Values such as N/A, TBD, 99999 or 1900-01-01 stand in for real data.
    • Distinct counts and top values change.

    Common causes:

    • A form requires a field the user does not have.
    • A default fills a failed lookup.

    Detected by: drift:placeholder_surge, rule:no_placeholder

    Reproduce: shape pack run library:placeholder_values

    new-category-values¶

    New category values (severity: medium)

    Symptoms:

    • A code or status appears that no earlier batch had.
    • Mappings and dashboards drop or mislabel it.

    Common causes:

    • A source released a new status or product code.
    • A typo or a case difference created a variant.

    Detected by: drift:new_categorical_values

    Reproduce: shape pack run library:new_category_values

    null-rate-creep¶

    Gradual rise of nulls (severity: medium)

    Symptoms:

    • The share of nulls in a column grows a little each day.
    • No single day looks wrong.

    Common causes:

    • A field is being retired or collected less often.
    • A partner has started to send less complete data.

    Detected by: drift:null_rate_change, rule:max_null_rate

    Reproduce: shape pack run library:null_rate_creep

    numeric-distribution-shift¶

    Numeric distribution shift (severity: medium)

    Symptoms:

    • A measure keeps its shape but its centre and spread move.
    • Thresholds and alerts tuned to the old level misfire.

    Common causes:

    • Prices, volumes or sensor calibrations changed.
    • A new customer segment arrived.

    Detected by: drift:distribution_shift

    Reproduce: shape pack run library:numeric_shift
