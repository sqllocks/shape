# Shape in Azure Synapse: runbook

Owner-operated. **Built and tested locally; not run in a Synapse workspace.** The notebook's code
cells run against a local Spark with `mssparkutils` replaced by a stub; the pipeline definition is
checked at schema level and its expressions are evaluated locally. Everything that needs a live
workspace is tagged **[VERIFY]** and listed in [section 6](#6-verify-in-the-workspace-on-first-run)
and the [dry-run checklist](#7-live-dry-run-checklist).

| Item | Source in this repo |
|---|---|
| `shape_profile_synapse` (PySpark notebook) | `notebooks/shape_profile_synapse.ipynb` |
| `shape_gate_synapse` (pipeline: Notebook activity, If Condition, Fail) | `pipelines/shape_gate_synapse.json` |
| `shape_generate_synapse` (PySpark notebook: a domain to Delta or Parquet tables in ADLS, with its contract; PF-06) | `notebooks/shape_generate_synapse.ipynb` |
| `shape_profile_domain_synapse` (PySpark notebook: profile the generated tables, check the contract; PF-06) | `notebooks/shape_profile_domain_synapse.ipynb` |
| `shape_generate_gate_synapse` (pipeline: generate, profile and check, If Condition, Fail; PF-06) | `pipelines/shape_generate_gate_synapse.json` |

Both are generated by `build_synapse.py` (`python integrations/synapse/build_synapse.py && ruff
format integrations`); a test fails if the committed files drift from it.

## 1. Prerequisites

- A Synapse workspace with an **Apache Spark pool**. Shape needs **Python 3.11 or newer** (plan
  T-06): pick a runtime whose Python is 3.11+ (check the runtime's release notes on Microsoft
  Learn; this was not checked here). **[VERIFY]**
- An ADLS Gen2 account with: the data (Delta, Parquet or CSV), a container for contracts and
  artifacts (`shape` below), and the contract (`contracts/orders.json`, the format in plan
  section 12.3).
- Access: the identity the notebook runs as (the pipeline's managed identity, or the user in an
  interactive run) needs **Storage Blob Data Contributor** on the output container and **Storage
  Blob Data Reader** on the data. With `linkedServiceName` set, the *linked service's* identity
  needs those roles instead.
- The Shape wheels from the release: the pure-Python wheel `sqllocks_shape-<v>-py3-none-any.whl`
  and, for the Rust kernel, the `abi3` `manylinux` x86_64 wheel. Both have one version.

## 2. Dry-run every local step first (no Synapse needed)

```bash
pip install -e '.[dev]' -r tests/demo/fabric/requirements.txt   # Java 17 is needed for Spark
pytest tests/demo/fabric/test_synapse.py -q
```

## 3. Install Shape on the Spark pool

1. **Manage > Workspace packages > Upload** the wheel(s) (keep one pure wheel and, optionally,
   the platform wheel).
2. **Manage > Apache Spark pools > (pool) > Packages**: select the workspace package(s) and apply
   (the pool restarts its sessions). **[VERIFY]** that a pool accepts two wheels of one version and
   that `import shape` uses the Rust kernel with the platform wheel (the notebook prints
   `Shape <v>, kernel: rust|python` and returns `kernel` in its exit value).
3. Without outbound access to PyPI, upload numpy, pyarrow and pandas wheels as workspace packages
   too if the runtime's versions are older than `numpy>=2.0,<3` / `pyarrow>=14.0.1`.

## 4. Notebook: `shape_profile_synapse`

1. **Develop > Notebooks > Import** `notebooks/shape_profile_synapse.ipynb`; attach the Spark pool.
2. Set the parameters cell (**Toggle parameter cell** if Synapse did not keep the `parameters` tag):
   `sourcePath` (an `abfss://` folder or file) and `sourceFormat` (`delta`, `parquet`, `csv`), or
   `tableName` for a lake database table; `contractPath`, `baselinePath`, `outputPath` as `abfss://`
   URLs; `linkedServiceName` if storage access goes through a linked service. **[VERIFY]** the
   `spark.storage.synapse.linkedServiceName` / `LinkedServiceBasedTokenProvider` settings the
   notebook applies when `linkedServiceName` is set.
3. Run day 1 (`mode = "exact"`, the default). Expected: the HTML report shows with `displayHTML`;
   the exit value has `"passed": true`, `"checked": true`; `outputPath/<name>/<timestamp>/` holds
   `.shape`, `.html` and `.summary.json`.
4. Run day 2 with `baselinePath` set to the day-1 `.shape`. Expected: `"passed": false`, the
   documented violations, `"drifted": true`.
5. `mode = "distributed"` profiles every partition on the executors in bounded mode (Shape must be
   on the executors: it is, for pool packages) and merges on the driver. It is for data too large
   for the driver. Its exit value says `"checked": false` and the notebook **refuses** a contract or
   baseline in this mode; it is never a gate. Artifacts: `<name>.profile.json`, `<name>.summary.json`.
6. Exact mode samples above `DRIVER_ROW_LIMIT` (5,000,000 rows) and reports `"sampled": true`.

Exit rule: `mssparkutils.notebook.exit(...)` is the **last statement, at top level, never inside
`try`/`except`.** Do not add cells after it.

## 5. Pipeline: `shape_gate_synapse`

1. **Integrate > Pipeline**: create an empty pipeline and paste `pipelines/shape_gate_synapse.json`
   into its code view (or import it as a template). Replace `<<SPARK_POOL>>` and `<<STORAGE_ACCOUNT>>`.
2. Graph: **ProfileTable** (Synapse notebook activity, `shape_profile_synapse`) -> **CheckGate**
   (If Condition on `@json(activity('ProfileTable').output.status.Output.result.exitValue).passed`)
   -> on false, **FailGate** (Fail activity listing the violations).
3. The activity passes every notebook parameter except `mode` and `partitions`, so the pipeline
   always runs the exact mode. Pipeline parameters: `sourcePath`, `sourceFormat`, `tableName`,
   `contractPath`, `baselinePath`, `outputPath`, `failOnDrift`, `linkedServiceName`.
4. **Expected:** day 1 -> Succeeded; day 2 -> **Failed** at `FailGate`, message
   `Shape gate failed for <sourcePath>: [<violations>]`.

## 6. Verify in the workspace on first run

Not checked live; each is a risk until you confirm it.

1. The exit-value expression `@json(activity('ProfileTable').output.status.Output.result.exitValue).passed`
   evaluates in the If Condition. If not, open the Notebook activity's output in a debug run and
   adjust the path; the condition and the Fail message share it.
2. The Notebook activity's `parameters` encoding (`{"value": {"value": "@...", "type":
   "Expression"}, "type": "string"}`): wire one parameter by hand, export the pipeline JSON, compare.
3. A Spark runtime with Python 3.11+ is available, and `import shape` works on driver and executors.
4. `mssparkutils.fs.head/cp/put` on `abfss://` URLs with the identity in use; `file:` staging paths.
5. The `linkedServiceName` token-provider settings (section 4, step 2).
6. `displayHTML` shows the report; `df.rdd.getNumPartitions()` and `mapInArrow` in `distributed` mode.
7. Spark 3.x runtimes: the notebook uses `toPandas()` (no `toArrow()` before Spark 4).

## 7. Live dry-run checklist

Record timings as measured (pool size, rows, seconds); do not extrapolate.

- [ ] Prerequisites met (section 1); `pytest tests/demo/fabric/test_synapse.py -q` passes locally
- [ ] Shape installed on the pool; `Shape <v>, kernel: ...` printed (kernel `rust` with the platform wheel)
- [ ] `shape_profile_synapse` day 1: `passed: true`, report renders, artifacts written to `outputPath`

- [ ] `mode = "distributed"` on a large table: finishes, `checked: false`, `<name>.profile.json` written; a contract set in this mode fails with the explanatory error
- [ ] `linkedServiceName` set: reads and writes succeed through the linked service

- [ ] Anything in section 6 that needed a correction is written down (open an issue or tell the lead)

## 8. Generating data in a pipeline (PF-06)

Built and tested locally: `pytest tests/demo/fabric/test_generate_synapse.py -q` runs both notebooks
against a local Spark session whose `abfss://` paths resolve into a temporary directory, and evaluates
the pipeline's expressions on their real exit values. **Not run in a Synapse workspace.**

### 8.1 Install the domains

A domain is a plugin (`sqllocks-shape-domains`). Next to the Shape wheel, upload `sqllocks_shape_domains-<v>-py3-none-any.whl`
(`pip wheel --no-deps plugins/shape-domains`, or the release) as a workspace package and add it to the
pool (section 3). **[VERIFY]** that the pool resolves its requirement `sqllocks-shape==<v>` against the
uploaded Shape wheel.

### 8.2 Notebook: `shape_generate_synapse`

1. Import `notebooks/shape_generate_synapse.ipynb`, attach the Spark pool.
2. Parameters: `domain`, `scale` (a preset of the domain), `seed`, `mode` (`3nf`, `star` or empty),
   `outputPath` (an `abfss://` folder), `tablePrefix`, `tableFormat` (`delta` or `parquet`), `writeMode`
   (`overwrite` or `append`), `maxRows`, `linkedServiceName`. Names are checked: letters, digits and
   underscores only; `outputPath` must be an `abfss://` URL.
3. **The data is generated on the driver** and handed to Spark to write, so `maxRows` (default
   20,000,000) refuses a scale that is too large before anything is generated. Larger scales: run
   `shape generate` on an Azure Batch node (the ADF runbook).
4. Expected with the defaults (`retail`, `small`, seed 42): nine folders `<outputPath>/tables/<table>`
   (21,750 rows in all) and `<outputPath>/retail/contract.json`, the contract that the domain's own schema
   implies for these tables. The exit value has `tablesPath`, `contractPath`, `tables` (name, path,
   rows), `totalRows` and `kernel`. The same seed always generates the same rows.

### 8.3 Notebook: `shape_profile_domain_synapse`

1. Import it; run it after the first notebook with the same `tablesPath`, `tablePrefix` and
   `tableFormat`, and `contractPath` set to the contract the first one wrote.
2. It reads every table named in the contract, whole (a sample would fail the row counts), profiles
   them together on the driver (`DRIVER_ROW_LIMIT`, 20,000,000 rows), checks the contract, optionally
   diffs `baselinePath`, writes `.shape`, `.html` and `.summary.json` below `outputPath/<domain>/<timestamp>/`.
3. Expected: `"passed": true`, `"violations": []`. After damaging a table (delete rows from `customer`):
   `"passed": false` and the violation `customer:row_count.min`. A missing table makes the notebook fail.

### 8.4 Pipeline: `shape_generate_gate_synapse`

`GenerateDomain` (`shape_generate_synapse`) -> `ProfileAndCheck` (`shape_profile_domain_synapse`, given
`tablesPath` and `contractPath` from the first notebook's exit value) -> `CheckGate` (If Condition on
`@json(activity('ProfileAndCheck').output.status.Output.result.exitValue).passed`) -> on false, `FailGate`
(error code `ShapeContractFailed`). Replace `<<SPARK_POOL>>` and `<<STORAGE_ACCOUNT>>`. Parameters:
`domain`, `scale`, `seed`, `mode`, `outputPath` (where the tables and contract go), `reportPath` (where the
profile artifacts go), `tablePrefix`, `tableFormat`, `writeMode`, `baselinePath`, `failOnDrift`,
`linkedServiceName`. Expected: defaults succeed; damaged tables fail at `FailGate` with the violations.

### 8.5 Verify in the workspace on first run (PF-06)

1. The exit-value expressions, **[VERIFY]**:
   `@json(activity('GenerateDomain').output.status.Output.result.exitValue).contractPath` and `.tablesPath`.
2. `spark.createDataFrame(<pandas DataFrame>)` of the generated tables, and a Delta write to `abfss://`, on the
   pool's runtime (the notebook relies on Delta being available; use `tableFormat = "parquet"` otherwise).
3. `mssparkutils.fs.put` writes `contract.json` to the `abfss://` URL with the identity in use.
4. The pool's driver memory against `maxRows` at your scale.

### 8.6 Live dry-run checklist (PF-06)

- [ ] The domains wheel is on the pool; `Shape <v>, kernel: ...` printed
- [ ] `shape_generate_synapse` (defaults): nine tables, 21,750 rows, `contract.json` written; a second run with the same seed leaves the same tables
- [ ] `maxRows = 1000` refuses the run with the explanatory error and writes nothing
- [ ] `shape_profile_domain_synapse`: `passed: true`; after damaging a table, `passed: false` with the named violation
- [ ] Pipeline `shape_generate_gate_synapse`: succeeds with the defaults (both exit-value expressions **verified**); fails at `FailGate` on a damaged table
- [ ] Timings (generate, write, profile) recorded; anything in section 8.5 that needed a correction is written down
